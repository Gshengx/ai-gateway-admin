## 一、确定问题（建议重构）

### 1. 协议编辑器：双向 watch + 三重补丁【已修复】

位置：`src/views/model/access/InvocationEditor.vue`

**原问题**：内部 `rows` 镜像外部 `standard` / `custom` 两个 model，两个 `flush: 'sync'` 的 watch 互相触发，靠 `syncing` 布尔标志防循环、`JSON.stringify` 值比较防重建、`row.key` 稳定键防失焦——三层补丁全是为镜像状态服务的。

**根因**：`rows` 这份镜像状态本身不必要。协议行 = `custom_invocation_apis`（含 protocol + path），`standard` 只是它的投影。

**修复结果（已复验）**：

| 原补丁                        | 现状                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `rows` 内部镜像 + 双向 watch  | 已删除。`rows` 改为 computed，直接派生自 `configuration.custom_invocation_apis`                |
| `syncing` 布尔守卫防循环      | 已删除。写操作全部是显式事件函数（selectProtocol / updatePath / addRow / removeRow）直改 model |
| `JSON.stringify` 值比较防重建 | 已删除                                                                                         |
| `nextKey` 稳定键防失焦        | 已删除。输入框完全受控（`:value` + `@change`），状态在数据里，`:key="index"` 不再有失焦风险    |

- 保留的唯一 watch 是单向的"props 变化 → 拉取协议选项 → 初始化"，竞态处理收敛到 `useLatestRequest`，属合理实现。
- `standard` 不再是独立 model，由 `syncProtocols()` 从 custom 派生，消除双份数据。
- 父组件接线已同步：`ModelForm.vue` 改为 `v-model:configuration="model"`；`OnboardingGuide.vue` 用 `:configuration="model"` 单向传入（子组件只改嵌套属性不重赋值，引用共享可生效）。

**复验证据（2026-11-17）**：

- `npm run type-check`：exit 0，无错误。
- 浏览器端对端验证（本地 dev server，测试账号登录 → 模型管理 → 创建模型抽屉）：PASS
  - 路径框逐键输入 `/v1/chat`：值按序累积、光标单调递增、每键后焦点均在输入框，失焦问题消除；清空复测及"已初始化协议行"状态下复测均通过。
  - 选择协议自动填充默认路径、切换协议路径随动。
  - 新增行 / 删除行 / 删除中间行均正确，其余行已输入数据不丢；单行时删除按钮禁用。
  - 控制台无 error / warning；验证后取消关闭，未产生脏数据。

**遗留小提醒（非阻塞）**：

1. 行为变化：新校验对"多行中存在空协议行"判为 incomplete，即使 DRAFT 的 `allowEmpty` 场景也会阻止保存（旧版空行会被过滤掉）。若原型允许草稿带空行保存，需确认是否符合预期。
2. OnboardingGuide 的单向 `:configuration` 依赖共享引用隐式回写，能工作但较隐晦，后续可统一为 `v-model:configuration`。

### 2. 授权对象选择：强制重建树 + 镜像 + timer 三件套

位置：`src/views/model/access/SubjectSelect.vue`（L109 / L251、L117-122 / L225-226）

- 现状：每次加载成功 `treeVersion++` 用 `:key` 重建整棵 t-tree；重建导致勾选态丢失，又加 `checkedIds` 镜像 + watch 同步；懒加载子节点与勾选恢复竞态，再加 `setTimeout(syncTreeSelection, 0)` 兜底（L224 注释自认 "rebuilding its data here races checked-state restore"）。典型的"补丁催生补丁"。
- 根因：用重建组件代替更新数据。
- 建议：去掉 `treeVersion` 重建，直接更新 `departments` 数据；勾选用单一 `selection` 源 + 树受控 value，`checkedIds` 改 computed；删掉 timer。

### 3. 部门树选择：rAF 逐帧轮询 + 签名比较 + 失败重建

位置：`src/components/DepartmentTreeSelect.vue`（L6 `:key="treeVersion"`、L163-183 rAF 轮询测弹层几何 + `join(',')` 签名比较、L312-314 失败 setTimeout 重建、L572-610 locale 切换全清重建）；`src/views/cost/useDepartmentPopup.ts`（L21-88）同一套模式复制了一份。

- 根因：TDesign 弹层宽度约束和 TreeSelect 浅监听问题，用重型 DOM 补丁绕过。
- 建议：弹层宽度用 CSS max-width / popper 配置解决，尺寸监听用 ResizeObserver 替代逐帧轮询；加载失败走组件重试而非重建整树；两处重复实现合并为一个 composable。

### 4. 安全规则表单：翻译名写进数据字段，保存时再"还原"

位置：`src/views/security/components/RuleForm.vue`（L286 / L313-317），`DocumentRuleForm.vue`、`PolicyForm.vue` 同模式。

- 现状：初始化时把 i18n 展示名写入 `form.name`，保存时在 `payload()` 里按 seed_key 回填原始名。展示与传输混用同一字段，靠转换层掩盖。
- 建议：`form.name` 始终保留原始值，展示名用 computed 派生；删掉 payload 里的还原逻辑。

### 5. 权限快照 stringify 比较 + 整页强制重建

位置：`src/stores/modules/user.ts`（L184-195）+ `src/layouts/BasicLayout.vue`（L18）

- 现状：已经比较了 `permissions_version` / `configuration_version`，又叠加两个 `JSON.stringify` 比较 capabilities 和导航 route_id，任一变化 `generation++`，`:key="generation"` 强制重建整个布局，丢页面状态。
- 根因：不信任后端版本号，用全量内容比较兜底。
- 建议：与后端确认版本号语义后只信 `permissions_version`；确需重建时仅在导航结构变化时重建菜单区，不整页重建。

### 6. 轮询失败伪造业务状态

位置：`src/views/security/discovery/index.vue`（L470-473）

- 现状：轮询请求抛错（可能只是网络抖动）时，前端本地把任务置为 `status='FAILED'`——把"请求失败"伪装成"任务失败"，掩盖真实状态。
- 建议：保留任务原状态，提示网络错误并提供重试；任务失败状态只能来自服务端。

### 7. ModelForm：签名 / 快照比较体系

位置：`src/views/model/access/ModelForm.vue`（L452-613 附近）

- 现状：`configurationSignature`、`preparedSignature`、`loadedMetadataKey`、`originalPrice` 四份 JSON 字符串快照 + `applyingMetadata` 抑制标志 + `pendingMetadata` / `pendingNameValidation` 去重缓存，共同维护"配置变没变 / 准备做没做"。其中 `applyingMetadata` 与原 InvocationEditor 的 `syncing` 同族——用标志压制自己触发的 watch。
- 根因：把"派生状态"（是否已准备、是否脏）做成了需要手工维护的平行状态机。
- 建议：准备状态改为显式状态机（idle / loading / ready / failed + 对应的配置 key 一份即可）；`applyingMetadata` 可通过把 metadata 应用与 watch 触发解耦（应用时直接调用准备函数，而非依赖 watch 联动）消除；价格脏检查保留一份快照即可，建议封装成统一的 `useDirtyTracker`，避免每个表单各写一套。

### 8. 多层重复守卫（同一竞态防了三四遍）

- `src/views/identity/users/components/UserDetailDrawer.vue`（L583-665）：signal + 计数器 + keyGeneration + drawerGeneration 四重守卫。
- `src/views/identity/keys/index.vue`（L319-356）：`useLatestRequest.isCurrent` + disposed + requestId 三重。
- `src/views/identity/users/index.vue`（L569-1073）：session + searchVersion + branchVersions + inFlight 四层，且 300ms 防抖不取消旧请求（同文件 fetchUsers 却已正确使用 useLatestRequest）。
- 根因：每次出竞态 bug 就加一层守卫，而不是统一机制。项目已有正确范式 `src/utils/useLatestRequest.ts`。
- 建议：全部收敛到 useLatestRequest（abort + 单一 isCurrent），删除其余守卫层。

### 9. 表单重置三层叠加

位置：`src/views/identity/groups/components/GroupFormDialog.vue`（L20 / L104-119）、`DepartmentFormDialog.vue`（L23 / L159-184）、`UserFormDrawer.vue`（L7 / L12）。

- 现状：`:key` 重建 / destroy-on-close、手工逐字段清空、nextTick 后 clearValidate 三种重置手段同时存在（DepartmentFormDialog 还重复置 loading=false）。
- 建议：任选其一（推荐 destroy-on-close 或 key 重建，天然干净），删掉另外两层。

### 10. mock 时间驱动伪造成功

位置：`src/api/mock/cost.ts`（L1108-1111）

- 现状：账单 GENERATING 超 600ms 自动变 COMPLETED，无失败分支。违反 AGENTS.md 4.1"不得伪造创建成功"，且掩盖了"生成失败"这一真实业务分支未被 UI 处理的事实。
- 建议：按后端契约补失败态并让 UI 走失败分支。

### 11. 前端硬编码 ID 映射掩盖契约不一致

位置：`src/views/cost/budgets/ProjectBudgetForm.vue`（L154-163）

- 现状：`'d-root' → 'hq'` 之类的部门 ID 硬编码转换。
- 根因：前后端 ID 不一致，应由后端统一或 mock 对齐契约，而不是前端垫转换层。
