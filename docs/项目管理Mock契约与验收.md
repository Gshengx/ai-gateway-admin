## 状态与契约

入口：`/identity/projects`、`/account/projects`（别名 `/personal/projects`）、`/account/projects/:id`（对应别名同样可用）。

接口均经过 `src/api/request.ts`。Mock 使用现有 `success/fail` 响应壳、Cookie/CSRF 校验、共享权限目录和管理操作审计。读写项目分别受 `identity.projects`、`personal.projects` 能力控制；个人详情必须是项目成员，成员写操作还必须是进行中项目的管理员。不能靠全局管理权限绕过项目角色。

| 接口（相对于 `/api/v1`）                                    | 用途                                                                        |
| ----------------------------------------------------------- | --------------------------------------------------------------------------- |
| `GET /projects`、`GET /me/projects`                         | 指定页列表、筛选、服务端排序分页                                            |
| `POST /projects`、`PATCH /projects/:id`                     | 创建、更新基本信息、管理员、成员和模型策略                                  |
| `POST /projects/:id/enable`、`disable`、`archive`、`delete` | 生命周期变更                                                                |
| `GET /me/projects/:id`                                      | 当前用户角色、预算、本人消费、模型策略及历史排行                            |
| `GET/POST /me/projects/:id/members`                         | 成员分页、添加成员                                                          |
| `POST /me/projects/:id/members/remove`、`promote`           | 移除、设置管理员                                                            |
| `GET /projects/user-options`、`model-options`               | 分页候选，用户搜索含姓名/用户名/部门/用户组，模型来自现有已上架模型共享状态 |

列表遵循 `page + page_size`，响应 `items/page/page_size/total/total_pages`。项目筛选包含名称、状态、责任部门及下级、创建时间范围、人数上下限、仅本人参与；个人列表额外按项目角色筛选。排序在服务端分页前执行。

项目字段包含 `id/name/description/department_id/admin_ids/member_ids/model_ids/status/created_at`。状态为 `ACTIVE/DISABLED/ARCHIVED`，成员角色为 `ADMIN/MEMBER`。`member_count` 由去重的管理员与成员 ID 联集计算。用户列表的可选 `projects` 字段投影为 `{id,name,display_name}[]`；真实后端尚未返回时按空值展示。

`mock/_projects.ts` 使用现有 `runtimeState` 保存唯一项目集合。浏览器刷新、切换入口、退出重登、mock 热重载读取同一份结果；停止开发服务后恢复确定性样例，持久范围与项目既有 mock 一致，不写磁盘。用户来自共享 `directory`，部门来自共享组织数据，模型来自共享模型状态。新项目没有虚构的使用量、预算或检测结果。已有消费及模型明细为固定历史样例，不因修改成员或模型策略而重新分摊历史费用。

添加成员对已有成员、重复 ID 去重；非 GET 请求按操作者与幂等键缓存响应。至少保留一名管理员；普通成员无成员管理按钮，直接调用写接口也被拒绝。归档停用预算快照；重新启用项目不自动恢复预算，并在确认框提示检查预算。
