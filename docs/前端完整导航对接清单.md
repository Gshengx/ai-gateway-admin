核对日期：2026-11-12。源码基准：`codex/integrate-interim-ma6@06194861a3a42215bd787ddaa265a439d7adf135`。本清单整理当前已实现契约，不新增页面、业务接口或权限规则。

**交付给前端时优先阅读本清单，再按接口文档接线。当前完整目录为5个分组、19个叶子入口（13个侧栏项、6个隐藏项）。项目管理、消费账单、费用明细、预算管理四项只有菜单、路由约定和权限资源，尚无业务接口、业务表和专业前端页面。** 其余入口已有对应业务接口或公共会话能力；“工作台”只使用公共会话/能力信息，不代表完整统计仪表盘已实现。

## 1. 接入入口和数据来源

1. 复用现有登录与会话。完整会话后请求`GET /api/v1/me/permissions`，可用`?locale=en`显式选择语言。
2. `data.navigation.groups/items`是当前可见菜单；`data.capabilities`是当前操作能力。菜单不是从数据库权限资源表直接逐行生成，也不由前端按资源前缀推测。
3. 菜单结构/标题/顺序来自后端编译目录；数据库角色授权及资源状态决定能力，后端再筛选叶子与非空分组。数据库权限资源的展示名和导航标题是两个来源，修改前者不自动改菜单标题。
4. 服务端返回`route_id`，**不返回URL/path**；前端按下面的路由表注册SPA页面。API路径与页面路径不可混用。
5. 完整请求字段、错误、写入确认、版本与幂等条件以当前服务OpenAPI为准；本清单中的代表接口不替代操作级契约。

## 5. 页内能力与组合权限

下列能力已存在业务接口，但不另设独立侧栏菜单。

| 资源              | 前端用途                                 | 代表接口（GET读；写方法见契约）                                                                                                             |
| ----------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| model.permissions | 物理模型授权；身份部门/组/用户的模型授权 | `/api/v1/model-access/models/{model_id}/permissions`；`/api/v1/model-access/users/{user_id}/model-grants`；同前缀departments/groups授权接口 |
| model.pricing     | 模型价格读写及版本                       | `/api/v1/model-access/models/{model_id}/pricing`、`/pricing/current`（后者接在模型路径后）                                                  |
| model.admission   | 准入、健康检测记录和触发                 | `/api/v1/model-access/models/{model_id}/admission-tests`、同模型路径`/health-checks`                                                        |
| model.review      | 批准/拒绝、确认上架                      | PUT `/api/v1/model-access/models/{model_id}/status`；POST `/api/v1/model-access/providers/{provider_id}/models/publish`                     |
| audit.annotations | 审计事件标注                             | GET `/api/v1/audit/annotations`；PUT `/api/v1/audit/annotations/{event_id}`                                                                 |

21项实际资源全部支持READ/WRITE。`model.review`的READ能力不对应独立“审核列表”路由或专用读取API；按实际操作契约调用。`demo.control_plane`为示例定义，不是业务菜单；当前未初始化时返回false/false，不创建UI入口。

必须处理下列操作级规则，不能只检测所属页面资源：

| 动作                           | 要求                                                                                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 删除供应商                     | model.providers WRITE **且** model.models WRITE                                                                                                         |
| 导入模型D02                    | model.providers WRITE **且** model.models WRITE                                                                                                         |
| 批量准入D03                    | model.models WRITE **且** model.admission WRITE                                                                                                         |
| 编辑模型M05                    | 按提交字段组合：base/metadata/health要求model.models WRITE；grants要求model.permissions WRITE；pricing要求model.pricing WRITE；一次提交多个域须同时满足 |
| 模型状态操作                   | APPROVE/REJECT要求model.review WRITE；REACTIVATE/RESUME/RETIRE/SUSPEND要求model.models WRITE                                                            |
| 独立自动健康配置               | model.models WRITE，不能混同为触发检测的model.admission WRITE                                                                                           |
| 型号ID可用性检查、价格准备预览 | GET也要求model.models WRITE，不能根据HTTP方法推断READ                                                                                                   |
| 只读企业默认计价规则           | 完整会话接口，无独立资源位；不新增默认价管理后台                                                                                                        |

以上对应OpenAPI的`x-resource/x-action`、`x-permission-all-of`、`x-permission-write-by-field`和`x-permission-write-by-action`。无单一`x-resource`不表示无需鉴权。

当前两环境已明确的默认授权：SUPER_ADMIN显式拥有21项业务资源读写；SYSTEM_ADMIN已有六项模型资源读写，其他既有授权保持。新增项目与成本四项仅默认给SUPER_ADMIN，其他角色不变；它们是可配置资源，后续显式赋权可以改变可见性。roles/permission_resources仍有可信超管限制。前端始终消费有效capabilities/navigation，不按角色中文名硬编码授权。

管理能力与模型使用授权是不同概念：拥有model.permissions WRITE允许管理授权，并不自动获得任意模型的数据面使用许可。

## 6. 响应字段与渲染规则

统一响应封装为`code/data/params/request_id`，成功`code=OK`。没有通用`message`字段；错误通过既有错误码与参数本地化，request_id用于定位问题。

| data字段                                    | 前端处理                                                                                                              |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| navigation.schema_version                   | 当前3；识别支持的结构，未知版本进入兼容错误，不猜结构                                                                 |
| navigation.catalog_version                  | 静态目录摘要`sha256:…`，变化时刷新菜单结构/标题缓存；不是权限版本                                                     |
| navigation.locale                           | 本次协商选中的有效语言                                                                                                |
| navigation.groups[]                         | group_code、可选parent_group_code、title、title_locale、sort_order；当前5组上限                                       |
| navigation.items[]                          | menu_code、route_id、可选parent_group_code、title、title_locale、sort_order、sidebar_hidden；契约上限20，当前全目录19 |
| capabilities[]                              | resource_code、can_read、can_write；用资源码查找，不依赖数组顺序                                                      |
| capabilities[].data_scope                   | 目前仅identity.groups返回GLOBAL或DEPARTMENT_SUBTREE，不代表其他资源的数据范围                                         |
| department_scope_root_id                    | 当前会话部门范围根；不能改传任意根来扩大权限                                                                          |
| permissions_version / configuration_version | 十进制字符串，不转JS number；用于识别权限/配置变化并重新获取                                                          |

渲染顺序：按sort_order升序排列groups；按parent_group_code归组并按sort_order排列items；仅sidebar_hidden=false显示侧栏。不要因为隐藏而移除已授权的头像/页面内入口。分组是容器，不使用group_code请求业务API。当前响应不含图标字段；图标由前端按稳定code映射，不用标题判断。

路由白名单以第3节注册表为准；不将未知route_id拼接为URL，不使用接口title作为HTML。遇到新增未知route_id记录兼容问题并安全处理，不把它错误映射到旧页面。WRITE按钮与READ列表分别控制；无权限不提前请求相关接口。后端返回403时刷新权限并提示，不能因为菜单缓存还在就重试越权请求。

登录、用户切换、权限/配置版本变化、语言切换时重新获取；退出登录清理会话对应缓存。语言切换应保留未提交表单，不将刷新导航等同于重新提交业务。

## 7. 多语言规范与完整标题表

选择优先级：**显式locale → 用户preferred_locale → Accept-Language → 系统默认语言**，只使用已注册且ACTIVE的语言。支持明确映射en-US/en-GB→en、fr-FR→fr，不任意截断语言标记。无可用候选时回退系统默认；不要总回退中文。参数格式错误或显式空值按接口校验处理。

`navigation.locale`是协商语言，`title_locale`是实际标题来源语言；目录缺少选中语言时使用系统默认标题，两者可能不同。标题按纯文本直接显示，不再二次翻译。route_id/menu_code/group_code/resource_code等协议标识不翻译。

目录当前包含zh-CN、en、fr三套标题；**有法文文案不等于环境已启用法文**。最近两环境验收中fr未启用，法文请求回退zh-CN；启用状态以实际语言配置为准。权限资源名称来自资源翻译接口，不能拿导航标题代替资源名。供应商认证模板、价格模板等动态字段沿用各自API的本地化契约，详见模型前端指南，不由导航目录代替。
