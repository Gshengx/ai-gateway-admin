# Mock 账号配置

在项目目录运行 `npm run dev:mock`，服务会自动读取 `mock/accounts.json`，无需先设置环境变量或运行 PowerShell 脚本。修改配置后请重启服务。

```json
{
  "users": [
    { "username": "mock_admin", "password": "MockAdmin@2026" },
    { "username": "mock_auditor", "password": "MockAudit@2026", "role": "auditor" }
  ],
  "roles": {
    "auditor": [{ "resource_code": "audit.management", "can_read": true, "can_write": false }]
  }
}
```

- `users` 可配置多个账号，用户名必须唯一。
- 省略 `role` 时默认为 `super_admin`（超级管理员），也可显式填写 `super_admin`。该角色使用现有 mock 全量权限，无需在 `roles` 内定义。
- 其他角色在 `roles` 中定义，使用与接口一致的 `resource_code`、`can_read`、`can_write`；未列出的资源无权限，写权限必须同时有读权限。菜单和按钮继续由前端现有权限逻辑控制。
- 未定义的角色、重复用户名或配置格式错误会阻止 mock 服务启动，避免配置错误意外获得超管权限。
- 可选的 `needs_password: true` 用于测试首次登录修改密码。修改后的密码只保存在当前进程中，重启后恢复配置值。
- 兼容 `AIS_MOCK_USERNAME` / `AIS_MOCK_PASSWORD`：同时设置时会添加或覆盖同名账号的凭据；同名账号保留配置角色，否则默认为超级管理员。`AIS_MOCK_NEEDS_PASSWORD` 控制该环境变量账号的密码门禁。
- 此文件只供本地 mock 使用，请勿配置真实系统凭据。账号配置由服务端读取，不注入客户端环境变量。

默认账号：`mock_admin` / `MockAdmin@2026`（省略角色，默认超管）；`mock_auditor` / `MockAudit@2026`（审计只读，个人中心可写）。角色配置仅影响 mock 权限响应，不代表真实后端角色定义，也不替代后端鉴权。

## 本次启动内的数据联动

所有可变 mock 数据存放在服务端进程的共享内存中。浏览器刷新、退出重登以及 mock 文件正常热重载不会重新初始化业务数据；停止服务后重新运行 `npm run dev:mock`，恢复初始样例和账号配置。不同服务进程各有独立数据，不跨端口同步，也不写入磁盘。

- 模型状态、生命周期时间线、检测记录、价格版本、供应商模型数量、可授权模型选项、用户/用户组模型授权读取同一份模型数据。下架保留历史与授权记录，但不再出现在可用模型列表中。
- 工作台的“已上架模型”读取当前 ACTIVE 模型数量。没有接入实际请求数据的月活、请求数、Token 和消费趋势仍是演示样例，不因管理操作生成虚构用量。
- 用户、部门、用户组共享数据；组成员变化影响用户所属组及继承的模型授权，改名影响授权对象名称。删除用户清理其 Key、组成员关系、直接模型授权及登录凭据；删除用户组或部门清理对应授权。
- 个人 Key、管理端 Key 和用户详情使用同一份 Key 数据，创建、改名、启停和删除互相可见；用户禁用和须知确认状态参与 Key 的控制条件判断。
- 配置账号同步进入用户目录；创建用户的初始密码可用于 mock 登录，重置密码后旧会话失效。账号启停、姓名、角色和个人偏好会反映到登录上下文。
- 密码策略同时用于创建用户、导入校验和登录后修改密码；须知确认生成实际审计证据，新版本发布后需重新确认。
- 成功的变更操作进入管理操作日志，记录实际操作者、对象、时间、原因；模型状态变更记录前后状态。预览、失败操作、明确的幂等重放不生成成功变更日志。密码、Key 明文和供应商凭据不会复制到日志参数中。
