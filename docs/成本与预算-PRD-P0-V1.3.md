## 1\. 模块概述

### 1\.1 业务目标

建立企业 AI 消费的全面成本管理与预算控制体系，解决：

> **企业在 AI 上花了多少钱，花在哪里，以及如何控制花费不超预期。**

成本与预算是 AI 安全网关的运营管理核心模块。企业需要清晰掌握 AI 消费全貌，并通过预算机制将 AI 支出控制在可预期的范围内。本模块依赖身份管理模块提供的组织和用户信息，依赖模型接入模块提供的物理模型价格配置和请求计量数据。

### 1\.2 P0 范围定义

### 1\.3 核心对象关系

```Plaintext
费用计量：
  请求记录（AccessLog）
    └── 费用明细（CostRecord）1:1
          ├── 归属用户（User）
          ├── 归属部门（Department）
          └── 物理模型（Model）→ 价格配置（ModelPricing）

预算体系（跟随部门树）：
  总部预算（根部门 DepartmentBudget）← 即企业总预算
    └── 子部门预算（DepartmentBudget）1:N
          └── 用户预算（UserBudget）1:N

消费账单：
  账单生成任务（BillTask）N:1 → 创建人（User）
    ├── 部门范围（Department，单个节点及其子树）
    └── 自动生成的账单（Bill）1:N
          └── 账单明细项（BillItem）1:N
  手动生成的账单（Bill）无自动生成任务关联
```

核心原则：

- 每次 AI 请求产生一条费用明细，费用归属到具体用户和部门

- 费用按实际路由到的物理模型价格计算，计算公式由模型接入模块定义

- **预算是 AI 使用的前提条件**：用户必须拥有预算额度才能使用 AI，未分配预算的部门/用户无法发起 AI 请求

- **预算跟随部门树**：总部（根部门）预算即企业总预算；子部门可配置本级预算，也可按共享模式规则继承祖先预算

- **成本数据按部门树授权**：成本管理员仅可查看、配置所属部门及其下级部门的用户消费与预算数据；总部预算仅总部账号可配置，下级部门管理员可只读查看

- 部门预算支持两种模式：共享模式（用户共享部门额度）和独立模式（用户必须分配个人额度）

- 预算控制实时生效：每次请求前检查预算额度，超额或无预算时拒绝请求

## 2\. 功能需求

### 2\.1 费用计量

#### 2\.1\.1 业务说明

费用计量是成本管理的数据基础。每一次经过 AI 安全网关的请求，系统自动记录 Token 消耗并计算费用，形成费用明细记录。费用数据按用户、部门、模型等维度聚合后，用于仪表盘成本总览、消费账单生成和预算消耗追踪。

#### 2\.1\.2 数据模型

**费用明细（CostRecord）**

| 字段                  | 类型            | 必填     | 说明                                        |
| --------------------- | --------------- | -------- | ------------------------------------------- |
| id                    | string \(UUID\) | 系统生成 | 费用明细唯一标识                            |
| access\_log\_id       | string          | 是       | 关联的访问记录 ID                           |
| user\_id              | string          | 是       | 归属用户 ID                                 |
| department\_id        | string          | 是       | 归属部门 ID                                 |
| logical\_model\_id    | string          | 是       | 请求的逻辑模型 ID                           |
| physical\_model\_id   | string          | 是       | 实际路由的物理模型 ID                       |
| provider\_id          | string          | 是       | 供应商 ID                                   |
| input\_tokens         | int             | 是       | Input Token 数量                            |
| output\_tokens        | int             | 是       | Output Token 数量                           |
| cached\_input\_tokens | int             | 否       | 缓存 Input Token 数量                       |
| input\_price          | decimal         | 是       | 计费时使用的 Input 单价（每百万 Token）     |
| output\_price         | decimal         | 是       | 计费时使用的 Output 单价（每百万 Token）    |
| cached\_input\_price  | decimal         | 否       | 计费时使用的缓存 Input 单价（每百万 Token） |
| total\_cost           | decimal         | 是       | 本次请求总费用                              |
| currency              | enum            | 是       | 币种                                        |
| created\_at           | datetime        | 系统生成 | 创建时间                                    |

#### 2\.1\.3 计量规则

- 费用计算在请求完成后（收到供应商响应后）执行

- 计算公式：`总费用 = (Input Token × Input 单价 + Output Token × Output 单价 + Cached Input Token × 缓存 Input 单价) / 1,000,000`

- 使用请求发生时该物理模型当前生效的价格记录

- 如物理模型未配置价格，费用记录为 0

- Token 计数以供应商返回的 usage 字段为准

- 费用明细在请求完成后实时写入，同时异步更新预算消耗

**F\-BILL\-01 账单列表**

- 列表字段：账单周期、周期类型（周/月）、部门范围、总消费金额、总 Token、总请求次数、状态、生成时间

- 支持按周期类型筛选

- 支持按时间范围筛选

- 支持按部门范围筛选；选项仅包含当前管理员本部门及下级部门；“重置筛选”同时恢复周期、时间和部门范围默认值

- 按周期倒序排列

- 支持分页，通过分页控件展示结果总数

- 每条账单记录支持重新生成和一键导出账单；列表导出生成四份独立 CSV，分别包含供应商、部门、用户、模型维度，并覆盖完整账单部门范围

- 账单范围部门必须位于当前管理员所属部门及其下级部门内；展示部门范围，并只返回范围内账单

**F\-BILL\-02 账单生成规则**

- 消费账单页的“生成账单”用于手动生成：管理员选择账单周期、具体月份/日期和单个部门范围后，立即异步生成账单；手动操作不创建自动生成任务

- 部门范围为单选节点，只提供当前管理员所属部门和下级部门；账单统计所选节点及其下级部门内用户的消费明细

- 管理员可创建多个自动生成任务，每个任务配置自动生成周期（月度/周度）、部门范围、是否邮件外发及收件邮箱

- 月度任务每月 1 日 02:00 自动生成上一个自然月账单；周度任务每周一 02:00 自动生成上一个自然周（周一至周日）账单

- 邮件外发开启时，必须填写一个或多个有效收件邮箱；关闭时收件人列表为空

- 创建自动生成任务只保存规则，不立即生成账单；启用中的任务按计划周期运行，可编辑、禁用、重新启用或删除

- 任务列表仅展示当前管理员创建的任务；创建人只能查看和管理自己的自动生成任务，不能查看或操作其他管理员的任务

- 任务列表支持按部门范围和状态筛选

- 同一周期类型、周期起止和部门范围的账单按该次生成结果更新；不同部门范围分别保留账单

- 手动和自动账单生成过程中状态为 GENERATING，完成后为 COMPLETED；自动账单记录关联任务

**F\-BILL\-03 账单详情**

- 账单摘要：总消费金额、总 Token、总请求次数、平均每次请求费用

- 四个维度 Tab：供应商维度、部门维度、用户维度、模型维度

- 每个维度展示该维度下的汇总表格：

  - 供应商维度：供应商名称、消费金额、Token 量、请求次数、占比；展开行展示该供应商下各物理模型的 Token 量和消费金额

  - 部门维度：默认展示总部直属部门，按组织树逐层展开直属下级；同级按当前排序指标排序。父级消费金额、Token 量和请求次数包含整个子树汇总，并标注“含下级”；父级存在直接消费时，展开后以“本部门”单列，避免与下级合计混淆；筛选指定部门时以该节点为展示范围

  - 部门行名称可展开该部门使用的逻辑模型明细

  - 部门维度 CSV 按完整组织路径导出所选范围内的全部节点，并标明“含下级/本部门”统计口径

  - 用户维度：用户名、姓名、所属部门、消费金额、Token 量、请求次数、占比；展开行展示该用户使用各模型的 Token 量和消费金额

  - 模型维度：逻辑模型名称、消费金额、Token 量、请求次数、占比；展开行展示关联物理模型的消费金额、Token 量和请求次数

- 占比列左对齐，仅显示百分比数值，不显示进度条

- 展开明细紧跟对应记录显示，以“物理模型/逻辑模型、消费金额、Token 量、请求次数”为左对齐表头（供应商和模型维度显示物理模型，部门和用户维度显示逻辑模型）；不显示重复的父级标题，也不在列表底部重复展示维度合计

- 每个维度的表格支持按金额/Token/请求次数排序

- 排序方向和 CSV 导出按钮完整显示文案，空间不足时换行

- 详情页支持按当前维度和部门筛选导出 CSV；列表操作提供“导出账单”，一次下载四份独立 CSV（供应商、部门、用户、模型各一份），范围覆盖完整账单部门范围

- 详情摘要、四个维度、展开明细和 CSV 均继承账单的部门范围；部门范围标签展示统计节点及其下级组织

### 2\.3 预算管理 — 部门预算

#### 2\.3\.1 业务说明

部门预算是 AI 使用的准入条件。**未被任何预算覆盖的部门，其用户无法使用 AI 服务。**

预算跟随部门树结构配置，总部（根部门）的预算即企业总预算，是所有消费的全局上限。系统部署后首次登录时引导管理员配置总部预算。

总部预算编辑表单允许管理员配置预算币种（P0 支持 CNY 人民币和 USD 美元）及预算周期（月度/季度）。币种和预算周期均为企业统一配置：只有总部预算可以修改；子部门预算和个人预算跟随总部配置，表单只读展示，不允许单独修改。切换总部币种时，所有预算同步采用新币种，已有预算数值不自动换算，需提示管理员复核各预算额度；费用计量币种与预算币种不一致时，按 4\.4 的规则折算。切换总部预算周期时，所有部门和用户预算同步采用新周期，预算金额和已消费金额保持不变，周期起止日期由系统按新周期规则维护。

总部预算由总部部门账号配置。下级部门管理员可只读查看总部预算卡片，不显示配置入口；其可管理的部门预算、用户预算和消费数据仅限本部门及下级部门。总部管理员的数据范围覆盖全组织。

**预算继承规则**：子部门如果没有配置自己的预算，可以继承最近祖先部门的预算——但仅限祖先预算为**共享模式**时生效（共享该祖先的预算池）。如果最近祖先预算为独立模式，则不可继承，子部门必须配置自己的预算。例如：总部（共享）→ 技术部（共享）→ 后端组（未设预算），则后端组用户共享技术部的预算池；若技术部为独立模式，后端组必须配置自己的预算，否则其用户无法使用 AI。

部门预算支持两种模式：

| 模式         | 说明                                                                                                      | 适用场景                                   |
| ------------ | --------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| **共享模式** | 部门内所有用户共享部门预算池，先到先得。可选为个别用户设置单独限额（在部门总额度内）                      | 部门内用户用量差异不大，管理员不想逐个配置 |
| **独立模式** | 管理员必须为部门内用户分配个人预算，未分配预算的用户不能使用 AI。用户预算之和建议不超过部门预算（软校验） | 需要精确控制每个用户的消费额度             |

#### 2\.3\.3 功能点

**F\-DBUDGET\-01 部门预算列表**

- 列表字段：部门名称、预算模式（共享/独立）、预算金额、已消费、剩余额度、使用率、预警状态、超额策略

- 预警状态用颜色标识：绿色（正常）、黄色（预警）、橙色（严重预警）、红色（超额）

- 未配置预算的部门根据祖先预算模式展示不同状态：

  - 祖先为共享模式：展示"继承自XX部门"（灰色斜体），标注生效的祖先预算来源

  - 祖先为独立模式：展示"未配置"（红色），提示需配置预算后该部门用户方可使用 AI

- 部门预算列表按组织架构以可逐级展开的树状列表展示：默认展示各顶级部门，子部门收在父部门下；点击展开后在父部门记录下方显示子级，父部门名称旁标注"含下级"

- 总部预算在列表上方的企业总预算卡片中展示，显示总部预算模式（共享/独立）及预算金额、已消费、剩余额度、周期、使用率、状态和超额策略；部门列表不重复列出总部根节点

- 支持按部门名称搜索

- 支持按预警状态筛选（全部/继承/正常/预警/严重预警/超额）

- 不提供单独的部门筛选控件；层级定位通过树状列表展开完成

- 预算行提供"编辑"操作；已配置本级预算的部门额外提供"移除预算"操作。未配置预算的部门通过"编辑"进入配置表单

- 不提供多选框或独立的"创建部门预算"按钮

- 支持分页，按顶级部门条目分页，展开的子级随所属顶级部门显示

- 部门树按组织架构顺序展示；预警状态通过标签和颜色识别，不改变树的层级顺序

**F\-DBUDGET\-02 配置部门预算**

- 从部门列表对应行点击"编辑"打开配置表单：已配置预算的部门进入编辑，未配置预算的部门进入新增配置

- 每次配置一个部门，不提供部门预算批量创建

- 表单字段：

  - 预算金额（必填）

  - 预算模式（必填，共享模式/独立模式，默认共享模式）

  - 币种（必填，只读，跟随总部预算币种）

  - 预算周期（必填，只读，跟随总部预算周期）

  - 预警阈值（必填，默认 80%）

  - 严重预警阈值（必填，默认 95%）

  - 超额处理策略（必填，默认 BLOCK\_DEPARTMENT）

  - 通知接收人：预警通知、严重预警通知、超额通知分别搜索、多选用户；每个级别可独立选择站内信、邮件渠道，详见 2\.6

- 预算模式说明：

  - 共享模式：部门内用户共享预算池，无需逐一分配用户预算。可选为个别用户设置单独限额

  - 独立模式：必须为部门内用户分配个人预算，未分配预算的用户无法使用 AI

- 超额处理策略说明：

  - ALERT\_ONLY：记录告警并按预算中配置的接收人发送通知，不阻断请求

  - BLOCK\_DEPARTMENT：界面文案显示为“阻断请求”；超额后阻断该部门所有用户的 AI 请求

- **软校验提示**：创建/编辑时，如所有子部门预算总和超过总部预算，给出提示"子部门预算总和（按币种格式化的金额）已超过总部预算（按币种格式化的金额），请确认"，不阻止保存

**F\-DBUDGET\-03 编辑部门预算**

- 可修改预算金额、预算模式、阈值、超额策略、各级通知接收人和通知渠道；编辑总部预算时还可修改币种和预算周期，其他部门的币种及预算周期只读并跟随总部设置

- 总部修改预算周期后，所有部门和用户预算同步采用新周期；预算金额和已消费金额保持不变，周期起止日期由系统按新周期规则维护

- 修改后立即生效

- 修改记录计入变更历史

- 修改金额时同样触发软校验提示

- 从共享模式切换为独立模式时，提示"切换后需为部门内用户分配个人预算，未分配的用户将无法使用 AI"

**F\-DBUDGET\-04 删除部门预算**

- 删除部门预算后，该部门回退为继承上级预算（仅上级为共享模式时生效；上级为独立模式时该部门用户将无法使用 AI）

- 仅本级已配置预算的部门显示"移除预算"操作，移除操作需二次确认

- 移除弹窗提供复选项"同步移除子部门及用户预算"，默认不勾选

- 默认仅移除当前部门预算，保留所有子部门预算和用户个人预算配置

- 勾选后，同步移除所有下级部门预算，以及当前部门和其下级部门用户的个人预算配置；不影响部门树范围之外的预算

**F\-DBUDGET\-05 部门预算详情**

- 展示：

  - 预算配置信息，包括各级通知接收人

  - 消费进度（进度条，颜色随状态变化）

  - 当前周期每日消费趋势图

  - 该部门下各用户消费排行（Top 10）

  - 该部门使用的各模型消费排行（Top 10）

  - 预算变更历史，包含基础额度变更、临时追加创建及到期记录

### 2\.4 预算管理 — 用户预算

#### 2\.4\.1 业务说明

用户预算用于控制单个用户的 AI 支出。用户预算的必要性取决于所属部门的预算模式：

- **共享模式部门**：用户预算可选。未设置个人预算的用户共享部门预算池；设置了个人预算的用户在部门总额度内有单独限额

- **独立模式部门**：用户预算必设。管理员必须为每个用户分配个人预算，未分配预算的用户无法使用 AI

### 2\.5 预算检查（数据面）

#### 2\.5\.1 业务说明

预算检查是数据面请求链路的一个环节。在身份识别和权限检查通过后、实际转发请求之前，系统检查该用户的各级预算是否允许本次请求。

#### 2\.5\.2 检查逻辑

```Plaintext
请求进入 → 身份识别 → 权限检查 → 预算检查 → 安全检测 → 模型路由 → 请求转发

预算检查流程：
1. 确定用户的生效部门预算
   ├── 用户所属部门有自己的预算 → 使用该部门预算
   └── 用户所属部门无预算 → 沿部门树向上查找最近祖先预算
       ├── 找到共享模式的祖先预算 → 继承该预算
       ├── 找到独立模式的祖先预算 → 不可继承，拒绝，提示"所属部门未配置预算"
       └── 找到总部仍无预算（理论上不会出现，总部必设）→ 拒绝

2. 检查总部预算（根部门，全局上限）
   ├── 超额 + 策略为 BLOCK_DEPARTMENT → 拒绝，提示"企业总预算已超额"
   └── 超额 + 策略为 ALERT_ONLY → 记录告警，继续

3. 检查生效部门预算（如果不是总部本身）
   ├── 超额 + 策略为 BLOCK_DEPARTMENT → 拒绝，提示"部门预算已超额"
   └── 超额 + 策略为 ALERT_ONLY → 记录告警，继续

4. 检查用户预算（根据生效部门的预算模式）
   ├── 共享模式：部门额度已在步骤3检查；如该用户有个人预算，额外检查：
   │   ├── 超额 + BLOCK_USER → 拒绝，提示"个人预算已超额"
   │   └── 超额 + ALERT_ONLY → 记录告警，继续
   └── 独立模式：
       ├── 该用户未配置预算 → 拒绝，提示"未分配个人 AI 预算，请联系管理员"
       ├── 超额 + BLOCK_USER → 拒绝，提示"个人预算已超额"
       └── 超额 + ALERT_ONLY → 记录告警，继续

5. 所有检查通过 → 继续请求
```

- 每一层级独立判断：先看是否超额，再看超额策略是阻断还是仅告警

- 个人预算检查使用当前生效额度：基础额度加上当前有效的临时追加额度；共享模式下仍先检查部门预算，再检查该用户个人预算。

- 临时额度到期导致当前生效额度降低时，已消费金额不变；如基础额度大于 0 且消费金额高于新的额度，立即按该个人预算的超额策略处理。若为基础额度为 0 的临时专用个人预算且临时配置已全部到期，则按无个人预算处理，不按 0 额度触发个人超额策略。

- 策略为 ALERT\_ONLY 时，超额不阻断请求，仅记录告警并通知

- 策略为 BLOCK\_\* 时，超额立即拒绝请求

- 部门预算支持继承：子部门无预算时使用最近祖先部门的预算

- 预算检查需在毫秒级完成，使用内存缓存实时更新消费额度

#### 2\.5\.3 预算消费更新

- 请求完成后，根据实际消费金额异步更新各级预算的 consumed\_amount

- 更新时同步检查是否触发预警状态变化（NORMAL → WARNING → CRITICAL → EXCEEDED）

- 状态变化时触发相应的通知

### 2\.6 预算预警通知

#### 2\.6\.1 业务说明

预算配置人可在每条部门预算或个人预算中，分别配置预警、严重预警、超额通知的接收人和通知渠道。个人预算默认通知预算所属用户；通知其他用户时需显式添加。部门预算由配置人显式指定接收用户。P0 支持站内信和邮件，并允许各预警级别独立选择渠道。

#### 2\.6\.2 功能点

**F\-NOTIFY\-01 按预算配置接收人与渠道**

- 在每条预算新增、编辑表单中增加通知配置区域，按预警级别分别设置接收人和渠道：

| 配置项       | 触发条件                       | 接收人                                                                 |
| ------------ | ------------------------------ | ---------------------------------------------------------------------- |
| 预警通知     | 使用率达到该预算的预警阈值     | 部门预算：显式所选用户；个人预算：预算所属用户默认接收，可添加其他用户 |
| 严重预警通知 | 使用率达到该预算的严重预警阈值 | 同上；各级接收人可不同                                                 |
| 超额通知     | 使用率达到或超过 100%          | 同上；各级接收人可不同                                                 |

- 每个级别可选渠道：站内信、邮件，可同时选择，也可清空表示该级别不发送通知；新预算默认选中站内信。

- 部门预算在任一级别启用渠道时，必须为该级别指定至少一名接收用户。个人预算的预算所属用户为默认接收人，不重复存入额外接收人列表；所属用户的站内信和邮件渠道也受该级别所选渠道控制。

- 接收人按用户 ID 保存；通知渠道按预警级别保存。预算状态判定和超额阻断策略仍按预算配置执行。

- 个人预算通知阈值、使用率和超额判定均以当时生效额度（基础额度加有效临时追加）为基数。

- 只有拥有预算管理写权限且预算处于其可管理范围内的用户才能修改；总部预算仅总部账号可配置。

- 候选用户为当前配置人本部门及下级部门内的启用用户；支持按姓名、用户名、部门路径搜索，显示“姓名（用户名）· 部门路径”，可选择普通用户，无需接收人拥有预算管理权限。

- 已有接收人由上级管理员配置、但处于当前配置人可选范围外时，保留现有配置并展示；不得借此新增范围外用户。已停用或删除的用户保留异常标识，发送时跳过。

- 用户邮箱从账号资料读取。选择邮件渠道时，该级别所有接收人（包括个人预算所属用户）必须为启用用户且已配置有效邮箱；否则阻止保存并提示完善邮箱或调整接收人/渠道。邮件使用账号当前邮箱地址。

- 个人预算批量分配时，三组额外接收人和渠道统一应用到所选用户的预算；每个预算所属用户仍分别默认收到自己的预算通知。

- 继承或共享预算的用户、部门使用来源预算的通知配置；不因每个继承者再重复生成同一预算池的通知。

- 预算详情分别展示每级接收人和渠道；部门预算接收人为空时显示“不通知”，个人预算显示“本人（默认）”及额外接收人。修改配置记录操作人、时间和各级接收人/渠道，并写入预算变更历史。

- 旧预算缺少通知接收人配置时，部门预算初始化为空接收人；个人预算按预算所属用户默认接收处理。旧预算缺少渠道配置时默认站内信；不继续使用旧版固定角色通知规则。

**F\-NOTIFY\-02 预警触发与发送规则**

- 预算消费更新、预算配置保存或临时追加额度到期后检查使用率；对达到阈值且已启用渠道的级别，分别向配置接收人发送站内信和/或邮件。一次跨越多个阈值时，分别处理各级通知。

- 同一预算、同一周期、同一级别、同一渠道只发送一次；同一通知内重复用户合并。不同级别或渠道分别记录发送结果。

- 发送时校验接收用户仍存在且为启用状态；无有效接收人或该级未启用渠道时不发送。变更通知配置后，尚未发送的级别/渠道使用新配置；已成功发送的渠道不重复发送，新增渠道可独立发送一次。

- 保存实际接收人、邮件地址、预算周期、触发级别、消费金额、当时生效预算金额（基础额度加有效临时追加）、触发时间的快照。刷新页面、重复消费更新、调整阈值或接收人均不重复发送已成功发送的同周期同级别同渠道通知。

- 新预算周期按新的周期标识独立触发。

**F\-NOTIFY\-03 通知方式与访问权限**

- P0 支持系统内站内信和邮件通知；站内信在管理端/用户端消息中心展示，各接收人的已读、未读状态独立。邮件按通知事件发送至用户账号邮箱。

- 通知包含预算名称、预算周期、触发级别、当时生效预算金额、已消费金额、剩余额度、使用率、超额策略和触发时间；严重预警与超额采用对应状态标识。

- 被选为接收人仅允许接收该通知摘要，不自动授予预算查看、配置或审批权限，也不扩大管理数据范围。

- “查看”入口按接收人当前权限和数据范围展示：预算本人可进入个人使用概览；有预算查看权限且数据在范围内的用户可进入预算管理；其余接收人仅查看通知内容。

- 删除预算后保留已发送的通知记录，移除已失效的预算查看入口。

## 4\. 业务规则

### 4\.1 预算层级与准入

| 层级       | 适用范围   | 配置要求                         | 未配置时                                                              |
| ---------- | ---------- | -------------------------------- | --------------------------------------------------------------------- |
| 总部预算   | 全部用户   | **必须配置**，系统部署后引导设置 | 系统引导配置，不可跳过                                                |
| 子部门预算 | 部门内用户 | 可选，建议配置                   | 祖先为共享模式：继承祖先预算池；祖先为独立模式：该部门用户无法使用 AI |
| 用户预算   | 单个用户   | 取决于生效部门的预算模式         | 共享模式：共享部门额度；独立模式：无法使用 AI                         |

- **预算是使用 AI 的前提条件**，无预算即不可用

- **总部预算即企业总预算**，所有子部门和用户的消费均计入总部预算

- **预算向下继承（仅共享模式）**：子部门未配置预算时，如最近祖先预算为共享模式则自动继承；祖先为独立模式则不可继承，子部门必须配置自己的预算

- 部门预算支持两种模式：

  - **共享模式**：用户共享部门预算池，可选为个别用户设置单独限额

  - **独立模式**：每个用户必须分配个人预算，未分配的用户无法使用 AI

- 预算允许超额分配（子部门预算之和可以超过总部预算，独立模式下用户预算之和可以超过部门预算），配置时系统给出软校验提示但不阻止保存

- 请求时按总部 → 生效部门 → 用户顺序逐级检查

### 4\.2 预算周期管理

| 规则         | 说明                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------- |
| 周期类型     | 月度（自然月）或季度（自然季）                                                                      |
| 配置范围     | 仅总部预算可配置周期类型；所有部门预算和用户预算只读跟随总部周期                                    |
| 周期起止     | 月度：每月 1 日至月末；季度：1/4/7/10 月 1 日起                                                     |
| 自动滚动     | 当前周期结束后自动开始新周期，consumed\_amount 归零                                                 |
| 临时追加额度 | 有效期跨越预算周期时，在每个有效周期计入个人预算上限；每个新周期仍从 0 开始累计消费，不结转剩余额度 |
| 中途创建     | 在周期中间创建预算时，当前周期从创建日开始，下一完整周期按自然月/季对齐                             |
| 中途修改     | 修改预算金额立即生效，已消费金额不变                                                                |

总部修改周期类型后，所有部门预算和用户预算立即同步新周期类型；预算金额和已消费金额保持不变，当前周期起止日期由系统按新周期规则维护。

### 4\.3 预算状态判定

| 状态     | 条件                                                          | 展示 |
| -------- | ------------------------------------------------------------- | ---- |
| NORMAL   | 消费 \< 当前生效额度 × 预警阈值                               | 绿色 |
| WARNING  | 当前生效额度 × 预警阈值 ≤ 消费 \< 当前生效额度 × 严重预警阈值 | 黄色 |
| CRITICAL | 当前生效额度 × 严重预警阈值 ≤ 消费 \< 当前生效额度            | 橙色 |
| EXCEEDED | 消费 ≥ 当前生效额度                                           | 红色 |

个人预算状态判定中的当前生效额度为基础额度加上当前有效的临时追加额度；临时额度创建或到期时重新计算状态。

### 4\.4 费用计量与预算的币种处理

- 费用明细以物理模型价格配置的币种记录

- 预算消耗按总部预算配置的统一展示币种计算

- 如费用明细币种与预算币种不同，按当日汇率折算（汇率配置见系统管理）

- P0 阶段简化：建议企业统一使用同一币种配置所有价格和预算，避免汇率换算复杂度

### 4\.5 用户/部门删除对预算的影响

| 操作         | 影响                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| 删除用户     | 同步删除该用户的预算配置，历史费用记录保留                                             |
| 用户转移部门 | 用户预算删除，需在新部门重新分配预算；旧部门消费额不回退，新部门开始累计该用户后续消费 |
| 删除部门     | 同步删除该部门的预算配置和部门下所有用户的预算配置                                     |
| 新增用户     | 共享模式部门：自动共享部门预算池；独立模式部门：需管理员分配预算后方可使用 AI          |

### 4\.6 账单生成规则

| 规则         | 说明                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------- |
| 手动生成     | 消费账单页选择周期、月份/日期和部门范围后，立即异步生成账单；不创建自动生成任务              |
| 自动生成周期 | 月度任务每月 1 日 02:00 生成上月账单；周度任务每周一 02:00 生成上周账单                      |
| 自动生成任务 | 管理员按需为部门创建周期任务，可设置邮件外发和多个收件邮箱；创建时只保存任务规则，不立即出账 |
| 数据范围     | 汇总所选部门节点及其下级部门内用户在该周期的已完成请求费用明细                               |
| 维度快照     | 账单中的部门名称、用户名等使用快照值，不受后续修改影响                                       |
| 重复生成     | 同一周期和部门范围的账单按最近一次生成结果更新；自动生成账单关联对应任务                     |
| 任务可见范围 | 仅创建人可查看、编辑、启用/禁用和删除自己的自动生成任务                                      |

## 7\. 非功能需求

### 7\.1 性能

| 指标                        | 要求                                            |
| --------------------------- | ----------------------------------------------- |
| 预算检查响应时间            | \< 5ms（数据面关键路径，需内存缓存）            |
| 费用记录写入                | 异步处理，不阻塞请求响应                        |
| 仪表盘成本概况加载          | \< 1s                                           |
| 消费账单详情加载            | \< 2s                                           |
| 月度账单生成（10 万条记录） | \< 5min                                         |
| 预算消耗更新延迟            | \< 3s（从请求完成到预算 consumed\_amount 更新） |

### 7\.2 安全

- 成本管理角色只能查看和管理当前账号所属部门及其下级部门的用户消费、账单明细、用户预算和部门预算；总部账号范围为全组织

- 下级部门管理员可只读查看总部预算卡片；总部预算金额、币种、周期、模式及其他配置仅总部账号可修改

- 所有成本与预算接口在服务端校验部门树范围；前端隐藏筛选项和操作入口不构成授权边界

- 自动生成任务列表、编辑、启停和删除均按创建人隔离，不能读取或操作其他管理员的任务

- 审计员对费用和预算数据仅有只读权限

- 普通用户仅可查看自己的预算和费用信息

- 所有预算配置变更记录操作日志

- 预算变更历史不可修改、不可删除

### 7\.3 数据

- 费用明细（CostRecord）永久保留，不可修改、不可删除

- 消费账单永久保留

- 预算变更历史永久保留

- 预算周期结束后，历史周期的消费数据保留用于账单查询和趋势对照

### 7\.4 容量

容量基线与《身份管理 PRD（P0）》7\.4 保持一致：最多 100,000 个用户、10,000 个部门。当前没有生产环境 DAU 和请求频率数据，费用明细容量按日活用户比例和日活用户请求量进行场景估算；费用明细和消费账单按年度新增量估算，预算配置按当前有效对象数量估算。以下请求量是容量规划假设，不是线上实测或行业基准；试点后应使用实际 DAU 和请求分布校准。

| 对象                   | 设计容量   | 估算依据                                                                                                                                                                                                                      |
| ---------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 费用明细（CostRecord） | 10 亿条/年 | 基准场景：100,000 用户 × 30% DAU × 每名日活用户每天 30 次请求 × 365 天 = 3\.285 亿条/年；压力场景：100,000 × 50% DAU × 每名日活用户每天 50 次请求 × 365 天 = 9\.125 亿条/年，按 10 亿条/年规划。请求量按用户所有 API Key 合计 |
| 消费账单（Bill）       | 65 万条/年 | 10,000 个部门范围 ×（每年 12 个月度周期 \+ 最多 53 个周度周期）；同一周期类型、周期起止和部门范围只保留一条账单记录，重新生成时更新该记录                                                                                     |
| 部门预算               | 10,000 条  | 每个部门最多配置一条当前有效预算，含总部预算                                                                                                                                                                                  |
| 用户预算               | 100,000 条 | 每个用户最多配置一条当前有效预算                                                                                                                                                                                              |

费用明细和消费账单永久保留，因此年度容量表示每年新增量，不代表全生命周期存量上限。存储、索引和归档设计须按累计留存量规划；账单容量按所有部门范围均生成月度及周度账单的上限估算，实际新增量取决于启用的账单范围和生成周期。

### 7\.5 数据精度

- 费用金额统一使用 decimal 类型，精度保留到小数点后 6 位

- 页面展示时保留 2 位小数

- 汇总计算使用精确计算，避免浮点数误差累积

### 7\.6 国际化

- 所有页面文本、提示信息、错误信息支持中文/英文双语

- 金额展示跟随币种配置展示对应币种符号（¥/$€ 等）

- 数字格式跟随语言环境（千分位分隔符等）

- 预算状态枚举内部使用英文（NORMAL/WARNING 等），展示层按语言翻译

## 8\. 系统初始化

首次部署时自动完成以下初始化：

1. 系统部署后首次登录引导管理员配置总部预算（预算金额、币种、周期、阈值）

2. 启用费用计量功能（默认开启，每次请求自动记录费用）

3. 管理员按需创建自动生成任务，配置月度/周度周期、部门范围及邮件外发；手动生成不创建自动任务

4. 初始化预算站内信及邮件通知模板
