# 前端开发规范

适用范围：`ais-gateway-admin`（AI 安全网关管理端）。技术选型依据见《前端技术选型文档.md》。

## 1. 技术栈

| 分类   | 选型                                        | 版本  |
| ------ | ------------------------------------------- | ----- |
| 框架   | Vue 3（`<script setup>` + Composition API） | ^3.5  |
| 语言   | TypeScript（`strict: true`）                | ~5.6  |
| 构建   | Vite                                        | ^5.4  |
| UI     | TDesign Vue Next                            | ^1.10 |
| 状态   | Pinia                                       | ^2.3  |
| 路由   | Vue Router（hash 模式 + 动态权限路由）      | ^4.5  |
| 国际化 | vue-i18n（`legacy: false`）                 | ^11.4 |
| 图表   | ECharts（按需引入 `echarts/core`）          | ^5.6  |
| 请求   | Axios                                       | ^1.7  |
| Mock   | vite-plugin-mock                            | ^3.0  |

## 2. 目录约定

```
ais-gateway-admin/
├─ index.html
├─ mock/                  # 仅 dev:mock 生效；按业务域拆分文件
│  ├─ _utils.ts           # 响应壳、token 校验、分页（page/page_size）等公共能力
│  ├─ auth.ts
│  └─ identity.ts
├─ public/                # 原样拷贝的静态资源
├─ src/
│  ├─ api/
│  │  ├─ request.ts       # Axios 实例 + 拦截器（唯一封装点）
│  │  ├─ types.ts         # 响应壳 / 分页等通用类型
│  │  └─ modules/         # 按业务域拆分：auth.ts、identity.ts …
│  ├─ components/         # 跨业务域复用的组件
│  ├─ directives/         # 全局指令（v-permission）
│  ├─ layouts/            # 布局壳与其子组件
│  ├─ locales/            # index.ts 初始化，zh-CN.ts / en-US.ts 汇总语言包
│  │  ├─ common/         # 公共文案、路由标题、通用错误；按语言配对
│  │  └─ modules/        # 按功能建目录，各含 zh-CN.ts / en-US.ts
│  ├─ router/             # index.ts（静态路由）、routes.ts（业务路由）、guard.ts
│  ├─ stores/modules/     # Pinia：user.ts、permission.ts
│  ├─ styles/
│  ├─ utils/
│  └─ views/<业务域>/<页面>/index.vue
└─ docs/
```

新增页面：在 `src/views/<业务域>/<页面>/index.vue` 建文件 → 在 `router/routes.ts` 追加路由 → 在 `locales/common/zh-CN.ts` 与 `en-US.ts` 补 `route.*` 文案，业务文案补到对应功能目录。

## 3. 接口层规范

- **所有请求必须经 `src/api/request.ts`**，禁止在组件内直接 `import axios`。
- **响应壳**：后端统一返回 `{ code, data, message, params, request_id }`，`code === 'OK'` 为成功。拦截器已统一拆壳，业务层拿到的即 `data`，不要再判 `code`。
- **会话**：真实后端使用 HttpOnly Cookie（`withCredentials: true`），前端拿不到 token；Mock 模式用 Bearer token 模拟。本地仅保存 `ais_session` 会话标记供路由守卫判断，实际鉴权以后端为准。
- **CSRF**：登录后调 `GET /auth/context` 取 `csrf_token`，拦截器对非 GET 请求自动附加 `X-CSRF-Token`。
- **登录失效**：仅 HTTP 401 或业务码 `UNAUTHORIZED` / `UNAUTHENTICATED` 视为登录失效，清理会话并跳登录页（带 `redirect`），随后 `reload` 卸载已动态注册的路由，避免越权残留。HTTP 403 但业务码为 `OUT_OF_SCOPE` / `FORBIDDEN` 等属于无权访问，只做错误提示，不得清理会话（F-USER-01A：通过 ID 或 URL 直接访问范围外用户按无权访问处理）。
- **错误提示**：拦截器统一弹提示并给 Error 打 `notified` 标记；调用方仅在 `!err.notified` 时补充提示（如登录门禁），避免重复弹窗。
- **分页**：列表接口统一使用指定页分页（`page` + `page_size` → `items` / `page` / `page_size` / `total` / `total_pages`）；`page` 从 1 开始，`page_size` 默认 20、最大 100，两者需同时提供。列表分页由 `total` 驱动，使用 `t-table` 的 `pagination` 或紧随列表下方的 `t-pagination`，禁止再用游标累加或本地切片模拟页码。
- **变更类操作**（启用/禁用/删除/移动等）的 `reason` 字段以具体接口契约为准；明确要求时传递，不得自行增加必填原因。
- **幂等**：拦截器为所有非 GET 请求自动生成 `Idempotency-Key`；重试同一业务操作时应复用原 key，避免后端重复执行。
- **国际化入参**：拦截器为所有请求附加 `Accept-Language`，并为 GET 请求自动追加 `locale` 查询参数（后端据此解析 `display_name` 等本地化字段）。文件下载等无需本地化的接口传 `skipLocale: true` 关闭。
- **用户偏好**：语言切换后调用 `PATCH /me/preferences` 写入 `preferred_locale` 与 `time_zone`，下次登录由后端返回偏好。
- **时间展示**：后端统一返回 UTC 时间（ISO 8601）。禁止直接截取字符串展示，必须经 `src/utils/datetime.ts` 的 `formatDate()`（`YYYY-MM-DD`）/ `formatDateTime()`（`YYYY-MM-DD HH:mm:ss`）按浏览器当前时区转换；无时区字面量的时间按 UTC 解析。

## 4. 权限规范

- 后端 `capabilities[].can_read` → 权限码 `resource_code`（页面/菜单级）；`can_write` → `resource_code:write`（按钮/操作级）。
- 路由权限：在 `routes.ts` 的 `meta.permission` 声明，守卫校验不通过跳 `/403`。
- 按钮权限：使用 `v-permission.write` 控制可写操作，无权限时隐藏元素；`v-permission="'identity.users:write'"` 为兼容形式。

```vue
<t-button v-permission.write="'identity.users'">{{ t('users.create') }}</t-button>
```

- 权限完全由后端 capabilities 决定：`can_read` 控制菜单/页面可见与可进入，`can_write` 控制新增/编辑/删除等可写操作；前端不设通配符或写死的超管旁路。
- 危险操作（删除、批量启停、重置密码等）必须二次确认。确认框如无需求或接口契约的明确要求，不需要填写原因；严格依据原型展示样式和文案，正文、图标与按钮须对齐，文案须准确说明操作对象与实际影响，禁止无意义提示。

## 5. 国际化规范

- 所有用户可见文案走 i18n，**中英文语言包必须同时补齐**，key 结构严格一致。
- **语言包目录**：`locales/zh-CN.ts` 与 `en-US.ts` 只负责导入、汇总；公共文案放 `locales/common/`，业务文案放 `locales/modules/<功能>/zh-CN.ts` 与 `en-US.ts`。新增业务分组在两个语言入口同步引入，不把业务文案直接写进入口。已有中英文成对词条表可保留在对应功能目录的 `messages.ts`，由两个语言文件分别导出；移动文件不改变既有翻译 key。
- key 的每一段必须与对象嵌套层级一致，禁止带点的叶子键。父级分组名用 `label` 子键：

```ts
route: { identity: { label: '身份管理', users: '用户管理' } }
```

- 路由标题：`meta.title` 存 i18n key，由 `translateRouteTitle()` 解析；key 缺失时原样返回，便于渐进迁移。
- 组件内统一 `const { t } = useI18n()`；非组件环境（store、拦截器）用 `i18n.global.t()`。
- 页面词条应接入全局语言入口，不得使用只包含部分词条的局部语言包导致公共文案反复回退；不得关闭缺失词条及回退警告掩盖问题。提交前运行 `npm run check:i18n`，检查中英文键、插值参数、静态翻译调用与消息编译；动态状态、按钮、抽屉和弹窗分支还需在浏览器中切换中英文回归。
- 表格列定义、下拉选项等随语言变化的结构，用 `computed` 包裹以响应语言切换。
- **语言入口必须是下拉选框**（`HeaderBar` 的 `t-select`），不允许做成"图标点击轮换"。选项来自 `GET /locales/options`，仅展示 `status === 'ACTIVE'` 的语言，按 `sort_order` 升序，label 用后端返回的 `native_name`（母语名称）；接口失败时回退本地 `SUPPORTED_LOCALES`。
- **切换即同步偏好**：选中语言后先本地 `setLocale()` 并刷新 `document.title`，再 `PATCH /me/preferences` 写入 `{ preferred_locale, time_zone }`；偏好写失败不得阻断本次切换。
- **语言编码**统一使用 BCP 47（`zh-CN` / `en-US`），与 i18n `locale`、后端 `locale` query、`Accept-Language` 三处保持同一个值。
- 新增语言：在 `src/locales/common/` 和各功能目录中补齐对应语言文件，在 `src/locales/` 新增汇总入口并在 `index.ts` 注册，同步补 `SUPPORTED_LOCALES`。

## 6. 组件与样式

- **全局基础样式一致性（强制）**：搜索框、筛选控件、列表、分页、抽屉、弹窗、确认框及其标题、正文、操作区必须复用同一套全局基础样式；管理端与个人中心遵循同一标准。不得因页面不同自行修改基础高度、圆角、边框、字号、内外间距、按钮排列、滚动方式或让搜索框随剩余空间任意拉伸。
- 列表筛选统一复用 `FilterBar`；紧凑工具栏使用 `list-toolbar`，搜索框使用 `list-search`，普通筛选项使用 `list-filter`，部门树筛选使用 `list-department`。基础宽度与间距从 `src/styles/index.css` 的公共变量读取，不再为每个业务模块复制一套默认值。
- **例外必须有明确依据**：只有需求或原型明确指定的业务尺寸／交互可覆盖基础规则（例如 1300 宽预算配置弹窗、特定详情抽屉宽度）；例外尺寸集中定义在 `src/styles/` 并注明依据。原型未明确要求差异时，按全局基础样式实现；不能把页面中的偶然差异当作自行分化样式的理由。
- 调整或新增基础组件后，必须同时对照一个现有管理页面与个人中心页面进行浏览器验证；检查正常、空态、加载、筛选、窄窗口以及抽屉／弹窗打开后的布局一致性。
- 一律 `<script setup lang="ts">`，props 用类型声明式 `defineProps<{...}>()`，事件用 `defineEmits<{...}>()`。
- 样式用 `<style scoped>`。
- **数字步进框**：统一禁止负数，包含后端模板定义的动态 NUMBER 字段；使用 `v-nonnegative-number` 拦截手输和粘贴，并配置非负或业务正数下限，保存时继续校验。模板若显式声明负数范围，反馈契约冲突，不自行放开。查询返回的负余额仍按真实值展示，不作为可编辑步进框处理。
- **样式必须完全遵循 TDesign CSS Variables**：颜色、字号、字重、圆角、间距、阴影、层级一律引用 `--td-*` 变量，禁止硬编码色值、`px` 间距与自定义色板。这样后续换主题（含暗色模式）只需在根节点覆盖变量即可全局生效。

  常用变量（按用途选用，不要自造同名变量）：

  | 用途               | 变量                                                                                                                                   |
  | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
  | 文本               | `--td-text-color-primary` / `--td-text-color-secondary` / `--td-text-color-placeholder` / `--td-text-color-disabled`                   |
  | 品牌与状态         | `--td-brand-color` / `--td-brand-color-hover` / `--td-success-color` / `--td-warning-color` / `--td-error-color`                       |
  | 背景与描边         | `--td-bg-color-container` / `--td-bg-color-page` / `--td-bg-color-container-hover` / `--td-component-stroke` / `--td-component-border` |
  | 间距               | `--td-comp-margin-{xs,s,m,l,xl}`、`--td-comp-paddingTB-{s,m,l}`、`--td-comp-paddingLR-{s,m,l}`                                         |
  | 字号               | `--td-font-size-{body-small,body-medium,body-large,title-small,title-medium,title-large}`                                              |
  | 圆角 / 阴影 / 层级 | `--td-radius-{small,medium,large}` / `--td-shadow-1..3` / `--td-z-index-*`                                                             |

- 仅当 TDesign 未提供对应变量时（如内容区最大宽度）才允许自定义尺寸，且必须集中写在 `src/styles/` 内并加注释说明来源。
- **区块间距**：页面内同级区块（工具栏/筛选区、列表、分页器、表单分组、弹窗内容区）之间必须留出统一间距，禁止元素紧贴，也不得依赖组件默认外边距凑合。纵向区块间距统一用 `--td-comp-margin-l`，区块内部紧凑元素之间用 `--td-comp-margin-xs` / `--td-comp-margin-s`；间距一律走变量，不写死 `px`。新增或调整页面前，先对照同模块已有页面确认间距一致。
- **分页器位置**：优先使用 `t-table` 的 `pagination` 属性，让分页器随表格内置在列表底部；确实需要独立渲染 `t-pagination` 时，必须紧接列表下方，与列表间距为 `--td-comp-margin-l`。禁止用容器撑高（`height: 100%`）、`margin-top: auto`、`justify-content: space-between` 把分页器推到容器底部形成大片空白，也不得与下方表单、按钮区紧贴。弹窗/抽屉内的列表与分页器同样适用。
- 通用能力下沉：筛选区用 `FilterBar`，图表用 `ChartCard`（已按需注册 ECharts 组件，勿整体引入 `echarts`）。
- **部门展示**：凡是涉及部门的地方，一律以树结构 + 懒加载展示，复用 `src/components/DepartmentTreeSelect.vue` 的实现方式（按 `has_children` 动态加载子级，不得一次性拉全量部门树）。是否允许搜索以具体需求为准：筛选类下拉允许搜索，其余场景不额外增加搜索。
- **可选列表**：实现可选择列表（表格多选、穿梭选择等）时，除非需求明确要求，不展示“已选择 X 人”之类的已选数量文案。
- 未开发的页面统一挂 `views/common/placeholder.vue`，不要用空文件占位。

### 全局抽屉与弹窗叠层（长期要求）

- 所有 TDesign 抽屉和模态弹窗统一由 `src/utils/overlayStack.ts` 维护一层视觉蒙层。业务组件不得另加遮罩或自定义叠加的蒙层背景；保留组件原生的点击拦截、焦点管理和动画。
- 抽屉内打开另一个抽屉时，原详情面板收起、新面板独立滑入，共用持续显示的蒙层，不得直接替换正文、叠加变暗或先撤掉蒙层再重建。原抽屉加全局 `app-drawer-handoff` 类保留外壳并执行面板收起，新抽屉使用独立组件及原生进入动画；可参考模型详情中的编辑、授权入口。关闭新抽屉后应通过 `useDrawerClose` 等待动画，再释放原详情并返回列表。
- 抽屉内打开弹窗时，弹窗必须挂到 `body`（TDesign 默认挂载点），相对整个浏览器视口水平、垂直居中。不得挂在抽屉正文或使用抽屉宽度计算位置，不得通过 `top` 偏移覆盖全局居中规则。
- 新增同类入口必须回归进入动画、蒙层连续性、关闭按钮、Escape、取消、保存及关闭后再次打开；弹窗关闭后原抽屉内容和状态应保留，整个层级关闭后不得残留蒙层或滚动锁。只读回归不得顺手提交授权、删除或其他无关业务写操作。

## 7. Mock 规范

- `npm run dev` 的认证与已实现接口直连真实后端（Vite 代理，并重写 `Origin` 头以满足后端同源校验）；项目、成本与预算模块使用开发服务的共享 Mock。经用户授权的本地工单权限及审批账号与真实权限、数据隔离，详见《本地混合Mock模式.md》。`npm run dev:mock` 启用完整 mock。
- mock 文件按业务域拆分，`export default [] as MockMethod[]`；响应必须用 `_utils.ts` 的 `success()` / `fail()` 包装，保持与真实后端一致的响应壳。
- mock 数据要求确定性（不用随机数），便于调试分页与筛选；需要覆盖 `null`、禁用态等边界分支。
- mock 的长期关联与验收要求见项目 `AGENTS.md` §4.1：列表、详情、统计、发现/导入及授权使用共享状态，不维护独立假数据；变更后必须验证跨页面读回及重复操作。
- 复杂样例不可随更新丢失：多版本价格（含多时段多条件）、多次检测（含成功/失败）、有顺序的生命周期事件应能在详情中验证；字段、版本、快照仍严格遵循正式契约。
- 文件下载、multipart 上传等无法用 JSON 表达的接口，用 `rawResponse(req, res)` 自行处理。

## 8. 工程化

- 提交前：`husky` + `lint-staged` 自动跑 ESLint 与 Prettier；提交信息经 `commitlint`（Conventional Commits）。
- 代码风格：无分号、单引号、行宽 100、末尾逗号（见 `.prettierrc.json`）。
- 类型检查：`npm run type-check`（`vue-tsc --noEmit`）。`tsconfig.json` 开启 `noUnusedLocals` / `noUnusedParameters`，不留无用变量。
- 构建：`npm run build` 先类型检查再打包；产物按 `tdesign` / `echarts` / `vendor` 手动分包。
- 环境变量：仅 `VITE_` 前缀会注入客户端，新增变量必须同步补 `src/env.d.ts` 的 `ImportMetaEnv` 声明。

| 变量                | 说明                                                |
| ------------------- | --------------------------------------------------- |
| `VITE_APP_TITLE`    | 应用名，用于浏览器标签页标题                        |
| `VITE_API_PREFIX`   | 接口前缀，Axios `baseURL` = `${VITE_API_PREFIX}/v1` |
| `VITE_USE_MOCK`     | `true` 时启用 vite-plugin-mock                      |
| `VITE_PROXY_TARGET` | dev 代理目标后端地址                                |
