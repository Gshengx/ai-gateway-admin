## 1\. 模块概述

### 1\.1 业务目标

建立以成本中心为归口的预算管理体系，解决：

> **企业的 AI 预算由谁承担、在哪个费用主体上消耗、当前是否超支，以及如何按组织范围预警和拦截。**

- 以成本中心承接企业预算，向下拆分为费用主体和成员配额，形成「成本中心 → 费用主体 → 成员」三层管理结构。

- 额度管控启用后，按各层阈值和超额动作执行预警或拦截；未启用时只记录用量。

- 为工单审批提供费用主体归属、当期额度与剩余额度信息，支撑个人预算追加的业务决策。

### 1\.2 角色权限矩阵

| ---------------------- | ---------------------------------------------------- | ---------------------------------------------------- | ----------------------------------------- | -------------------------------- |
| 超级管理员、系统管理员 | 全部成本中心、费用主体和成员配额；可新建、编辑、删除 | 全部范围；可生成、管理任务、查看和导出               | 可查看、开启 / 关闭管控并配置全局兜底策略 | 全部对象                         |

### 1\.4 核心业务对象

```Plaintext
成本中心（CostCenter）
  ├── 费用主体（FeeSubject）1:N
  │     ├── 周期额度（FeeSubjectPeriod）1:N
  │     └── 成员配额（MemberBudget）1:N
  └── 变更记录（ChangeLogEntry）1:N

部门（Department）→ 费用主体：N:N（覆盖范围含下级部门）
用户组（Group）→ 费用主体：N:N（覆盖范围展开为成员）
用户（User）→ 费用主体：N:N（覆盖范围直接选择）
API Key → 费用主体：N:1（创建时按用途绑定费用主体；消费保存发生时的实际归属和额度管控状态）

额度管控
  └── 全局设置（QuotaGlobalSettings）1:1

消费账单（BillV2）
  ├── 账单范围：部门 / 成本中心 / 费用主体（三选一）
  └── 自动账单任务（BillTask）0:1

费用明细（ExpenseRowV2）→ 账单范围：按部门归属、成本中心归属或费用主体归属归集
```

| 成员配额     | 费用主体下为单个成员配置的独立额度，不配置时按共享池或独立模式处理                                                                     |

### 1\.5 关键概念与口径

| 概念                  | 说明                                                                                                                                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 费用主体基础预算      | 费用主体创建 / 编辑时配置的预算，对应 `budgetAmount`                                                                                                                                                    |
| 费用主体当前可用预算  | 等于费用主体基础预算，对应 `currentBudgetOf`                                                                                                                                                            |
| 成员基础预算          | 成员各期基础配额合计                                                                                                                                                                                    |
| 成员当前可用预算      | 当前成员周期基础配额与本期生效的临时追加之和；不分期成员按有效期总额计算                                                                                                                                |
| 增加每期配额          | 申请金额为每期增量，审批执行时当前及费用主体有效期内后续各成员周期的基础配额各增加一次；当前期不按剩余天数折算。总额增量＝获批每期增量 × 受影响期数；费用主体续期产生的新期在容量校验通过后延续相同增量 |
| 成员额度使用顺序      | 受管控消费及在途预占先使用当前期基础配额，再使用本期生效的临时追加；多笔临时追加按到期时间由近到远使用。结算、释放按原来源回写，未来期基础配额不得提前使用                                              |
| 本期预算 / 本期已消费 | 当前日期所在周期的额度与消费；无当前周期时展示「—」                                                                                                                                                     |
| 成本中心剩余可分配    | 成本中心预算总额 − 子费用主体当前可用预算合计；展示值最小为 0，编辑费用主体时先排除该主体原有预算再计算可分配上限                                                                                       |
| 费用主体剩余可分配    | 还能配置给成员的额度。独立模式为同一统计范围的预算额度 − 已单独配置；共享模式为同一统计范围的预算额度 − 已消费 − 已单独配置中尚未消费的配额，成员已消费金额不重复扣减；展示值最小为 0。                 |
| 剩余额度              | 费用主体按对应范围预算扣除预算消费；成员按当前期基础及有效临时追加分别扣除各自的已用；未管控消费不扣减                                                                                                  |
| 使用率                | 取对应范围的预算消费 ÷ 预算额度，分母为 0 时展示「—」                                                                                                                                                   |
| 子费用主体占比        | 该费用主体预算消费 ÷ 成本中心累计预算消费                                                                                                                                                               |
| 时间进度              | \(今天 − 有效期开始\) ÷ \(有效期结束 − 开始\)，限制在 0%–100%                                                                                                                                           |
| 费用主体类型          | `subjectType = PROJECT`（项目）/ `DEPARTMENT`（部门）；项目用途 Key 使用项目型费用主体，个人用途 Key 使用部门型费用主体                                                                                 |
| 默认费用主体          | 成本中心创建时自动生成，`isDefault = true`                                                                                                                                                              |
| 覆盖范围              | 部门、指定成员和用户组；选择与校验规则见 2\.3\.5                                                                                                                                                        |
| 单人消费金额上限      | 共享模式下单个成员使用共享池时的个人消费上限；不分期为费用主体有效期内的每人累计上限，月度 / 季度 / 年度为每人每期上限。上限不预留费用主体预算，请求仍受费用主体及成本中心额度约束                      |
| 离用户最近的费用主体  | 创建 Key 时默认带出的部门型费用主体：覆盖用户（直接选择、所属部门或所属用户组）的主体中层级最深者；覆盖层级相同时取有效期生效且当前可用预算更高者；仅用于默认选中，实际归属以保存后的绑定关系为准       |
| 消费归属              | 数据库保存消费发生时的费用主体、成本中心及名称快照；无有效关联时保存为空并标记为未关联                                                                                                                  |
| 消费管控状态          | `UNCONTROLLED` 表示消费发生在额度管控生效前，`CONTROLLED` 表示发生在生效后；费用明细按该快照展示，不随当前开关回溯                                                                                      |
| 预算消费              | 仅统计 `CONTROLLED` 消费，用于已消费、剩余额度、使用率、预算检查和预算告警；`UNCONTROLLED` 消费不扣预算                                                                                                 |
| 实际消费              | `CONTROLLED` 与 `UNCONTROLLED` 消费合计，用于消费账单、费用明细及消费归集展示                                                                                                                           |
| 未管控                | 额度管控生效前的消费展示状态；费用明细中的费用主体类型、费用主体和成本中心均展示「未管控」                                                                                                              |
| 未关联                | 管控生效后未关联有效费用主体的状态；正常情况下该 Key 在消费前已被禁用                                                                                                                                   |

**额度状态（三级阈值口径）**

| 状态     | 判定                                                                              |
| -------- | --------------------------------------------------------------------------------- |
| 仅记录   | 全局额度管控未启用；实际消费正常记录，但不参与预算计算、告警或拦截                |
| 未生效   | 今天早于有效期开始日                                                              |
| 已到期   | 今天晚于有效期结束日                                                              |
| 未配置   | 预算总额为 0 且尚未发生计费消费时的配置状态；额度管控开启后，请求仍按预算策略检查 |
| 超额     | 使用率 ≥ 100%                                                                     |
| 严重预警 | 使用率 ≥ 严重预警阈值且 \< 100%                                                   |
| 预警     | 使用率 ≥ 预警阈值且 \< 严重预警阈值                                               |
| 正常     | 未达到预警阈值                                                                    |

状态优先级：超额 \> 严重预警 \> 预警 \> 未配置 \> 未生效 \> 正常 \> 已到期 。预算为 0 时，发生计费消费的请求按超额处理，未发生消费时展示「未配置」。

异常口径：未配置、已到期、超额、严重预警计入异常；预警、未生效、仅记录、正常不计入异常。未管控、未关联属于消费归属状态，不属于预算对象异常。

- 超额动作只在「超额」状态（使用率 ≥ 100%）下触发，严重预警与预警仅标记，不触发阻断。

- 严重预警阈值必须大于预警阈值。

- 成本中心和费用主体预算允许为 0，展示「未配置预算」；请求检查见 1\.6，Key 选择规则见 2\.3\.5。

- 不分期费用主体在列表的本期预算四列展示「—」；整体使用率按 1\.5 口径展示。

### 1\.6 AI 请求预算检查

预算检查发生在 AI 请求到达时，使用实时消费数据和本次请求预计费用；账单、列表的 T\+1 数据不参与请求放行判断。

| 检查环节               | 通过条件                                                                                                 | 不通过或触发后的处理                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 额度管控开关           | 未开启时请求直接通过，消费记录按 1\.5 的管控状态口径处理                                                 | 未开启时不执行预算、阈值和超额检查                                     |
| Key 与费用主体         | Key 处于可用状态，已关联存在且有效的费用主体，用户在费用主体覆盖范围内                                   | 任一条件不满足，拒绝请求并提示具体原因                                 |
| 有效期                 | 成本中心、费用主体和成员均在有效期内                                                                     | 到期后按所属成本中心兜底策略执行：自动放行则通过并记录，强制拦截则拒绝 |
| 成员额度与费用主体额度 | 不分期时只检查总额度；分期情况下同时检查当前期额度和总额度。均未超过则通过。                             | 成员或上级额度不足时按超额策略处理                                     |
| 成本中心额度           | 检查成本中心总额度，未超过则通过                                                                         | 额度不足时按超额策略处理                                               |
| 消费记录               | 请求通过后记录实际消费、费用主体、成本中心、成员及管控状态；预算消费、实际消费和归属快照按 1\.5 口径处理 | 被拒绝的请求不计入消费账单；拒绝原因写入请求审计记录                   |

## 2\. 功能需求

### 2\.1 额度管控与状态判定

#### 2\.1\.1 业务说明

额度管控关闭时只记录实际消费，开启后对新消费按成本中心、费用主体和成员三层额度检查。预算状态、请求处理及通知分别见 1\.5、1\.6 和 2\.4\.3；有效期结束策略采用全局默认值，成本中心可单独覆盖。

#### 2\.1\.2 数据模型

**QuotaGlobalSettings**

| 字段                    | 类型                           | 说明                                                                       |
| ----------------------- | ------------------------------ | -------------------------------------------------------------------------- |
| enabled                 | boolean                        | 额度管控总开关，默认关闭                                                   |
| enabledAt               | string（可选）                 | 最近一次开启额度管控的生效时间；消费记录据此保存管控状态                   |
| defaultFallbackStrategy | `NOT_ENFORCED` / `FORCE_BLOCK` | 有效期结束后的全局默认兜底策略，默认为到期后自动放行；成本中心未覆盖时生效 |
| 兜底策略取值：          |                                |                                                                            |

| 取值          | 名称           | 说明                                                         |
| ------------- | -------------- | ------------------------------------------------------------ |
| NOT\_ENFORCED | 到期后自动放行 | 成本中心有效期结束后系统将自动放行，不做额度校验，只记录用量 |
| FORCE\_BLOCK  | 强制拦截       | 成本中心有效期结束后阻断该范围内的 AI 请求                   |

#### 2\.1\.3 功能点

- **F\-CC\-01 查看管控状态**：页面顶部展示额度管控状态、说明和开关；该区域仅超级管理员、系统管理员可见。

- **F\-CC\-02 开启 / 关闭管控**：开启时若存在异常对象，提示异常数量；关闭时二次确认。仅超级管理员、系统管理员可操作。

- **F\-CC\-03 配置全局兜底策略**：在「全局兜底策略配置」弹窗中仅配置有效期结束后兜底策略的全局默认值（到期后自动放行 / 强制拦截）。仅超级管理员、系统管理员可操作。

- **F\-CC\-04 异常汇总**：启用后按“异常口径”展示异常横幅，分别统计异常的成本中心数量与费用主体数量；统计范围限定为当前登录人有权管理的成本中心与费用主体，无权对象不计入。

- **F\-CC\-05 状态统一判定**：按 1\.5 的状态口径判定，成本中心状态不聚合子费用主体。

#### 2\.1\.4 页面设计

**状态栏**

- 未启用：展示「额度管控 · 未启用」

- 首次进入预算管理页面需要展示当前仅记录实际消费的说明。

#### 2\.1\.5 业务规则

- 关闭管控时，所有对象状态为「仅记录」，不做预警与拦截。费用主体不对 API Key 形成限制：无论 Key 是否绑定费用主体、绑定主体是否到期或覆盖用户，除手动禁用外 Key 均为可用状态；

- 开启管控时按当前绑定关系重新计算 Key 状态，未关联有效费用主体的 Key 自动禁用并向所属用户发送站内通知

- 兜底策略采用「全局默认 \+ 成本中心可选覆盖」：成本中心未覆盖时跟随全局默认；覆盖后按到期后自动放行或强制拦截执行，修改全局默认不影响已覆盖的成本中心；费用主体与成员按所属成本中心的生效策略执行。

- **删除成本中心：**展示关联费用主体数量，提示将一并删除这些费用主体及其成员配额。用户确认后，级联删除成本中心及其全部费用主体（含默认费用主体）。

- **成本中心预算校验：**预算总额允许为 0，为0时是未配置状态。如果已有下级费用主体，编辑成本中心预算时不得低于子费用主体当前可用预算合计；低于时阻止保存，提示先调整下级预算。

- **管理范围变更：**已独立修改的默认费用主体覆盖范围不联动。缩小成本中心范围时，若子费用主体覆盖范围超出新范围，阻止保存并列出冲突主体。

- **下级费用主体预算配置：**基础预算允许为 0；大于 0 时不得超过成本中心剩余可分配额度，超出时阻止保存。

- **有效期到期策略**：结束后默认跟随全局默认。成本中心可单独选择「到期后自动放行」或「强制拦截」以覆盖全局；修改全局默认不影响已覆盖的成本中心。

**详情页**

#### 2\.3\.5 业务规则

- 配置预算时，预算超出所属成本中心预算上限时阻止保存并提示上限，仅超出剩余额度时提示可能触发超额预警。

- 超管、系统管理员、成本中心负责人编辑费用主体时可编辑所有信息，费用主体负责人不允许修改基础预算，同一用户拥有多种角色取并集。

- 不分期按整个有效期总额管控；分期按周期生成预算计划。

- 切换周期类型时保留已完成消费，不清零、不丢失，并按新的周期计划展示。

- 编辑费用主体时的成员配额联动：

  - 覆盖范围变化释放不再属于范围的成员配额；

  - 有效期缩短或延长时，到期日与主体一致的成员跟随新的结束日，单独设置过结束日的成员仅在超出时截断，缩短当前期需在预览中展示失效金额，新增周期默认 0；

  - 周期类型变化时，配额周期默认跟随费用主体的成员新周期重新生成周期计划，没有默认跟随费用主体周期规则的成员保留原设置，配额总额按新周期重新均分，已完成消费不重算；周期变更当日显示实际生效时刻。详见 2\.4\.5 业务规则。

- 覆盖范围可组合选择部门（含下级部门）、指定成员和用户组，至少选择 1 项。候选成员只能来自所属成本中心的管理范围；按用户 ID 去重。编辑后离开覆盖范围的成员配额自动释放。

- 费用主体当前可用预算为 0 时可被 API Key 选为预算来源，在所有费用主体选择列表中排在最后并标注「未配置预算」，不在选择阶段禁用；额度管控开启后，实际请求仍按预算策略检查。

### 2\.4 成员配额管理

#### 2\.4\.1 业务说明

成员配额用于控制费用主体下单个成员的消费。共享模式可设置单人上限，独立模式按已配置的成员额度执行；预警阈值和超额策略默认继承费用主体，通知接收人默认成员本人、渠道默认站内信。

#### 2\.4\.2 数据模型

**MemberBudget**

#### 2\.4\.3 功能点

- **F\-CC\-16 成员概览**：展示整个有效期的分配摘要；字段见 2\.4\.4，金额口径见 2\.4\.5。

- **F\-CC\-17 成员列表**：展示整体与本期预算、配置和额度状态，支持筛选及单人操作；字段见 2\.4\.4。

- **F\-CC\-18 配置 / 编辑配额**：通过抽屉设置有效期、周期计划、预警和通知；编辑已配置成员时只读展示历史周期与已消费，按「有效期总额 − 历史占用」生成当前及未来周期，保存前预览影响并校验。

- **F\-CC\-19 批量配置**：仅独立配额模式下、为当前未配置成员创建配额；已配置成员不出现在可选列表，也不能批量修改。任一成员已配置或校验失败则整批不提交。

- **F\-CC\-20 释放配额**：成员不再属于覆盖范围时释放其配额，额度回到费用主体。

- **F\-CC\-21 未配置提示**：独立模式下存在未配置成员时提示「还有 N 名成员未配置配额，这些成员当前无法使用该预算」。

- **F\-CC\-22 单人消费金额上限**：共享模式下可配置上限、周期和达到上限后的动作，提供建议值与清除操作；规则见 2\.4\.4—2\.4\.5。

- **F\-CC\-23 配置引导弹窗**：

  - 成本中心创建成功后，引导用户去配置费用主体。主按钮「去配置费用主体」，打开默认费用主体编辑弹窗并聚焦预算输入框；默认费用主体覆盖范围已带出成本中心覆盖的部门，可继续修改；次按钮「稍后处理」关闭弹窗，保留列表中的「未配置预算」标记。

  - 费用主体预算配置成功后触发引导弹窗，引导用户去配置成员配额（新建且预算 \> 0；或编辑时预算由 0 / 空变为 \> 0）。主按钮「去配置成员配额」→ 打开费用主体详情并定位到「成员配额管理」Tab，独立模式同时打开批量配置弹窗，共享模式聚焦「单人消费金额上限」卡片；次按钮「稍后处理」关闭。

- **F\-CC\-24 通知中心接入**：扫描三个预算层级的额度提醒与成本中心、费用主体的到期提醒；文案、接收人和去重规则如下。

到期提醒在结束日前 30、15、3 天发送，到期当天不发送；不受额度管控总开关影响。

#### 2\.4\.4 页面设计

- 顶部「分配摘要」固定展示整个有效期的预算额度、已单独配置、剩余可分配及有效期；指标旁提供口径说明，剩余可分配口径见 1\.5。

- 共享模式在成员配额管理 Tab 顶部展示「单人消费金额上限」：

  - 金额输入框、动作下拉（跟随费用主体 / 仅告警 / 阻断请求）；不分期时金额标签为「每人累计上限」，分期时为「每人每期上限」，并显示当前上限周期的起止日期；

  - 动作下拉默认「跟随费用主体（当前：\{生效动作\}）」，未设置金额时动作下拉禁用；

  - 「上限周期」默认跟随费用主体；可主动选不分期，或选择不粗于费用主体的年度 / 季度 / 月度。选择分期后，同一上限金额在有效期内各期分别适用，不要求填写各期金额；未用上限不结转。

  - 上限周期与费用主体周期一致、当前父周期生效且存在共享成员时，展示「建议值 ¥X（N 名共享成员）」及「应用建议值」按钮；计算口径见 2\.4\.5，应用前需确认。条件不满足时就近说明原因；费用主体已到期时提示调整有效期，所属成本中心也已到期时先提示延长成本中心有效期。

  - 操作依次为「应用建议值」「保存」「清除上限」。未配置上限时禁用清除并提示「当前未设置单人消费金额上限」；清除前说明影响，确认后将上限设为 0、动作恢复继承，并提示「已清除单人消费金额上限，成员共用共享池额度」。

- 成员列表工具栏：左侧为姓名 / 账号搜索、配置方式筛选、额度状态筛选、部门筛选与重置；右上侧为「配置配额」，点击后打开批量配置抽屉。

- 成员表格列：用户名、姓名、部门、配置方式、周期与有效期；整体预算（总预算、累计已消费、剩余额度、整体使用率）；本期预算（本期预算、有效临时追加额度、本期起止时间、本期已消费、本期使用率）；额度状态、超额动作、操作。本期预算已包含有效临时追加；不分期成员的本期五列显示「—」。

- 成员详情抽屉：展示成员配额规则、各期计划、追加记录及变更记录。各期计划列出基础配额、临时追加、已消费和剩余；增加每期配额记录列出每期增量、涉及期数、累计增加额与来源工单。

#### 2\.4\.5 业务规则

- 成员配额金额必须大于 0，有效期默认继承所属费用主体，并只能在费用主体有效期内调整。已结束周期作为历史周期只读展示，历史消费始终保留，不因有效期、周期或额度调整被回退、裁剪或重算。成员配额到期后剩余额度失效，不自动结转。

- 共享模式下成员分为「已单独配置配额成员」和「共享成员」。已单独配置成员占用独立配额，按成员周期计划扣减；共享成员不占用个人独立配额，消费直接扣减费用主体共享预算池。独立模式下，所有成员需要单独配额，未配置配额的成员无法使用该费用主体预算。

- 新增或调整成员配额时，需按费用主体剩余可分配额度校验；调整时先排除成员原配额（包括生效临时追加），再计算净占用。已单独配置统计包含成员当前持有的各期基础配额与生效中的临时追加，费用主体剩余可分配按第 1\.5 节规则计算。

- 成员周期可继承费用主体，也可主动设置为不分期或不粗于费用主体周期的分期粒度。周期计划按总额均分生成，允许调整每一期额度，最后一期自动补齐；合计不等于总额时禁止保存。周期切换仅影响生效后的周期，已结束周期锁定，历史消费保留。具体可分成以下三种场景：

| 场景                     | 历史周期展示                                       | 历史占用（用于扣减）                           | 新周期总额                  |
| ------------------------ | -------------------------------------------------- | ---------------------------------------------- | --------------------------- |
| **不分期 → 分期**        | 展示原不分期周期（开始日\~今天）的总额度与实际消费 | 实际消费金额                                   | 有效期总额 − 已消费         |
| **分期 → 更粗/更细周期** | 展示各已结束周期的额度与消费明细                   | 已结束周期的预算合计 \+ 当前进行中周期的已消耗 | 有效期总额 − 历史占用合计   |
| **周期不变、只改金额**   | 已结束周期原样只读，不可修改                       | 各期预算合计                                   | 新有效期总额 − 历史占用合计 |

- 成员默认继承费用主体的预警阈值、严重预警阈值和超额策略；若保持继承，费用主体调整后成员同步生效。共享成员可配置单人消费金额上限，留空或为 0 表示不限制。单人上限不占用费用主体预算，仅用于限制共享成员在对应周期内的消费；达到上限后按「仅告警」或「阻断请求」执行。已单独配置配额的成员不受单人消费金额上限约束。

#### 2\.6\.3 范围、统计与权限

**三类范围及统计口径**

| 范围     | 可选与可查看对象                                                                                                 | 费用明细归集口径                                |
| -------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 部门     | 超管、系统管理员为全部部门；部门管理员仅为本人所属部门及其全部下级部门                                           | `costDepartmentId` 属于所选部门及其全部下级部门 |
| 成本中心 | 超管、系统管理员为全部成本中心；其他用户仅为 `ownerId` 等于本人 ID 的成本中心                                    | `costCenterId` 等于所选成本中心                 |
| 费用主体 | 超管、系统管理员为全部费用主体；费用主体负责人仅为本人负责的主体；成本中心负责人另可管理其成本中心下全部费用主体 | `feeSubjectId` 等于所选费用主体                 |

- 账单范围、权限过滤和历史归属使用数据库保存的实际归属 ID；费用明细的费用主体类型、名称和成本中心名称按消费管控状态展示。

- 部门管理员身份本身不授予成本中心或费用主体权限；成本中心、费用主体负责关系本身也不授予部门权限。

- 同一用户兼具部门管理员、成本中心负责人、费用主体负责人等多个身份时，各身份范围取并集；任一身份失去后，剩余身份仍按各自规则生效。

- 费用主体的覆盖部门、覆盖用户组只用于业务归集，**不授予账单或费用明细查看权限**。

#### 2\.6\.4 功能点与页面设计

- **F\-CC\-28 手动生成账单**：在「生成账单」弹窗依次选择月度 / 周度、账期、范围类型与范围对象。范围类型只展示当前用户至少拥有一个可选对象的类型；切换类型后清空原对象并从新类型的可选项中选择。选择本月或本周时展示提示：「账单数据每日更新，当前已更新至 YYYY\-MM\-DD；今日消费将在次日账单中体现。」其中日期动态展示实际截止日期。

- **F\-CC\-29 账单列表**：「消费账单」Tab 支持周期类型、范围类型、范围对象、账期月份筛选，展示账期、周期、范围、金额、Token、请求次数、状态、生成时间与操作；所有筛选项和结果仅从可查看账单派生。

- **F\-CC\-30 账单详情**：按「账单详情统一口径」展示总览与六个维度的消费金额，支持管控状态筛选、维度筛选、排序、导出，并可携带当前账单范围与账期进入费用明细。

- **F\-CC\-31 自动任务管理**：「账单任务」Tab 展示自动生成周期、范围类型、账单范围、邮件外发、状态、下次生成时间、创建时间与操作；支持按范围类型、范围对象、状态筛选。任务列表不按创建人过滤，同一范围内有权限的管理者均可查看和管理。

- **F\-CC\-32 新建 / 编辑任务**：填写生成周期、范围类型、范围对象、邮件外发开关和收件邮箱。编辑时允许调整周期和范围，保存后按新周期计算下次执行时间；历史已生成账单保留原范围与来源快照。

- **F\-CC\-33 任务启停与删除**：启用后重新计算下次执行时间；禁用后不展示下次执行时间；删除前二次确认并展示范围名称。删除任务不删除已经生成的账单。

- **F\-CC\-34 费用明细**：按可见明细生成用户、模型、供应商、费用主体、成本中心和部门筛选项；消费归属及管控状态展示口径见 1\.5。

- **F\-CC\-35 导出**：账单可导出完整六维度文件或当前维度文件；费用明细可导出当前筛选结果或当前账号可见的全部明细。任何导出均不得读取未授权的全量数据。

#### 2\.6\.5 业务规则

- 月度账期为自然月 1 日至月末；周度账期为所选日期所在周的周一至周日。统计按请求发生日期的起止日闭区间过滤。

- 消费账单数据每日更新，最早可获得截止昨日的数据；手动生成账单选择本月或本周时展示对应数据截止提示。费用明细保持现有页面展示，不增加该提示。

- 总消费、个人用途 / 项目用途消费、Token 和请求次数均根据范围内的请求级明细汇总，六维度分析复用同一批账单明细，不能采用另一套权限或统计口径。

- 同一 `periodType + periodStart + scopeType + scopeId` 只保留一份账单；重复生成或任务重复触发时复用该账单，避免同范围同账期重复出账。手动重新生成沿用原账单 ID 并覆盖生成状态与结果。

- 自动任务按每月 1 日 02:00 或每周一 02:00 执行，调度方负责计算本次账期边界；生成入口复用手动账单统计逻辑，写入 `generatedBy = AUTO` 与 `taskId`，并回写任务 `lastRunAt`、`lastBillId`。

- 邮件外发开启时至少填写一个有效邮箱，支持逗号、分号、顿号或空白分隔并自动去重；关闭时清空收件邮箱且不发送邮件。

- 负责人或角色变更后权限即时重算：原用户立即失去对应账单、任务、明细与导出访问权；已打开的详情和提交中的写操作也必须重新校验。历史账单与任务不随负责人变化转移或删除。

## 4\. 非功能需求

### 4\.1 性能

- 列表与详情首屏接口响应时间不超过 2 秒（原型阶段以本地数据模拟）。

- 排行与趋势查询支持按成本中心、费用主体、时间范围分页或限制返回条数。

### 4\.2 安全与权限

**角色范围**

- 超级管理员、系统管理员：无需额外授权即可创建成本中心与费用主体，并查看和管理全部成本中心与费用主体。

- 成本中心负责人：由成本中心 `ownerId` 字段指定，可管理自身为负责人的成本中心及其下全部费用主体。

- 费用主体负责人：由费用主体 `ownerId` 字段指定，可管理自身为负责人的费用主体及其下全部成员配额。

- 普通成员：无预算管理权限，只能查看与自己相关的额度信息。

**Key 禁用原因与恢复**

关联费用主体的变化会联动影响 API Key 可用性。Key 维护独立的禁用原因集合，支持多原因叠加：

| 禁用原因                  | 触发                                       | 解除                                                        |
| ------------------------- | ------------------------------------------ | ----------------------------------------------------------- |
| QUOTA\_CONTROL\_REQUIRED  | 额度管控已启用，但 Key 未关联费用主体      | 用户 / 管理员为 Key 绑定有效费用主体后移除                  |
| FEE\_SUBJECT\_UNAVAILABLE | 关联费用主体被删除或到期                   | 费用主体恢复可用，或用户 / 管理员改绑可用费用主体后移除     |
| OUT\_OF\_COVERAGE         | Key 所属用户不再属于关联费用主体的覆盖范围 | 用户重新进入覆盖范围，或用户 / 管理员改绑可用费用主体后移除 |
| MANUAL                    | 管理员或 Key 所有者手动禁用                | 手动启用时移除该原因                                        |

- 管控关闭时上述费用主体相关原因不生效，Key 除 `MANUAL` 外均为可用状态；未绑定费用主体的 Key 也可正常创建。

- Key 最终状态：只要禁用原因集合非空即为禁用，为空即为启用；**手动禁用独立存储，不会因费用主体恢复或用户重新进入范围而自动解除**。

- 手动启用时除 MANUAL 外仍有其他原因则拦截，悬浮文案需明确告知「费用主体不可用 / 用户不在费用主体覆盖范围」，引导用户先处理费用主体或覆盖范围。

- 费用主体被彻底删除时，原关联 Key 保持禁用（该原因不会因恢复动作自动移除），需由所属用户或管理员改绑可用的费用主体后恢复。

**实现约束**

- 负责人判断实时生效：成本中心负责人可管理其下全部费用主体，费用主体负责人仅可管理本人负责的费用主体；变更后页面不刷新即可看到按钮禁用 / 启用状态切换。

- 成本中心 `ownerId` 变更后，所有未自定义通知接收人的预警级别自动跟随新负责人。

- 接口层按 `cost.budgets` 权限 \+ 对象级 `ownerId` 双重校验，禁止跨成本中心修改费用主体。

### 4\.3 数据一致性

- 成本中心已分配额度、费用主体当前可用预算、成员配额之间保持勾稽关系，删除或调整时同步释放额度；成员当前可用预算仅用于成员消费核算。

- 已产生的消费不回溯调整。

- 成本中心、费用主体与成员配额均不允许超配；配置及增加每期配额时，按费用主体各受影响周期与总额的剩余可分配校验。

- 状态计算结果需与列表、详情、工单审批页保持一致。

### 4\.4 兼容与可用性

- 页面遵循《原型页面布局与 UX 要求》，金额统一使用「¥」展示并保留两位小数。

- 空列表、加载失败、配置缺失均需提供可执行的下一步操作。

- 支持 1280px 及以上屏幕；费用主体详情为独立页面，内容区随页面宽度自适应，概览双卡在 900px 以下堆叠为上下两栏。

## 5\. 验收标准

1. 关闭额度管控后，新消费只计入实际用量；重新开启时，Key 状态按当前费用主体关系重算。

2. 预算为 0 且未消费的对象显示「未配置」；额度管控开启后，预计消费大于 0 的请求仍按超额策略处理。

3. 成本中心、费用主体和成员分别按自身额度判定状态；达到预警或严重预警时不阻断，达到超额时执行所配置的动作。

4. 成本中心的有效期结束策略可跟随全局或单独覆盖；全局默认值变化不影响已覆盖的成本中心。

5. 新建成本中心后生成预算为 0 的默认费用主体；调整其覆盖范围后不再跟随成本中心变化，删除成本中心时级联处理其费用主体与成员配额。

6. 缩小成本中心管理范围或扩大费用主体覆盖范围时，超出管理范围的配置无法保存；费用主体可只选择管理范围内的部分成员。

7. 费用主体预算超出成本中心剩余可分配、成员配额超出费用主体剩余可分配时，保存或审批执行失败并显示可分配额度。

8. 项目用途与个人用途 Key 分别带出可用的项目型与部门型费用主体，允许调整；预算为 0 的主体仍可选择，但消费按预算策略检查。

9. 不分期费用主体按有效期总额检查；分期费用主体同时检查当前期与有效期总额，不提前使用未来期额度。切换周期保留历史消费。

10. 编辑费用主体的覆盖范围、有效期或周期后，成员资格和计划按 2\.3\.5、2\.4\.5 联动；已发生消费不回滚。

11. 独立模式未配置配额的成员不能使用该预算；共享模式成员共用预算池，单独配置配额的成员不受共享单人上限约束。

12. 增加每期配额按 1\.5 写入当前及后续各期基础配额；任一受影响期或总额不足时不生效，未来期额度不能提前消费。

13. 单人上限建议值按 2\.4\.5 的公式计算；清除上限后，该成员恢复共享池规则与继承的超额动作。

14. 三层额度提醒及成本中心、费用主体到期提醒按 2\.4\.3 的模板、接收人、渠道和去重规则发送；额度增加或有效期变更后允许再次触发相应提醒。

15. 创建成本中心和首次配置费用主体预算后显示可跳过的配置引导，不阻断保存。

16. 账单和自动任务支持部门、成本中心、费用主体三类范围；列表、详情、筛选和导出均按对象权限过滤，越权直达不泄露数据。

17. 同一范围与账期重复生成账单时复用原账单；任务禁用或删除不影响历史账单，邮件外发仅在存在有效收件邮箱时启用。

18. 费用主体详情可从各入口进入并支持浏览器前进、后退；分期展示整个有效期与本期双卡，不分期展示单卡。

## 附录A：与V1\.4的核心差异

**预算由成本中心承担，费用主体决定一笔请求使用哪笔预算，成员配额决定该人在该费用主体内能用多少；请求归属以 API Key 绑定的费用主体为准。**

| **维度**     | **旧版：部门—项目—个人**                   | **当前：成本中心—费用主体—成员**                                                                                                                                                           |
| ------------ | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **预算归口** | 总部和部门预算为主，项目预算由责任部门承担 | 成本中心承担总预算，再分配给费用主体；成本中心或费用主体可包含多个部门，允许跨层级的部门在同一成本中心或费用主体，但所有成本中心是平级关系、所有费用主体也是平级关系，用户挂在费用主体下。 |
| **消费归属** | Key 关联项目则计入项目；否则计入使用人部门 | Key 按用途绑定费用主体，消费归集到所属成本中心                                                                                                                                             |
| **个人额度** | 个人预算管非项目消费；项目成员共用项目预算 | 成员额度按费用主体配置，可用共享池或独立配额                                                                                                                                               |
| **预算启停** | 无有效预算会影响使用                       | 全局管控关闭时仅记录用量；开启后检查三层额度                                                                                                                                               |
| **追加预算** | 可申请个人预算或项目预算追加               | 工单申请本人追加；费用主体预算不足由有权限者调整                                                                                                                                           |
| **管理权限** | 部门管理员按组织范围管理预算               | 成本中心、费用主体负责人按负责对象管理；部门管理员不管理预算对象                                                                                                                           |
