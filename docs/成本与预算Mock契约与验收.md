# 成本与预算 Mock 数据与验收

使用 `npm run dev:mock`，账号见《Mock账号配置.md》。普通 `npm run dev` 对接真实后端，不加载本地样例。数据保存在当前开发服务的共享内存中；刷新及跨页面读取同一结果，重启服务恢复初始样例。

## 样例入口

- `/identity/projects`：23 个项目，包含正常、禁用、归档、未配置预算以及零消费项目。
- `/account/projects`：按当前用户成员关系展示项目；项目预算、成员消费与预算管理、费用记录共享数据。
- `/cost/budgets?tab=project`：项目预算、周期、已消费、余额及历史；总部知识助理为 `project-10`。
- `/cost/budgets?tab=user`：用户预算，包含临时追加及过期追加；审批结果直接更新此处共享状态。
- `/personal/work-orders`：默认管理员“我的申请”包含项目/本人永久增加待审批、拒绝、撤回；“待我审批”包含项目/本人临时追加二级审批。已通过的临时追加与预算中的追加记录关联。
- `/cost/expenses`、`/cost/bills`：费用原始记录、账单维度统计及预算消费共用同一记录集合，包含免费、用量缺失、失败计费及缓存 Token 分支。

工单样例按稳定 ID 去重补种，不因已有申请而跳过其他样例，不覆盖已审批、撤回或拒绝的结果。首次初始化所需的用户尚未就绪时允许后续重试。

## 完整样例与共享来源

- 项目预算：23 个项目覆盖未配置、停用、正常、预警、临界及超额。总部知识助理采用 10—12 月自定义分配（20000/30000/20000），成员上限 8000/10000/12000；财务项目另有季度和年度方案，保留已结束、当前及未来周期。
- 本人预算：默认 `mock_admin` 已配置全年 12000 元、自定义月分配；11 月基础 1300、有效临时追加 500、已消费 295、可用 1505。另有过期追加 300，保留在 10 月历史周期，不计入本期额度。
- 项目临时追加：总部知识助理包含当前 250 元、历史 150 元，关联 `WO-2026-0122/0123`；本人追加关联 `WO-2026-0120/0121`。拒绝、撤回、待一级、待二级、通过生效都有可读记录。
- 费用：基于共享用户、部门、项目及物理模型生成 3821 条不可变请求记录；96 条未知用量、110 条已知用量免费请求、121 条失败计费、77 条部分成功，另有缓存 Token。计费项小计等于请求金额，Token 合计一致；不再使用备用模型名称充当 ID，零消费项目不生成虚构请求。
- 账单：9 条初始记录，包含周/月账单、失败账单，以及当前月包含项目费用的账单 `bill-current-projects`。当前月总额 301679 = 非项目 12159 + 项目 289520，共 871 次请求。项目维度只汇总项目费用，部门/用户/模型/供应商维度汇总全部费用。
- 自动任务：默认管理员有启用月任务、停用周任务；另一个创建人的任务由服务端隔离。月任务关联当前月账单，手动生成不创建任务。

服务端 `runtimeState` 保存唯一业务集合。项目预算账本保存配置版本、周期、追加与历史快照；本人预算保存共享用户 ID；预算消费、项目个人消费/排行、账单汇总/维度和费用导出都读取同一份费用记录。模型初始化先于项目及费用快照，模型导入不重写既有费用记录。

## 已确认业务口径

- 临时 mock 契约已获允许；列表分页为 `page/page_size`，响应包含 `items/total/total_pages`。
- 项目归档停用预算，重新启用后需要重新配置。
- 非总部本次配置超过来源总余额时禁止保存；不累计其他已配置额度进行扣减，不汇总用户预算额度作为部门预算占用。
- 两级审批全部通过后才更新额度；过期、版本冲突、无权操作不能伪造成功。
- 确认框无明确要求时不增加原因输入；调整批准内容和拒绝处理意见保留其明确要求。
