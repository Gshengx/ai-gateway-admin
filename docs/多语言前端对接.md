# 多语言前端对接指南

适用于 AIS Gateway 控制面 `/api/v1`。前端统一使用后端语言代码：**简体中文 `zh-CN`，英文 `en`**。支持 `locale` 的读取接口传 query 参数；控制面请求同时携带相同的 `Accept-Language`。全局切换语言时保存用户偏好，再刷新页面数据。

## 1. 语言代码从哪里取

调用公开接口 `GET /api/v1/locales/options`，使用 `data.items[].locale_code` 作为语言选项值，`data.default_locale` 作为系统默认语言。

| 语言     | API 使用的 `locale_code` | 前端语言包的 `ui_locale` |
| -------- | ------------------------ | ------------------------ |
| 简体中文 | `zh-CN`                  | `zh-CN`                  |
| 英文     | `en`                     | `en-US`                  |
| 法文     | `fr`                     | `fr`                     |

截至 2026-11-19，开发、联调环境均只启用 `zh-CN`、`en`，默认 `zh-CN`。法语包已交付，但尚未启用；运行时始终以 options 返回值为准。语言包映射见 [ui-locales.json](../web-demo/src/api/generated/ui-locales.json)，不要直接把 UI 的 `en-US` 当作后端标准代码提交。

## 2. 请求怎么传

以英文为例，权限和角色接口这样调用：

```http
GET /api/v1/me/permissions?locale=en
Accept-Language: en
```

```http
GET /api/v1/roles?locale=en
Accept-Language: en
```

中文将两处 `en` 改为 `zh-CN`。`locale` 可省略；权限、角色等接口按以下顺序选择当前启用的语言：

**query `locale` → 用户 `preferred_locale` → `Accept-Language` → 系统默认语言。**

因此，用户偏好为中文时，只传 `Accept-Language: en` 不能覆盖该偏好；传 `?locale=en` 可以。本次 query 选择不会保存偏好。

**全局切换语言按以下流程处理：**

1. 从 options 返回的语言中选择目标值。
2. 调用 `PATCH /api/v1/me/preferences` 保存目标语言，例如 `{"preferred_locale":"en"}`。复用现有认证客户端，携带会话 Cookie、合法 Origin、`Content-Type: application/json`、`X-CSRF-Token` 和 `Idempotency-Key`；该操作要求完整会话及 `personal.profile:WRITE` 权限。
3. 保存成功后切换前端语言包，更新控制面请求的 `Accept-Language`；对声明了 query `locale` 的展示读取接口，传入相同值。
4. 重新读取菜单权限、个人资料和当前页面数据。清除旧分页 `cursor`，从首屏或第 1 页重新加载；保留用户未保存的表单内容。

同一次保存超时重试复用原幂等键，下一次切换语言使用新键。保存失败要提示用户，不能将仅在本地切换视为全局切换成功。自行缓存响应时，缓存键包含语言和用户权限上下文；模板类数据还应包含适用版本。

## 3. 页面显示哪些字段

| 数据                              | 应使用的显示字段                                        | 语言来源                                                                              |
| --------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `/me/permissions` 菜单及分组      | `navigation.items[].title`、`navigation.groups[].title` | `title_locale` 是标题实际来源语言；`navigation.locale` 是本次选中的语言               |
| 角色                              | `display_name`、`display_description`                   | `resolved_locale` 是实际命中的译文语言；不要用原始 `name`、`description` 代替显示字段 |
| 部门、用户组及用户关联的部门/角色 | 按各接口契约使用对应对象的 `display_name` 等本地化字段  | 有 `resolved_locale` 时，以它判断实际译文语言                                         |
| 统一 API 错误提示                 | 前端按 `code`、`params` 翻译                            | 后端统一返回 `code/data/params/request_id`，不提供随 locale 翻译的 `message`          |

`requested_locale` 不代表一定命中了该语言的译文。缺少译文时可能回退到默认语言或业务原文；实体 `resolved_locale` 为 `null` 表示没有命中译文。菜单和业务标签直接展示后端返回文案；前端按钮、固定枚举和错误提示使用前端语言包。ID、代码和枚举值保持稳定，不按翻译后的文字判断业务状态。

## 4. 哪些接口支持 query locale

以下均为 GET，路径统一加 `/api/v1` 前缀；`locale` 都可省略。

| 分类           | 路径                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 权限、角色     | `/me/permissions`、`/roles`、`/roles/{role_id}`、`/assignable-roles`、`/user-role-options`、`/permission-resources`、`/permission-resources/{resource_id}`                |
| 用户、部门     | `/users`、`/users/{user_id}`、`/departments`                                                                                                                              |
| 用户组         | `/groups`、`/groups/{group_id}`、`/groups/initial-member-options`、`/groups/member-department-options`、`/groups/{group_id}/member-options`、`/groups/{group_id}/members` |
| API Key        | `/api-keys`、`/api-keys/{key_id}`                                                                                                                                         |
| 条款           | `/terms/current`、`/terms/required`                                                                                                                                       |
| 语言目录、审计 | `/locales`、`/audit/management`、`/audit/annotations`、`/audit/terms-acceptances`                                                                                         |

其他接口不要统一追加 `?locale=`，未声明的 query 参数可能返回 `400 MALFORMED_REQUEST`。以下差异按当前实现处理：

| 接口或模块                                            | 语言选择方式                                                                                                                                 |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 供应商 P 域、模型创建/管理/计价/检测中的本地化字段    | 用 `Accept-Language`。非空请求头优先；省略请求头时使用用户偏好，再回退默认语言。非空请求头未匹配启用语言时直接回退默认语言，不再采用用户偏好 |
| 模型授权 A 域的模型摘要，包括 A04/A05/A07/A09/A11/A13 | 用户偏好优先于请求头；先保存偏好，再刷新这些数据，不能将整个模型模块都当作请求头优先                                                         |
| `/me/profile`                                         | 只使用已保存且启用的用户偏好，否则用系统默认；不读取 query `locale` 或 `Accept-Language`                                                     |
| 用户导入模板及相关本地化输出                          | 请求头匹配启用的导入语言包时优先采用，未匹配时再用用户偏好、默认语言                                                                         |
| `/locales`、审计接口                                  | 接受 query `locale` 不表示全部内容会翻译；语言目录返回本地名称，审计保留历史原文                                                             |

## 5. 其他语言字段不要混用

- `preferred_locale` 是个人偏好，通过 `/me/preferences` 或 `/me/profile` 的 PATCH 保存。使用 options 返回的代码；`en-US` 在部分读取接口可回退为 `en`，保存偏好时应直接传 `en`。传 `null` 可清除偏好，空字符串无效；清除后 `/me/profile` 使用系统默认语言。
- 翻译维护接口的 `locale_code` 或 `{locale_code}` 指定正在编辑哪一份译文，不表示当前页面语言。系统设置的 `default_locale` 则是系统默认语言。
- 接受条款时，`POST /api/v1/terms/accept` 的 `locale_code` 使用刚刚展示的条款响应中的 **`resolved_locale`**，配合同一响应的 `terms_id` 和 `content_digest`，不要直接填 UI 偏好或 `requested_locale`。
- 未指定 query 语言时直接省略参数；不要传 `locale=`、`locale=null`、重复 `locale` 或 `zh_CN`。按 options 的原值传递，避免依赖各接口不同的纠错和回退行为。
- 自定义名称、描述、管理员确认保存的价格时段名及历史审计原文，不会因为切语言就自动翻译。

## 6. 联调时快速自查

- 中文、英文菜单与角色显示字段切换正确；英文 API 值始终是 `en`。
- 保存偏好后，个人资料和模型授权摘要也使用目标语言；保存失败时有明确提示。
- 切换语言后重新加载列表，没有复用旧语言的游标或缓存。
- 缺少译文时正常显示后端回退文案，没有把回退结果误标为请求语言。
- 条款接受使用实际展示译文的 `resolved_locale`，错误提示由前端翻译。

接口参数以[现行 OpenAPI](current/openapi.json)为准；认证与写请求见[首次联调](FIRST_CALL.md)，错误提示见[字段校验错误](VALIDATION_ERRORS.md)，模型字段的详细展示规则见[模型接入前端指南](../docs/model-access/rebuild-v14/07-前端协同对接指南.md)。
