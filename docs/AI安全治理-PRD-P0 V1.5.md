## 1\. 模块概述

### 1\.1 业务目标

建立“访问控制 →（数据控制 ∥ 安全检测）→ 响应侧数据控制与安全检测 → 审计留痕”的治理链路。访问控制按用户、模型和环境条件控制模型访问；未命中访问控制策略时默认放行。访问控制通过后，数据控制与安全检测分别按策略优先级选取首条匹配策略，对请求执行检测和处置；数据控制默认只检查请求，策略可通过“检测模型响应”开关选择是否对响应执行敏感数据检测，安全检测仍按规则方向评估模型响应。文件上传行为、格式、大小及后续样本库条件均属于数据控制策略。策略白名单按治理域生效，命中后跳过对应域的控制或检测；审计白名单只保留元数据。审计策略决定交互内容留存范围，未命中审计策略时仅保留元数据。

### 1\.2 P0 范围与实施边界

### 1\.3 核心对象

```Plaintext
访问控制策略 AccessControlPolicy
  └── 用户 + 环境 + 目标模型 + 观察模式
数据控制策略 DataControlPolicy
  └── 用户 + 环境 + 目标模型 + 文件/敏感数据规则动作组 + 观察模式
敏感数据规则 SensitiveDataRule
  └── 字段规则 / 文档模式规则（公开/一般/关键/核心）
安全检测策略 SecurityDetectionPolicy
  └── 目标模型 + 安全检测动作列表 + 观察模式
安全检测规则 SecurityDetectionRule
  └── 提示词注入 / 模型越狱 / 内容合规 / 恶意 IOC；高危/中危/低危
审计策略 AuditPolicy
  └── 用户 + 目标模型 + 全量/仅元数据/自定义审计级别
白名单 Allowlist
  └── 治理域 + 可选匹配条件
```

## 2\. 功能需求

### 2\.1 检测规则

检测规则包括数据控制使用的敏感数据规则和安全检测使用的安全检测规则。规则负责检测并返回标准结果；具体处置由策略中的规则－动作组定义。文件上传行为、格式、大小及样本库关联条件直接配置在数据控制策略中，不创建独立文件检测规则；安全检测规则使用风险级别，敏感数据规则使用敏感级别。

#### 2\.1\.1 检测场景分类

| 规则域   | 类型                                | 检测方向              | 说明                                                                                                                                                                                                                                 |
| -------- | ----------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 数据控制 | 敏感数据内容检测（SENSITIVE\_DATA） | INPUT / OUTPUT / BOTH | 请求侧按规则方向检测；模型响应仅在匹配的数据控制策略开启“检测模型响应”后检查 OUTPUT / BOTH 规则；手工创建字段规则或文档模式规则，也可采纳样本分析建议；文档模式结合语义、字段组、结构与关系识别，规则标记公开/一般/关键/核心敏感级别 |
| 安全检测 | 提示词注入（PROMPT\_INJECTION）     | INPUT / OUTPUT / BOTH | 直接/间接注入、多轮注入、System Prompt 泄露                                                                                                                                                                                          |
| 安全检测 | 模型越狱（JAILBREAK）               | INPUT / OUTPUT / BOTH | 角色扮演、编码绕过、多步越狱及输出验证                                                                                                                                                                                               |
| 安全检测 | 内容合规（CONTENT\_COMPLIANCE）     | INPUT / OUTPUT / BOTH | 违规请求与模型生成内容                                                                                                                                                                                                               |
| 安全检测 | 恶意 IOC（MALICIOUS\_IOC）          | INPUT / OUTPUT / BOTH | 经过网关的输入、输出及工具调用中引用的恶意 IP、域名或 URL；不代表监测网关外的实际访问                                                                                                                                                |

`INPUT` 对应网关请求 `REQUEST`，`OUTPUT` 对应模型响应 `RESPONSE`。安全检测规则按自身方向执行；敏感数据规则请求侧执行 `INPUT` / `BOTH`，响应侧仅在数据控制策略开启“检测模型响应”时执行 `OUTPUT` / `BOTH`。策略不得调用方向不适用或载体不支持的规则。文件检查条件不属于检测规则，配置与执行见 2\.4。

#### 2\.1\.2 数据模型与检测方式

**通用规则字段（DetectionRule）**

| ------------------ | ------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |

| description        | text          | 否                   | 规则说明                                                                                                                                              |
| rule\_domain       | enum          | 是                   | `DATA_LEAKAGE` 或 `SECURITY_DETECTION`                                                                                                                |
| engine\_type       | enum          | 是                   | `SENSITIVE_DATA` / `PROMPT_INJECTION` / `JAILBREAK` / `CONTENT_COMPLIANCE` / `MALICIOUS_IOC`                                                          |
| rule\_type         | enum          | 敏感数据内容规则必填 | 用于区分字段规则（`FIELD`）与文档模式规则（`DOCUMENT_PATTERN`）；创建自定义规则时由用户选择。                                                         |
| category           | enum/string   | 否                   | 敏感数据类别，如员工信息、企业信息、客户信息、产品研发、IT 基础设施；安全检测使用 `engine_type` 作为类型、`sub_category` 表示子类型                   |

| risk\_level        | enum          | 安全检测规则必填     | `HIGH` / `MEDIUM` / `LOW`，展示为高危/中危/低危                                                                                                       |
| direction          | enum          | 是                   | 敏感数据和安全检测规则均支持 `INPUT` / `OUTPUT` / `BOTH`；数据控制响应侧是否调用 `OUTPUT` / `BOTH` 规则由匹配策略的 `response_detection_enabled` 控制 |
| enabled            | boolean       | 是                   | 自定义规则默认启用                                                                                                                                    |
| built\_in          | boolean       | 系统生成             | 是否为系统预置规则                                                                                                                                    |
| config             | JSONB         | 是                   | 按 `engine_type` 及适用的 `rule_type` 校验配置；预置规则的识别定义只读，自定义规则可编辑识别条件                                                      |
| created\_by        | string        | 系统生成             | 创建人标识                                                                                                                                            |

| updated\_at        | datetime      | 系统生成             | 最近更新时间                                                                                                                                          |

**系统执行方式与用户可配置范围**

| 编码         | 展示名称       | 配置范围                                                                                                     |
| ------------ | -------------- | ------------------------------------------------------------------------------------------------------------ |
| `KEYWORD`    | 关键词匹配     | 自定义规则可填写关键词；预置规则由系统维护匹配内容                                                           |
| `REGEX`      | 正则表达式     | 自定义规则可填写表达式；预置规则由系统维护匹配内容                                                           |
| `CLASSIFIER` | 内置小模型检测 | 使用系统内置的小模型进行分类；预置规则绑定由系统维护，用户仅能选择当前已开放的检测类别                       |
| `LLM_JUDGE`  | 大语言模型研判 | 自定义规则可填写自然语言识别条件；预置规则的检测指南由系统维护。使用系统管理中已配置且获准处理相应内容的模型 |
| 系统情报匹配 | 威胁情报匹配   | 仅用于恶意 IOC 规则，由系统按有效情报指标匹配；属于系统执行引擎，不作为管理员可选检测方式                    |

**字段规则（FieldRule，****`SENSITIVE_DATA`**** \+ ****`FIELD`****）**

字段规则识别手机号、账号、密钥、企业项目代号等具体片段，返回精确的来源范围；仅验证后的范围可脱敏。

| config 字段        | 必填                                       | 说明                                                                                             |
| ------------------ | ------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| detection\_method  | 自定义规则必填                             | 从 `KEYWORD` / `REGEX` / `CLASSIFIER` / `LLM_JUDGE` 中选择一种，保存为单元素数组；预置规则只读。 |
| keywords           | 选择 `KEYWORD` 时必填                      | 至少填写一个关键词                                                                               |
| patterns           | 选择 `REGEX` 时必填                        | 至少填写一个正则表达式，需通过安全与格式校验                                                     |
| field\_description | 选择 `LLM_JUDGE` 时必填                    | 填写要提取的具体字段、出现位置或业务上下文、容易混淆但应排除的内容；填写示例见下文               |
| threshold          | 自定义 `CLASSIFIER` / `LLM_JUDGE` 规则适用 | 模型判定置信度，默认 0\.85；预置规则按系统执行配置维护                                           |
| match\_threshold   | 自定义关键词/正则规则适用                  | 命中数量阈值，默认 1；只作用于本字段规则。预置规则的阈值只读                                     |
| mask\_config       | 需要脱敏时必填                             | 指定脱敏方式及其参数；子字段和各方式的含义见下表                                                 |

`mask_config` 的子字段按所选方式填写，字段规则和文档模式规则中的敏感字段使用同一结构：

| 子字段         | 适用方式                    | 含义与填写内容                                                                                                                                             |
| -------------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mode`         | 所有方式必填                | 选择实际执行的脱敏方式：`FULL_MASK`、`PARTIAL_MASK` 或 `REPLACE_TEXT`                                                                                      |
| `mask_char`    | `FULL_MASK`、`PARTIAL_MASK` | 用来遮蔽原文的字符，例如 `*`；选择这两种方式时默认使用 `*`                                                                                                 |
| `keep_prefix`  | `PARTIAL_MASK`              | 从命中片段开头保留、不遮蔽的字符数；例如填 `3` 表示保留前 3 个字符                                                                                         |
| `keep_suffix`  | `PARTIAL_MASK`              | 从命中片段结尾保留、不遮蔽的字符数；例如填 `4` 表示保留后 4 个字符                                                                                         |
| `replace_text` | `REPLACE_TEXT`              | 用来替换整个命中片段的固定文本，例如 `[合同号]`；不填写样本中的真实敏感值。预置字段规则按规则名称生成初始固定文本，格式为 `安全网关检测到敏感数据[规则名]` |

`FULL_MASK` 用 `mask_char` 遮蔽整个命中片段；`PARTIAL_MASK` 仅保留配置的首尾字符，其余用 `mask_char` 遮蔽；`REPLACE_TEXT` 用 `replace_text` 替换整个片段。

人名、组织名称等模型已支持的类别由系统提供为预置检测项，用户直接在策略中选用，无需填写实体类别或模型提示词。规则详情展示支持范围及可调整的治理属性；内部实体类别绑定不接受用户修改。若能力只返回类别而不能准确定位原文，则该次 finding 不可脱敏。企业专有字段通过自定义关键词、正则或自然语言识别条件定义。

选择 `LLM_JUDGE` 时，表单显示“字段识别说明”文本框，要求写清 **识别对象、命中场景、排除情形**。例如：“识别公司项目立项或交付文档中的项目代号，通常位于‘项目代号’或‘项目编号’标签后，格式如 PRJ\-2026\-001；不要把商品型号、工单号识别为项目代号。”这里的编号只是格式示例，不应填写真实敏感值作为固定匹配条件。表单在输入框下显示这条示例，并提供“用测试文本验证”入口；模型返回的范围仍须由系统验证，不能因为模型给出字段值就直接改写。

**文档模式规则（DocumentPatternRule，****`SENSITIVE_DATA`**** \+ ****`DOCUMENT_PATTERN`****）**

文档模式规则识别合同、财务报表、资产清单等整体语义与结构，检测方式固定为 `LLM_JUDGE`，表单不提供检测方式选择。它不依赖字段数量阈值，也不把样本中的真实姓名、账号或合同号作为通用匹配值。

| config 字段           | 必填     | 说明                                                                 |
| --------------------- | -------- | -------------------------------------------------------------------- |
| detection\_method     | 系统生成 | 固定为 `[LLM]`，表单不提供选择                                       |
| identification\_guide | 是       | 文档类型的识别指南；各子字段的填写含义见下表，系统按字段组装检测提示 |
| negative\_guide       | 否       | 排除普通商务邮件、会议纪要或只有零散联系方式等易误报内容的指南       |
| sensitive\_fields     | 否       | 命中文档后需提取并脱敏的业务字段清单；可留空，每项的字段含义见下表   |
| threshold             | 是       | LLM 文档类型判定置信度阈值，默认 0\.85；仍须符合识别指南与排除指南   |

文档模式规则的识别对象由规则名称、子分类和识别指南共同定义。例如“公司合同”规则可归入 `CONTRACT` 子分类，并在识别指南中描述合同的业务语义与结构；无需单独填写文档类型。

`identification_guide` 由管理员按文档类型填写：

| 子字段                    | 含义与填写内容                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `summary`                 | 概括要识别的文档是什么、用于什么业务、通常包含哪些内容；例如“约定交易双方、标的、价款和履行义务的商业合同”。这里描述目标文档类型，不填写某份样本的摘要 |
| `key_indicators[]`        | 判定该文档类型所依赖的核心业务要素；例如合同双方、交易标的、价款与履约约定。应描述需要共同形成的业务语义，不能让单个姓名、电话或金额独立触发           |
| `supporting_indicators[]` | 帮助确认类型的辅助线索；例如合同号、联系人、收款信息。它们提高判断把握，但单独出现不构成命中                                                           |
| `structural_hints[]`      | 文档的布局或格式线索；例如分条条款、商品明细表、签署区。用于辅助判断，不要求示例结构全部出现                                                           |
| `decision_guidance`       | 说明核心要素怎样组合才算命中，以及哪些零散线索不足以命中；例如“交易双方与标的、价款或计价方式、履约约定共同构成合同语义”                               |

`sensitive_fields` 中每一项描述一种需要从命中文档中提取并脱敏的字段：

| 子字段        | 含义与填写内容                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| `field_name`  | 字段的业务名称或角色，例如“合同号”“收款账号”；填写字段类型，不填写样本中的真实编号或账号                  |
| `description` | 说明该字段在此类文档中的具体含义、出现位置或识别边界；例如“合同约定的收款账户，排除正文中的示例账号”      |
| `mask_style`  | 展示给管理员看的遮蔽方式说明，例如“替换为 \[银行账号\]”；与 `mask_config` 对应，不作为实际改写依据        |
| `mask_config` | 系统实际执行的脱敏设置，与字段规则使用相同的 `mode`、遮蔽字符、保留位数或替换文本配置；各子字段含义见上表 |

管理员保存的识别指南是可读的结构化文本，不要求编辑 JSON 逻辑树。以“公司合同”为例：摘要说明交易双方、标的、金额与权利义务；核心指标描述合同双方和交易内容；辅助指标可包括合同号、联系人、收款信息；结构提示可包括条款、明细表和签署区；决策指南明确“仅有姓名、电话或单个金额不足以判定”；排除指南列出讨论合同的邮件与会议纪要。敏感字段可单独配置合同方、联系人、账号和金额的遮蔽方式。指南各项需在规则详情中可查看和版本对比。

`sensitive_fields` 为空时，规则仅用于识别、告警或阻断。文档模式规则配置了需脱敏的敏感字段及各字段的 `mask_config` 后，可供脱敏策略选用；这不保证每次命中均能安全改写。最终替换文本由系统依据 `mask_config` 计算，模型给出的替换建议不能直接执行。只有全部应脱敏的字段均验证通过，才能把整个文档标记为脱敏成功。

**安全检测内容规则（****`PROMPT_INJECTION`**** / ****`JAILBREAK`**** / ****`CONTENT_COMPLIANCE`****）**

提示词注入、模型越狱、内容合规等通用检测能力直接提供为系统预置项。用户选用检测项并调整风险级别、状态；各预置项支持的 `detection_method` 及组合判定方式见系统预置检测规则清单，内置词表、表达式、模型类别绑定和模型阈值由系统提供。`config.check_system_prompt_leak` 等内部检测参数只读，不要求用户重新定义系统提示词泄露检测。

企业确有额外要求时，可在支持的安全检测类别下创建自定义内容规则，选择一种关键词、正则或大语言模型方式，并填写相应识别条件。关键词/正则方式使用 `keywords`、`patterns` 及 `match_threshold` 中适用的字段；大语言模型方式使用 `detection_guide`（检测目标、判断依据、排除情形）和 `threshold`。话题边界规则由管理员填写企业允许或禁止的话题、判断依据和排除情形。系统只开放实际支持的检测类别，不能通过创建表单扩展小模型的识别类别。

| config 字段                 | 必填                                   | 说明                                                                                                                             |
| --------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| detection\_method           | 自定义规则必填；预置规则系统写入       | 自定义规则从 `KEYWORD` / `REGEX` / `CLASSIFIER` / `LLM_JUDGE` 中选择一种，保存为单元素数组；预置规则由系统维护方式及组合判定条件 |
| keywords                    | 选择 `KEYWORD` 时必填                  | 输入要识别的词或短语，一项一个；例如企业禁止讨论的专有话题词。不用于配置预置模型的识别内容                                       |
| patterns                    | 选择 `REGEX` 时必填                    | 输入匹配表达式，一项一个，保存前进行格式与执行安全校验                                                                           |
| match\_threshold            | 选择 `KEYWORD` 或 `REGEX` 时适用       | 命中数量达到该值才判定规则命中，默认 1；只统计当前规则的匹配结果                                                                 |
| detection\_guide            | 选择 `LLM_JUDGE` 时必填                | 用自然语言说明检测目标、判断命中的依据和应排除的情形；例如话题边界规则写明允许或禁止的话题，以及相关澄清问题为何不算越界         |
| threshold                   | 选择 `CLASSIFIER` / `LLM_JUDGE` 时适用 | 模型判定置信度阈值，自定义规则默认 0\.85；预置规则的阈值由系统按实际检测能力维护                                                 |
| check\_system\_prompt\_leak | 仅系统预置的提示词注入规则适用         | 标识是否检查响应中的 System Prompt 泄露；系统维护且只读，不出现在自定义规则表单中                                                |

**恶意 IOC（****`MALICIOUS_IOC`****）**

本类使用系统管理的威胁情报匹配引擎；管理员不配置检测方式。IOC 指标、情报源及指标有效状态由情报数据维护，不写入规则 `config`。

| config 字段       | 必填     | 说明                                                                                                             |
| ----------------- | -------- | ---------------------------------------------------------------------------------------------------------------- |
| detection\_method | 系统生成 | 系统情报匹配引擎；只读，不作为管理员可选检测方式                                                                 |
| ioc\_types        | 是       | 选择需要检查的指标类型，可多选 `IP`、`DOMAIN`、`URL`，至少选择一种；所选类型中任一有效情报指标命中即判定规则命中 |

#### 2\.1\.3 样本分析与文档模式规则执行

样本分析及其字段规则、文档模式规则建议均属于 P1；以下“文档模式运行时判定与脱敏”也属于 P1。本节保留完整流程供本次需求与原型一并评审，P0 仅支持手动创建字段规则。

**敏感数据发现中的分析任务**

1. “敏感数据发现”提供统一的分析任务入口，管理员先选择“上传样本分析”或“从审计记录分析”。“敏感数据规则”页的“样本分析”按钮跳转到发现页并预选上传样本来源。两种来源共用任务列表、建议复核和规则创建流程。字段规则在 P0 即可手动创建；文档模式规则在 P1 可手动创建，两者均不要求先上传样本。

2. 管理员一次上传 1–5 个同类样本，支持可提取文本的 PDF、DOCX、TXT、CSV、XLSX；单文件不超过 20 MB。系统先完成文件类型、大小和恶意文件校验，再逐文件提取原始文件名、系统计算的哈希、识别出的实际格式和文件大小（字节）；文本提取结果保留段落、页码、表格行列与文件边界。纯扫描件或提取失败时显示原因和重新上传入口。

3. 使用系统批准且已配置的外接 LLM 分析样本内容，形成两组**建议**：字段规则建议包含字段名、建议检测方式、该方式所需的关键词/正则、内置实体类别或 LLM 字段识别说明，以及遮蔽示例；文档模式建议包含规则名称、子分类、`identification_guide`、`negative_guide` 和 `sensitive_fields`。每项显示可核对的样本原文依据、位置、置信度与待管理员确认的内容。姓名和电话等通用字段优先作为文档模式特征，不默认生成独立规则；样本中的真实值不得当作通用匹配条件。逐文件元数据单独形成结构化分析结果；后续如建设文件样本库，可经人工确认后用于样本库维护，不自动创建文件检查条件。

4. 管理员可逐项确认、编辑或忽略任意建议，再点击“创建规则”进入对应类型的创建表单，预填建议内容。两类建议可分别创建多条规则；分析任务与规则保存是独立事务，关闭表单不会把建议自动变成规则。建议由管理员确认后才可启用。

5. 分析任务保存状态、逐文件元数据、建议摘要、原始依据片段及操作者；原始样本与提取文本加密暂存并在完成、取消或到期后清理，文件元数据和依据片段按分析任务的权限和期限管理。内容规则建议仅将抽象字段类型与文档特征作为规则条件，不把样本真实值写入通用匹配条件。测试入口可用当前样本和管理员自选内容，系统提供生成的反例作为参考，不要求管理员自行上传反例。明显把零散电话/账号判成整份合同的规则只能保存为禁用草稿，修改并重新测试后启用。

6. “从审计记录分析”支持按时间、用户和模型筛选，并由管理员勾选记录后启动任务。列表仅包含操作者有权访问、审计策略确实留存且含请求正文的记录；分析只读取留存的请求正文，不读取响应、仅元数据或未留存内容。界面显示符合筛选条件、已选记录和不参与分析的记录数量。建议显示命中依据、记录时间、用户与请求位置；任务结果不保留完整请求正文。无可分析记录时说明需要调整筛选条件或检查审计留存策略。

7. 两种来源的任务历史分开标注来源、范围、状态和建议数量。建议可确认、编辑、忽略或恢复；确认后打开对应规则创建表单并预填内容。保存规则与任务结果分开，关闭表单不自动保存或启用规则。

**文档模式运行时判定与脱敏**

- 请求消息、响应正文或可提取文本的文件内容按单条消息、单个文件分别分析，不拼接不同文件的字段。长文件分段处理并在同一文件内汇总证据；无法完整分析时返回 `UNSUPPORTED` / `FAILED`，不能当作未命中。

- 系统按 `identification_guide` 和 `negative_guide` 组装 LLM 判定输入。只有模型确认文档类型、给出可解释的关键/辅助与结构依据、满足决策指南且达到置信度阈值时，文档模式规则才命中。关键词和正则可以提供线索，但缺少固定词不能直接跳过模型判定。合同号、姓名、电话或单个金额不能单独构成“公司合同”命中。

- 若规则配置了 `sensitive_fields`，模型在同次判定中提出每个待遮蔽字段的原文、字段类型、所属文档位置与上下文。系统逐项确认原文确实存在于待发送/待交付内容、字段角色与规则描述相符、位置可唯一定位；同一原文出现多次时按每处上下文分别验证，不默认全局替换。系统依据字段的结构化 `mask_config` 生成替换内容，模型给出的 replacement 只作建议，不直接执行。

- 字段规则和文档模式规则标记同一范围时，已验证的字段规则优先。所有替换在同一份原始内容上计算位置并一次提交；重叠、范围漂移、字段提取不完整或多处同名无法区分时，标记脱敏失败。对于文件载体，必须确认**实际发往模型或返回用户的文件**已安全重写且复检不含应遮蔽的原文；仅改写提取文本而原文件仍携带原文，不算脱敏成功。

- 已选脱敏策略若遇到文档字段提取或替换失败、文件无法安全重写或外接 LLM 超时，默认阻断并生成事件，不按全局 `FAIL_OPEN` 发送原文。只做分类而未配置 `sensitive_fields` 的规则可用于告警或阻断；分类和已验证替换分别记录，不能以“文档已识别”代替“字段已脱敏”。

样本分析与文档模式执行依赖外接 LLM。未配置时在样本分析入口提示“请先配置大语言模型检测能力”，并提供有权限的配置入口；字段规则的关键词、正则及已提供的内置模型能力继续可用。

#### 2\.1\.4 标准检测结果

所有检测方式返回统一 `status`：`MATCHED` / `NOT_MATCHED` / `FAILED` / `UNSUPPORTED` / `UNCONFIGURED` / `NOT_APPLICABLE`。只有 `MATCHED` 包含 findings；部分方法失败时不能把整体结果报告为“未命中”。每个 finding 记录规则域、规则类型、类别、本次实际检测方向、实际检测方式、适用的敏感级别或风险级别、置信度（模型方式）和原始命中证据。证据应包含可核对的命中原文或 IOC 指标值及其位置或载体定位；模型判断还需给出判定依据，不能只返回概括性标签。检测结果及审计详情不遮蔽命中证据，查看和导出仍受审计权限控制。

以下为 P1 文档模式规则的检测结果示例；P0 字段规则使用同一结果结构。

```JSON
{
  "direction": "INPUT",
  "carrier_type": "FILE",
  "status": "MATCHED",
  "findings": [{
    "rule_id": "rule-id-example",
    "rule_name": "公司合同",
    "rule_domain": "DATA_LEAKAGE",
    "engine_type": "SENSITIVE_DATA",
    "rule_type": "DOCUMENT_PATTERN",
    "detection_method": "LLM_JUDGE",
    "sensitivity_level": "IMPORTANT",
    "confidence": 0.94,
    "evidence": {
      "summary": "识别到交易双方、标的与金额及合同条款",
      "matched_indicators": ["交易双方", "交易标的与金额", "权利义务条款"],
      "matched_excerpts": [
        { "text": "甲方：某科技公司；乙方：某制造公司", "source_locator": "文件第 1 页" },
        { "text": "合同总价：人民币 120 万元", "source_locator": "文件第 2 页" }
      ],
      "excluded_indicators": [],
      "maskable": true,
      "verified_replacement_count": 3
    },
    "built_in": false
  }]
}
```

文档模式规则没有配置 `sensitive_fields` 或本次未能验证所有应脱敏字段时，`evidence.maskable=false`；后者还须返回独立的脱敏失败状态，不能以分类命中掩盖改写失败。模型提出的原文、替换建议及文件定位属于**内部改写计划**，只在受控执行链路中短暂存在，不作为标准 finding 或普通审计证据返回。内部改写计划的每项至少包含 `field_name`、`original`、`source_locator`（消息/文件/段落或表格单元）、`context` 和模型建议的 `replacement`；系统验证后另存确定的范围和按规则计算的替换文本。系统完成准确定位、角色核对、重叠处理与实际出站载体复检后，才返回已验证的替换数量和脱敏结果。字段规则是否配置脱敏依据规则的 `mask_config` 判断；实际改写还需验证 `match_positions` 并复检出站载体，不能仅凭配置认定脱敏成功。

恶意 IOC 命中结果还需包含 `indicator_type`（IP / DOMAIN / URL）、原始 `matched_indicator` 和 `threat_source`；指标值与情报源来自有效的情报数据。

文件上传行为及文件属性由数据控制策略直接检查，作为策略执行结果返回命中或未命中，并记录命中的文件与属性证据；不生成检测规则 finding，也不包含规则 ID、规则类型或敏感级别。

#### 2\.1\.5 系统预置检测规则

系统预置规则覆盖数据控制的字段规则、文档模式规则，以及安全检测的提示词注入、模型越狱、内容合规和恶意 IOC；文件上传行为与文件属性检查不在规则清单中。敏感数据规则按员工信息、企业信息、客户信息、产品研发、IT 基础设施分类，并可继续定义子类型；文档模式预置商业合同、财务报表、薪资/人事信息、IT 资产清单、客户信息列表、源代码/配置文件，作为 P1 交付内容保留在清单中，本次评审；P1 初始化时默认禁用，管理员按企业实际数据调整识别/排除指南和敏感字段后启用。完整清单见《AI安全治理\-系统预置检测规则》。

#### 2\.1\.6 检测规则管理功能

本节的字段规则手动管理属于 P0；样本分析及建议采纳、文档模式规则的创建、编辑、测试、启用及策略引用属于 P1。页面和表单规格保留在本 PRD 与原型中供本次评审。

**F\-RULE\-01 检测规则列表**

- “敏感数据规则”位于“AI安全治理 \> 数据控制”的 Tab2；“检测规则”位于“AI安全治理 \> 安全检测”的 Tab2。两个规则 Tab 分别采用左右布局：敏感数据规则按字段规则、文档模式规则分组；文件检查条件由数据控制策略配置；检测规则按 `engine_type` 与 `sub_category` 分类，并显示数量。

- 右侧列表展示规则名称、适用方向、检测方式、敏感级别或风险级别、来源和启用状态。

- 支持按名称搜索，并按内置/自定义状态和启用状态筛选；敏感数据、安全检测规则均可按请求/响应/双向适用方向筛选。支持分页、批量启停。

**F\-RULE\-02 创建和编辑规则**

- 通用字段：规则名称、类型、子类型、适用的敏感级别或风险级别、检测方向和描述；敏感数据类型按员工信息、企业信息、客户信息、产品研发、IT 基础设施及企业自定义类别组织，安全检测类型按提示词注入、模型越狱、内容合规、恶意 IOC 组织。两类规则均按能力选择“请求”“响应”或“双向”；内置标记由系统维护。检测方式按 `KEYWORD`、`REGEX`、`CLASSIFIER`、`LLM_JUDGE` 动态展示相应输入项。

- 字段规则与文档模式规则分别使用独立表单。字段规则按检测方式显示关键词、正则、分类模型能力或字段识别说明及脱敏方式；选择分类模型或大语言模型时展示相应能力的可用状态。文档模式规则固定使用大语言模型研判，按“识别指南、排除指南、敏感字段与遮蔽方式”组织，不显示检测方式选择。文件上传行为及文件属性检查均在数据控制策略中配置，不在检测规则表单中配置。

- P1 交付“样本分析”列表工具栏入口；分析建议可带入相应规则表单，不直接保存或启用规则。字段规则在 P0 可手动创建，文档模式规则在 P1 可手动创建；正例与反例测试提供参考，系统自动提供可编辑的反例候选，不强制管理员上传反例。

- 字段规则使用自身 `mask_config`；文档模式规则可选择不配置敏感字段以只做分类，也可为各敏感字段配置遮蔽方式。启用脱敏前展示该规则支持的载体范围及“模型提取的字段需经系统验证，无法安全改写时将阻断”的提示。

- 页面展示和维护检测规则；检测命中结果在检测记录和审计详情中展示规则、敏感级别或风险级别及证据。

- 修改敏感级别或遮蔽方式，或修改安全检测规则方向时，展示引用规则的启用策略及可能受影响的处置配置。

- 字段规则通过配置校验后可默认启用；文档模式规则需确认识别/排除指南，系统提供基础正反例检查及结果提示。依赖能力未配置时仍可保存和启用规则，页面显示配置缺口，运行时按 `UNCONFIGURED` 处理。内置规则不可删除，可编辑适配企业并禁用；自定义规则可编辑和删除。

**F\-RULE\-03 导入与导出**

- P0 支持敏感数据规则 CSV/XLSX 导入和 CSV 导出；只导入 `built_in=false` 的自定义规则，不覆盖同名规则。

- 批量导入仅支持 `FIELD` 规则，字段包括规则名称、子分类、检测方向、检测方式、正则、关键词、内置实体类别、字段识别说明、命中阈值、脱敏配置、敏感级别、状态和描述；检测方向接受 `INPUT`、`OUTPUT`、`BOTH`，并按所选检测方式校验对应字段。ID、内置标记、创建人及时间由系统维护。样本文件与文档模式规则不通过 CSV/XLSX 批量导入。

- 单次最多导入 1000 条、文件不超过 5 MB；同一文件内重名、与现有规则重名及必填或格式错误均标记为失败，不覆盖已有规则。确认后仅导入通过校验的行，失败行可下载为含失败原因的 CSV。

- 无选中规则时导出当前筛选结果（含所有分页）；有选中规则时仅导出所选项。导出 CSV 对公式前缀内容进行转义。

- 后续支持的其他检测规则及情报指标导入/导出，按相应数据结构定义。

### 2\.2 检测能力接入与标准结果

#### 2\.2\.1 业务说明

检测引擎负责识别风险并输出 2\.1\.4 定义的统一结果。策略中心根据请求上下文、检测类别和风险结果决定处置动作。

P0 提供敏感数据关键词、正则和分类模型检测，以及文件上传行为、实际格式和大小检测；字段实体分类能力按实际交付类别开放。敏感数据规则按规则方向在请求和响应中复用；请求侧按规则方向检测，响应侧仅在数据控制策略开启“检测模型响应”后检测文本。样本分析、获准外接 LLM 驱动的文档模式检测及其敏感字段脱敏安排在 P1，方案在本 PRD 中保留并参与本次评审。提示词注入、恶意 IOC、模型越狱和内容合规能力按相应引擎、模型和情报源就绪情况开放。

#### 2\.2\.2 检测能力定义（P0 交付与 P1 文档模式）

- 名称：敏感数据内容检测；文件上传行为和文件属性检查作为数据控制策略的直接检查项

- 敏感数据检测方向：按规则配置为 `REQUEST`、`RESPONSE` 或双向；请求侧对方向适用且能力就绪的规则检测，响应侧仅在策略开启 `response_detection_enabled` 后对 `RESPONSE` / 双向规则检测

- 敏感数据检测载体：P0 支持 TEXT，以及 PDF、DOCX、TXT、CSV、XLSX 文件中可提取的请求文本；策略开启响应检测时支持文本响应检测。无法提取文本的扫描件返回不支持，不视为未命中。P1 文档模式检测所需的段落、页码、表格和单文件边界在对应能力交付时提供

- 文件上传行为识别方向：REQUEST；在文件内容解析前检查请求是否携带 FILE 载体，结果供数据控制策略匹配，不生成检测规则命中项

- 文件属性检查方向：REQUEST；P0 按实际识别格式及单文件原始字节数直接匹配数据控制策略，不能只信任文件扩展名或客户端声明的大小；文件名、签名、哈希条件待样本库能力交付后按关联样本检查，策略不保存原始样本或内联匹配值

- 检测逻辑：P0 字段规则按选择的检测方式和适用阈值判断；P1 文档模式规则由 `LLM_JUDGE` 验证语义、字段组、结构关系及置信度，不能仅由关键词/正则的命中数量判定

- 输出：命中规则、实际检测方式、敏感级别或风险级别、匹配证据和已验证的可脱敏范围；内置模型或外接 LLM 判别结果返回各自置信度

参数配置由系统管理模块统一管理，配置入口为“系统管理 \> 检测能力配置”。其中检测失败策略为全局兜底配置，不按规则或安全策略分别设置。

| 参数                           | 类型 | 默认值     | 说明                                                                                                                  |
| ------------------------------ | ---- | ---------- | --------------------------------------------------------------------------------------------------------------------- |
| max\_content\_length           | int  | 100000     | 单个检测分段的最大字符数；长文件按段处理并在同一文件内汇总证据，不静默截断                                            |
| max\_document\_length          | int  | 2000000    | 单个文件可参与内容检测的最大提取字符数；超过时标记未完整检测并按失败策略处理                                          |
| detection\_failure\_policy     | enum | FAIL\_OPEN | 检测规则执行失败、检测引擎超时或必需上下文缺失时的处理方式：FAIL\_OPEN（放行并记录告警）/ FAIL\_CLOSE（阻断）         |
| timeout\_ms                    | int  | 5000       | 单次检测超时时间（毫秒）                                                                                              |
| document\_pattern\_timeout\_ms | int  | 30000      | P1 参数；单个文档模式规则的大语言模型研判超时（毫秒）；检测超时按检测失败策略处理，已选脱敏策略的改写失败按 4\.3 阻断 |

#### 2\.2\.3 检测引擎管理要求

- 检测引擎由系统统一管理，记录引擎类型、支持的检测类别、方向和载体范围，以及启用状态和运行状态。

- 检测请求包含待检测内容或载体引用，以及经过身份认证和授权的上下文；仅向引擎提供完成检测所需的数据。

- 检测结果按 2\.1\.4 的统一格式返回并记录，包含检测类别、命中规则、实际检测方式（适用时）、适用的敏感级别或风险级别、原始命中证据、置信度（模型判别时）、文档模式依据、已验证的可脱敏位置和情报源等适用字段。恶意 IOC 的指标和情报源信息由情报数据提供。

- 超时、不可用和结果缺失必须显式标记为检测失败，不能伪装成“未命中”。

#### 2\.3\.1 匹配与处置

### 2\.4 数据控制策略

#### 2\.4\.1 数据控制策略匹配与处置

数据控制策略按用户、环境和目标模型范围匹配。用户与目标模型的可选条件与 2\.3\.1 一致，三类范围维度之间按 AND 判断；环境条件包括时间范围、IPv4/IPv6 地址或 CIDR（支持取反）、客户端名称和终端属性，已配置的环境条件之间按 OR 判断，同一条件内多值按 OR。按优先级选取首条范围匹配的启用策略后，不继续匹配低优先级策略；没有策略匹配时直接放行。白名单命中时跳过数据控制。

策略可配置文件行为/属性检查和敏感数据规则的“规则－动作”组。动作按阶段执行：先并行检查所有已选阻断规则；任一规则命中即结束该数据控制策略内后续的脱敏和仅告警检测，普通模式下阻断并记录事件，观察模式下只记录事件、不阻断。阻断规则均未命中时，再并行检查所有已选脱敏和仅告警规则；每条命中规则分别执行对应动作，不要求同组规则全部命中。脱敏仅处理各命中规则准确定位出的内容，并按对应规则的 `mask_config` 执行；仅告警对每条命中规则分别记录事件。脱敏和仅告警处于同一优先级，分别命中则两种处置均生效。同一阶段的独立检查并行执行，完成后汇总检测结果再处置；两个阶段仍按阻断优先顺序执行。需要同时满足多个文件属性的条件（如格式和大小）应配置为同一组合文件条件，不代表动作组内所有规则必须同时命中。没有规则命中时放行。敏感数据规则选择支持全部规则、指定规则、指定敏感级别（公开/一般/关键/核心）及按属性匹配；规则组按规则配置的方向执行检测。

数据控制文件检查仅适用于请求。敏感数据规则支持 `INPUT`、`OUTPUT` 或 `BOTH`：请求侧始终按方向执行 `INPUT` / `BOTH` 规则；数据控制策略新增“检测模型响应”开关，默认关闭，开启后才在响应侧执行 `OUTPUT` / `BOTH` 规则。观察模式下，已开启方向上的规则只检测并记录安全事件，不阻断或脱敏。脱敏动作可设置“脱敏还原”：开启后，响应交付原用户前可恢复请求脱敏产生且属于同一用户、同一会话的映射；响应侧独立命中的敏感字段脱敏不被还原。

| 检查项                     | 策略内配置                                 | 匹配语义                                                                                   |
| -------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 文件上传行为 `FILE_UPLOAD` | 请求携带文件即命中                         | 作为独立规则时，命中文件即执行该规则所在组的动作；不要求动作组中的其他规则同时命中         |
| 文件格式 `FILE_FORMAT`     | 选择 PDF、XLSX、DOCX 等格式                | 按系统识别出的实际格式，不只依据扩展名；与大小等条件合并时作为同一组合文件条件             |
| 文件大小 `FILE_SIZE`       | 设置下限和/或上限，至少填写一项            | 按单文件原始字节数匹配；上下限含边界，上限不得小于下限；可与格式等条件组成单个组合文件条件 |
| 文件名 `FILE_NAME`         | 关联文件样本库中的文件名样本               | 仅保存有效样本引用，不在策略中录入匹配文本                                                 |
| 文件签名 `FILE_SIGNATURE`  | 关联文件样本库中的签名样本                 | 签名生成与匹配方式由样本库定义                                                             |
| 文件哈希 `FILE_HASH`       | 关联文件样本库中的哈希样本                 | 仅保存样本引用，不在策略中录入哈希值                                                       |
| 敏感数据规则               | 全部规则、指定规则、指定敏感级别或属性规则 | 按规则支持的方向和载体检测                                                                 |

文件名、签名和哈希条件依赖后续文件样本库；样本不存在、失效或不可用时不能按未命中放行，按 4\.2 的检测失败策略处理。样本库负责样本录入、更新、权限与失效管理；本 PRD 不增设文件规则管理页。多文件上传时，任一文件命中阻断组即命中，并记录命中的文件与条件。

| 指定 AI 客户端源代码及敏感文件外发控制    | 禁用     | 全部用户、INTERNET、企业指定的客户端            | 阻断：文件上传、凭证、源代码/核心数据规则、敏感级别 ≥关键；脱敏：个人信息规则，脱敏还原为否                                              | 是       |
| 互联网模型关键及核心数据阻断              | 启用     | 全部用户、INTERNET、全部环境                    | 阻断：凭证、敏感级别 ≥关键、样本库文件；脱敏：个人信息规则，脱敏还原为否；仅告警：单个组合文件条件（上传 PDF/XLSX/DOCX 且单文件 ≥20 MB） | 是       |

| 私有模型凭证阻断与敏感数据审计            | 启用     | 全部用户、PRIVATE、全部环境                     | 阻断：凭证、样本库文件；仅告警：敏感级别 ≥一般、文件上传行为，分别配置                                                                   | 是       |

预置策略说明以 V1\.2 设计为准：依赖 TO、值班组、网段、客户端或样本库的策略保持禁用，完成配置后由管理员启用；三条模型等级策略默认启用但均处于观察模式，只记录命中事件，不阻断或脱敏。管理员确认规则、网段、终端和误报情况后，可关闭观察模式以执行已配置动作。没有动作组命中时直接放行。

预置数据控制策略的“检测模型响应”开关默认关闭，保持请求侧数据控制；管理员可逐条策略开启响应检测。开启后，仅执行方向为 `OUTPUT` / `BOTH` 的已选敏感数据规则。

### 2\.5 安全检测策略

#### 2\.5\.1 匹配与处置

安全检测在请求侧与数据控制并行检查同一份请求原文；响应侧检查待交付响应。策略按目标模型范围匹配，支持全部模型、指定逻辑模型、指定物理模型、指定供应商安全等级，并支持观察模式。请求和响应分别选中第一条范围匹配的启用策略，不继续匹配低优先级策略；没有匹配策略时直接放行。选中后只调用方向包含当前请求或响应的规则，并按策略配置的检测－动作组执行；规则组可按检测类型、指定规则或高危/中危/低危风险级别选择，支持多选。命中动作仅支持“阻断并告警”和“仅告警”；不配置脱敏或默认动作，未命中时直接放行。观察模式开启时仍执行检测，但命中配置为阻断的规则只记录命中及本应执行的动作，不阻断请求或响应；仅告警命中照常记录安全事件。检测失败、能力未配置或载体不支持按 4\.2 处理。

#### 2\.5\.2 数据模型与管理

**安全检测策略（SecurityDetectionPolicy）**

| 字段                                             | 类型                                   | 是否必填              | 说明                                                                                            |
| ------------------------------------------------ | -------------------------------------- | --------------------- | ----------------------------------------------------------------------------------------------- |
| id、name、description                            | UUID / string / string                 | ID 系统生成；名称必填 | 策略标识、名称和说明                                                                            |
| enabled、priority                                | boolean / int                          | 是                    | 新建置顶；数值越小越优先                                                                        |
| target\_model\_condition                         | JSON                                   | 是                    | 全部模型、逻辑模型、物理模型或供应商安全等级                                                    |
| observation\_mode                                | boolean                                | 是，默认关闭          | 开启时仍执行检测；命中阻断动作时只记录命中及本应执行的动作，不阻断请求或响应                    |
| detection\_actions                               | JSON\[\]                               | 否                    | 有序的规则类型/规则 ID/风险级别选择器和对应动作；动作只可为 BLOCK / ALERT；无动作组时不执行检测 |
| built\_in、created\_by、created\_at、updated\_at | boolean / string / datetime / datetime | 系统生成              | 来源及操作追溯                                                                                  |

列表显示优先级、名称、模型范围、检测动作摘要、观察模式与状态，支持搜索、筛选、启停和拖动排序。表单按“基本信息、模型范围、检测规则与动作、观察模式”组织；可配置多组规则和动作并调整顺序，不展示默认动作。新建策略默认关闭观察模式；能力未就绪时允许保存为禁用并给出配置入口，不允许以未执行的结果启用依赖策略。

| 策略名称           | 模型条件       | 检测动作（按顺序）                                          | 观察模式 |
| ------------------ | -------------- | ----------------------------------------------------------- | -------- |

### 2\.6 请求与响应执行链路

#### 2\.6\.1 请求侧

```Plaintext
身份认证与可信属性获取 → 路由解析目标模型及供应商安全等级
→ 访问控制：按用户、模型及环境条件匹配策略
→ 访问控制阻断则结束；否则并行启动
   ├─ 数据控制：检查文件条件、检测原始请求敏感数据并处置
   └─ 安全检测：检测同一原始请求、匹配策略并处置
→ 汇总结果：任一分支实际阻断则终止；否则执行已选请求脱敏
→ 转发给模型
```

- 访问控制选一条范围匹配的策略；命中且非观察模式时阻断，不启动两条检测分支。命中观察模式策略时记录事件并继续。访问控制允许继续后，数据控制与安全检测基于同一份原始请求和可信上下文独立评估，各自只选一条范围匹配策略。

- 文件上传行为在内容解析前识别；P0 的文件格式和大小条件直接从数据控制策略读取并按原始上传文件判断。后续文件名、签名、哈希条件只读取策略关联的有效样本。需要按物理模型或供应商等级匹配的策略，在实际物理模型确定后、调用前评估；路由变化须重评估。

- 数据控制策略内先并行检查阻断规则；阻断命中即结束该策略的后续脱敏和仅告警检测。观察模式下该命中只记录事件、不阻断请求，但仍结束本策略的后续检查。阻断未命中时，再并行检查所选脱敏和仅告警规则，对各自命中项分别处置；同阶段结果汇总后执行脱敏和记录告警。

- 两条检测分支均检查未经脱敏的原始请求；IOC 规则据此匹配原始 IP、域名和 URL。数据控制或非观察模式的安全检测动作要求阻断时，不执行请求脱敏或模型转发；另一分支已经完成的检测结果与事件仍保留。安全检测处于观察模式时，即使命中组配置为阻断，也只记录命中和本应执行的动作，继续后续流程。两条分支均允许继续时，才执行数据控制策略选中的请求脱敏。访问记录保存命中的策略、动作组、观察模式、检测状态、事件与目标模型快照。

- 请求被阻断时返回 HTTP 403、事件 ID 和提示：“请求被安全策略阻止。请调整请求内容，或联系管理员了解访问要求。”文件上传阻断提示：“当前策略不允许上传文件。请移除附件，或联系管理员了解可用的上传方式。”不向用户展示检测证据。

#### 2\.6\.2 响应侧

```Plaintext
模型响应 → 解析实际响应模型和载体
→ 按配置还原本次请求脱敏映射
→ 若匹配的数据控制策略开启“检测模型响应”，并行评估方向适用的数据控制规则和安全检测规则；否则仅评估安全检测规则
→ 任一分支实际阻断则停止交付；否则执行响应脱敏
→ 返回用户
```

- 响应使用原请求的用户和可信环境快照，以及实际提供响应的物理模型。数据控制策略按用户、环境和模型范围匹配；仅当所选策略开启“检测模型响应”时，敏感数据规则才调用方向为 `OUTPUT` 或 `BOTH` 且支持当前载体的规则，`INPUT` 规则不在响应侧执行。安全检测仍按规则方向调用 `OUTPUT` / `BOTH` 规则。访问控制策略不在响应侧评估。

- 响应侧数据控制仅在匹配策略开启响应检测时执行，并先并行检查适用的阻断规则；命中后不再检查该策略的脱敏和仅告警规则。阻断未命中时，再并行检查所选脱敏和仅告警规则，并对各命中项分别执行相应处置。

- 请求侧若执行脱敏且开启“脱敏还原”，在响应侧数据控制或安全检测检查前只恢复与原用户、原会话对应的已建立映射，使已启用的检测检查最终拟交付的内容；响应侧敏感数据规则随后可阻断、告警或脱敏。响应侧新执行的脱敏不会被后续映射还原撤销。白名单只跳过各自对应的策略域，审计白名单不改变安全检测和数据控制结果。

- 数据控制或非观察模式的安全检测阻断响应时返回事件 ID 和提示：“模型响应被安全策略拦截，未向你展示。请联系管理员了解访问要求。”观察模式下安全检测命中阻断动作只记录事件并继续交付。已产生的模型用量和费用仍计量；请求侧已经完成的检测结果与事件仍保留。

- 流式响应先按可配置窗口缓冲，在尚未交付的窗口内完成适用映射还原、数据控制和安全检测，并在响应脱敏后再交付；默认窗口 500 字符。任一分支实际阻断时终止后续输出，已交付片段不能撤回，事件需记录已交付范围。跨窗口的还原映射或检测证据需延迟交付直到判定完成。

### 2\.7 安全事件

访问控制阻断或观察命中、数据控制/安全检测阻断或告警、实际执行脱敏或映射还原时均生成安全事件。安全检测观察模式下的阻断命中也生成事件，事件须区分策略配置动作（本应执行的动作）与实际处置（继续放行）。单次交互可在多个环节及两个方向产生不同事件；一条分支阻断时，另一分支已产生的告警或阻断事件仍须关联同一访问记录。事件记录关联访问记录、用户和模型快照、策略域与 ID、命中的动作组、规则及检测结果、观察模式、配置动作、实际处置、脱敏/还原状态、方向、载体和原始命中证据。未命中且未执行脱敏或还原时不因策略动作生成事件。安全事件异步写入，不阻塞关键路径。访问控制、数据控制和安全检测白名单命中时跳过对应治理域；审计白名单仅限制正文留存为元数据，不影响安全处置。事件查询和处置由审计中心定义。

### 2\.8 审计策略与延后分析

#### 2\.8\.1 匹配和留存

审计策略按用户范围与目标模型范围匹配。用户支持全部用户、指定部门、指定用户组、指定用户和按属性规则匹配；模型支持全部模型、指定逻辑模型、指定物理模型和指定供应商安全等级。维度之间按 AND、同维度多值按 OR。每次交互按优先级从高到低选择第一条完整匹配的启用策略；没有匹配策略时只记录元数据。

**审计策略（AuditPolicy）**

| 字段                                             | 类型                                   | 是否必填     | 说明                                                           |
| ------------------------------------------------ | -------------------------------------- | ------------ | -------------------------------------------------------------- |
| id                                               | UUID                                   | 系统生成     | 策略唯一标识                                                   |
| name、description                                | string                                 | 名称必填     | 策略名称和说明                                                 |
| enabled、priority                                | boolean / int                          | 是           | 新建置顶；序号越小优先级越高                                   |
| user\_condition、target\_model\_condition        | JSON                                   | 是           | 用户及模型范围条件                                             |
| audit\_level                                     | enum                                   | 是           | FULL（全量审计）/ METADATA\_ONLY（仅元数据）/ CUSTOM（自定义） |
| audit\_fields                                    | enum\[\]                               | 自定义时必填 | 自定义字段集合；元数据始终包含，不可取消                       |
| built\_in、created\_by、created\_at、updated\_at | boolean / string / datetime / datetime | 系统生成     | 来源及操作追溯                                                 |

新建策略默认启用并置顶，列表拖动调整优先级。审计策略在请求进入时确定初始范围，实际物理模型确定或路由变化时重评估，并在响应完成时按最终生效策略落库；已删除或修改的历史记录不追溯变更。

| 审计级别或字段                        | 保存内容                                                                                                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 仅元数据 METADATA\_ONLY；所有级别必含 | 请求/响应 ID、时间、会话关联、用户/API Key、逻辑与物理模型、供应商、用量、安全策略命中与动作、安全事件、状态及错误；不含正文           |
| 全量审计 FULL                         | 元数据、完整有序请求 messages（含各角色消息）、完整 tools 定义、响应 content 和 tool\_calls 等可审计交互正文；受字段权限和保留期限约束 |
| 自定义 SYSTEM\_PROMPT                 | 请求 messages 中 system 角色的完整提示词                                                                                               |
| 自定义 USER\_PROMPT                   | 请求 messages 中 user 角色的完整提示词                                                                                                 |
| 自定义 REQUEST\_TOOLS                 | 请求 tools 中函数名称、描述、参数定义等完整内容                                                                                        |
| 自定义 RESPONSE\_CONTENT              | 响应 choices\[\]\.message\.content                                                                                                     |
| 自定义 RESPONSE\_TOOL\_CALLS          | 响应 choices\[\]\.message\.tool\_calls，包含函数名称与 arguments                                                                       |

自定义级别始终包含元数据，须从上述五个字段中至少选择一项；仅元数据级别不展示正文选择。全量审计保留完整交互，必须明确展示留存范围并遵守查看、导出和检索授权。未选的正文或工具字段不得通过日志、索引或延后分析副本变相保存。检测命中证据作为独立的检测结果和安全事件字段按原值保留，仅供有权人员复核，不代表允许留存整段交互正文。

系统预置“全局默认审计策略”：全部用户、全部模型，默认启用且固定在自定义策略之后；审计级别为自定义，包含元数据、system\_prompt、user\_prompt、tools、tool\_calls，不包含响应 content。管理员可修改其审计级别和自定义字段或禁用；禁用后仍由“未匹配时仅元数据”兜底。数据控制策略脱敏的请求，已选请求字段按用户提交时内容记录；实际送达模型的改写结果及映射只在明确授权的受控审计数据中留存，不因默认策略自动保存映射。

#### 2\.8\.2 管理功能与延后审计分析

审计策略列表显示优先级、名称、用户、目标模型、审计级别、自定义字段摘要及状态；支持搜索、筛选、启停和拖动排序。创建表单按“基本信息、用户、模型、审计级别”组织；选自定义时展开五个字段，元数据固定显示。选择全量或工具参数时就近提示留存范围；保存失败保留已填内容并显示字段错误。

延后审计分析在后续版本以系统开关交付，不在单条审计策略中配置。开启后只分析所有按策略已留存且分析任务有权访问的内容；可将多次请求还原成用户视角会话、分析用户请求意图、排查工具违规调用与多轮敏感数据泄露风险，并提取智能体身份和权限线索。具体任务处理、结果展示、权限流程和质量指标留待后续版本。

延后分析不得回取未留存内容、扩大原记录权限或保留期限。仅留存元数据时不得声称完成内容级分析；结果需显示数据覆盖不足。关闭系统开关后不新建分析任务，既有审计记录仍按原留存策略管理。

### 2\.9 白名单管理

白名单分为访问控制、数据控制、安全检测和审计四类。白名单仅影响对应治理域：访问控制、数据控制和安全检测白名单命中时，该域不执行控制或检测；审计白名单命中时，交互正文不留存，仅记录元数据。命中其他治理域策略的能力不受影响。

白名单记录的名称、类型和状态为管理字段；各类匹配条件如下。配置项留空表示不限制该条件；一个条件中选择多个值时按 OR 匹配，同一白名单中的不同条件按 AND 匹配。

| 类型     | 可配置条件                                                                     | 命中效果                                                   |
| -------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 访问控制 | 指定用户、物理模型、时间、IP/IP 段（IPv4/IPv6）、客户端名称、终端 ID           | 跳过访问控制策略评估                                       |
| 数据控制 | 指定用户、物理模型、时间、IP/IP 段（IPv4/IPv6）、客户端名称、终端 ID、规则列表 | 跳过数据控制策略评估；规则条件可选敏感数据规则或文件检查项 |
| 安全检测 | 指定物理模型、规则列表                                                         | 跳过安全检测策略评估                                       |
| 审计     | 指定用户、物理模型                                                             | 仅留存元数据，不保存正文或工具内容                         |

每条白名单至少配置名称和类型；该类型下的所有条件均可留空，此时对该治理域形成不限范围的白名单。白名单列表支持按名称、类型、状态筛选，查看详情、创建、编辑、启停和删除；列表展示类型、条件摘要、状态和更新时间。保存时展示将跳过的治理域及匹配条件；删除确认说明恢复相应策略评估或正文留存后可能产生的影响。变更记入操作日志。

## 3\. 页面设计

AI 安全治理的二级菜单依次为“访问控制策略”“数据控制策略”“安全检测”“审计策略”“白名单”。数据控制策略页内设“数据控制策略”“敏感数据规则”“敏感数据发现”三个 Tab；安全检测页内设“安全检测策略”“检测规则”两个 Tab；白名单页内设“访问控制”“数据控制”“安全检测”“审计”四个 Tab。三级菜单均作为页面内 Tab，不在左侧导航展开。访问控制、数据控制、安全检测策略列表按策略名称、说明、目标模型或适用条件搜索，状态单独筛选；审计策略和白名单按各自匹配字段筛选。页面布局、表单密度、筛选与操作顺序遵循《原型页面布局与 UX 要求》。访问控制策略不配置默认动作；数据控制和安全检测无动作组命中时直接放行。

### 3\.1 访问控制页

- 访问控制策略工作区呈现筛选、操作、列表与分页。列表按优先级升序，拖拽柄位于序号旁；多选操作固定在工具栏，选择数量放在分页旁。表单按 2\.3 展示用户、模型、环境条件和观察模式，不配置文件检查或默认动作。普通模式下策略命中即阻断，观察模式仅记录事件。系统无预置策略；空列表提供“创建策略”。缺少 TO 属性、网段或客户端识别配置时，就近说明原因和配置入口；保存失败保留已填内容并就近标注字段错误。

### 3\.2 数据控制页

- Tab1“数据控制策略”按统一的筛选、操作、列表和分页组织工作区，列表展示用户、环境、模型、文件检查与敏感数据动作组摘要、观察模式和状态；表单按 2\.4 配置文件条件、敏感级别或规则选择器与对应动作。脱敏组显示“脱敏还原”；组内规则不支持脱敏时就近说明原因及命中后会阻断。先并行执行阻断检查，命中后停止该策略的脱敏和仅告警检查；阻断未命中时，再并行检测选中的脱敏和仅告警规则，汇总结果后处理命中项。不展示默认动作。空列表提供“创建策略”；规则、样本或检测能力缺失时说明下一步配置。

- Tab2“敏感数据规则”按字段规则和文档模式规则分组。筛选区、操作区、规则列表、分页组成一个工作区；窄屏下分组改为顶部选择控件。方向支持请求、响应和双向；检测方式按 `KEYWORD`、`REGEX`、`CLASSIFIER`、`LLM_JUDGE` 提供适用的配置项。文档模式页面与表单规格保留供本次评审，对应创建、测试和运行能力按 P1 交付。

- 敏感数据规则工具栏在 P0 提供“创建规则”，仅可手动创建字段规则；P1 增加“样本分析”入口和文档模式规则创建选项。P1 创建规则时先选择“字段规则”或“文档模式规则”，两者均可直接手动填写。字段规则表单按检测方式展示实体类别、字段识别说明、关键词或正则输入项，同时展示适用阈值及遮蔽方式。文档模式表单展示规则名称、子分类、识别指南、排除指南、敏感字段、遮蔽方式及阈值，不显示检测方式选择。

- P1 的敏感数据发现页提供“上传样本分析”和“从审计记录分析”两类任务入口，并展示来源、分析范围、状态及规则建议。上传样本时校验每次 1–5 份、单份不超过 20 MB，并展示文件名、哈希、可识别的实际格式和大小；文件格式不作为进入分析流程的前置条件。管理员点击“开始分析”后，分析进度依次展示样本读取与解析、字段及文档模式识别、结果整理，完成后直接进入结果页，不单独展示解析结果页。当前原型为保证任意文件格式都能安全走通，仅读取不超过 1 MB 的 TXT/CSV 内容；其他格式不在浏览器端解压。未能从文件形成样本命中建议时，展示通用规则候选建议，供管理员复核，且不伪造文件命中依据；实际分析服务接入后，以基于样本内容的分析结果替换通用候选建议。结果分开展示字段规则与文档模式规则建议。审计分析支持按时间、用户、模型筛选和勾选记录，只读取操作者有权访问且按审计策略留存的请求正文；结果显示命中依据与请求位置，不把未留存正文、仅元数据记录或模型响应作为分析对象。两种来源的建议都可查看依据、确认、编辑、忽略或恢复；确认后进入相应创建表单预填，不自动保存或启用规则。样本分析模型未配置时显示“请先配置大语言模型检测能力”；分析失败提供“重新分析”。“敏感数据规则”页保留“样本分析”快捷入口，跳转到发现页并选中上传样本来源。

- 文档模式测试支持粘贴文本或上传文件，系统提供可编辑反例候选，也可自行输入反例。结果展示命中依据、排除依据、置信度、敏感字段提取与逐项遮蔽结果；无法安全改写时显示“无法完成脱敏，请调整规则或改用阻断策略”。保存后可进入创建敏感数据策略并带入当前规则。

- Tab3“敏感数据发现”统一展示上传样本与审计记录分析任务、结果和敏感数据规则建议。上传样本按 1–5 份、单份不超过 20 MB 校验并展示哈希及可识别的实际格式；格式未知或内容无法提取时仍可完成任务，未形成样本命中建议则显示明确标记的通用规则候选建议，不展示虚构的位置或样本命中数。当前原型仅读取不超过 1 MB 的 TXT/CSV 内容，其他格式直接进入通用建议兜底，避免浏览器端解压任意文件。点击“开始分析”后，在同一页面展示样本读取、规则识别及结果整理进度，完成后直接展示分析结果。审计来源按操作者权限和审计策略留存范围筛选，只分析请求正文。两种任务都按字段规则、文档模式展示建议依据和建议字段；只有实际匹配时才展示命中依据与位置。管理员确认后可进入规则表单编辑和创建，不直接启用。任务分析与规则保存分离；样本分析依赖模型配置时提供配置入口。

### 3\.3 安全检测页

- Tab1“安全检测策略”呈现策略列表、筛选、主要操作与分页。列表展示观察模式状态；表单按 2\.5 展示模型范围、有序检测动作组和观察模式开关；可按检测类型、指定规则或风险级别配置每组动作并调整顺序，不展示默认动作。观察模式开启时命中阻断动作只记录事件并继续请求或响应；无动作组命中时直接放行。空列表提供“创建策略”；检测能力缺失时显示原因与配置入口；保存失败保留已填内容并标注字段错误。

- Tab2“检测规则”按提示词注入、模型越狱、内容合规、恶意 IOC 展示分组及数量。筛选区、操作区、规则列表、分页组成一个工作区；窄屏下分组改为顶部选择控件。规则表单使用风险级别。

- 检测能力或情报源缺失时显示实际状态与配置入口；规则不可用不显示为检测通过。规则测试展示命中、未命中、原始命中证据、失败原因及处理建议。

### 3\.4 审计策略页

- 列表按优先级展示名称、用户、模型、审计级别、自定义字段摘要和状态；系统预置全局策略固定在自定义策略之后。筛选与操作、列表、分页按统一工作区组织。

- 创建或编辑表单先选择“全量审计”“仅元数据”“自定义”；自定义时显示 system\_prompt、user\_prompt、tools、content、tool\_calls 独立选项，元数据固定包含。全量审计和工具参数选择就近提示留存范围；无匹配策略仅留存元数据的规则在字段帮助中说明。

- 空列表、获取失败、保存失败和字段权限不足均提供可执行的下一步操作。

### 3\.5 白名单页

- 页面内提供“访问控制”“数据控制”“安全检测”“审计”四个 Tab，各 Tab 使用独立列表和新增/编辑表单，仅展示该类白名单可配置的匹配字段。

- 筛选与操作区、列表、分页组成统一工作区。列表展示名称、条件摘要、状态和更新时间；条件未填写时在摘要中显示“全部”，不将空条件误解为无匹配范围。

- 表单允许各匹配条件留空；字段间按 AND 匹配，同字段多值按 OR 匹配。审计白名单表单就近提示命中后仅留存元数据；其他类型提示其跳过的治理域。删除确认说明删除后相应策略会重新参与评估或正文会恢复按审计策略留存。

- 空列表提供“创建白名单”；获取失败、保存失败、权限不足和规则不可选时提供可执行的下一步操作。

## 4\. 业务规则

### 4\.1 优先级与阶段边界

访问控制、数据控制、安全检测和审计策略各自维护独立的优先级序号；策略创建后默认置顶，列表拖动调整顺序。每个治理域按优先级选取首条匹配的启用策略，不继续评估低优先级策略。访问控制没有匹配策略时默认放行；数据控制或安全检测没有匹配策略、没有命中动作组或所有适用检查均未命中时默认放行；审计策略未命中时仅留存元数据。白名单按治理域独立生效；审计白名单使匹配记录只留存元数据。

访问控制策略以匹配条件决定是否阻断，观察模式只记录本应阻断的访问。数据控制动作优先级固定为“阻断 \> 脱敏 = 仅告警”，并分阶段执行：先并行检查全部阻断规则；任一规则命中即阻断并停止本策略后续脱敏和仅告警检测。观察模式下虽然不阻断请求，阻断规则命中仍会结束本策略后续检查并记录事件。阻断规则均未命中时，再并行检查所有已选脱敏和仅告警规则；阶段内汇总命中结果后，命中规则逐项按所在组动作处置，不要求组内全部规则命中。脱敏只作用于命中规则定位出的内容并按其 `mask_config` 改写，告警规则分别记录事件；脱敏和仅告警处于同一优先级，分别命中则两种处置均执行。观察模式下数据控制不阻断、不脱敏，只检测并记录事件。安全检测动作组只支持阻断并告警、仅告警；观察模式下命中“阻断并告警”只记录命中和本应执行的动作，不阻断请求或响应，命中“仅告警”照常记录安全事件。安全检测策略新建和预置策略默认关闭观察模式；无匹配组时直接放行。表单和接口按策略类型校验动作取值。

请求先评估访问控制；允许继续后，数据控制与适用于请求的安全检测同时评估原始请求。两条分支均未阻断时才执行请求脱敏并转发模型；任一分支实际执行阻断即整体阻断，不转发原始请求。请求侧并行分支互不覆盖动作：一条分支的放行或观察不能覆盖另一条分支实际执行的阻断，告警仍独立记录。响应阶段先按配置还原请求脱敏映射；安全检测按方向执行，数据控制仅在匹配策略开启“检测模型响应”时执行 `OUTPUT` / `BOTH` 规则。任一已执行分支实际阻断则停止交付，否则执行响应脱敏。审计策略只决定存储字段，不改变安全处置。

### 4\.2 检测状态与兜底

| 状态                                   | 处理                                                                                                                                                             |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 已检测且命中                           | 按治理域规则执行动作：访问控制按观察模式决定阻断或仅记录；数据控制按固定动作优先级执行；安全检测观察模式关闭时执行命中动作，开启时只记录命中和本应执行动作并继续 |
| 已检测且全部未命中                     | 不再评估本类低优先级策略，直接放行                                                                                                                               |
| 策略关闭当前方向检测或未配置检测动作组 | 不调用对应检测能力；数据控制和安全检测直接放行                                                                                                                   |
| 规则或能力未配置                       | 标记 UNCONFIGURED，不等于未命中；管理端提示配置入口，依赖该能力的策略不可启用                                                                                    |
| 载体不支持、执行超时或失败             | 标记 UNSUPPORTED / FAILED，不等于未命中；按全局检测失败策略处理                                                                                                  |
| 必需身份或模型属性缺失                 | 记录缺失字段；不能按“全部用户/模型”冒充已识别对象，按全局检测失败策略处理                                                                                        |

全局 detection\_failure\_policy 在系统管理配置：FAIL\_OPEN（默认，按未命中继续并记录告警）或 FAIL\_CLOSE（阻断并记录事件）。该设置只处理检测无法完成的情况，不替代策略命中动作。长文件按分段检测，跨段汇总时保留同一文件的字段组与结构关系；超过 max\_document\_length 或无法完成全量检测时标明未检测范围并按失败策略处理，不能把部分内容未命中视为整体未命中。

已进入脱敏改写阶段后，模型未返回必需字段、定位验证失败、文件无法安全重写或改写后复检失败，均属于脱敏失败；必须阻断原文发送或交付，不受 FAIL\_OPEN 影响。模型在完成分类前超时、无法判断是否命中时属于检测失败。

### 4\.3 脱敏与还原

请求或响应脱敏仅适用于数据控制策略中配置的脱敏组，且命中内容可准确定位和安全改写；响应侧脱敏还须由该策略开启“检测模型响应”。字段规则使用已验证的命中范围，并按自身 mask\_config 改写；文档模式规则的大语言模型仅提出字段原文及所在位置/上下文，由系统逐处核对字段角色和范围，再按各敏感字段的 mask\_config 计算替换内容。相同字符串多次出现时逐处验证，不能无条件全文替换。多条规则命中时按“核心、关键、一般、公开”敏感级别、规则 ID 固定顺序处理；同一片段只改写一次，字段规则与文档模式重叠时已验证的字段规则优先。所有替换完成后复检实际发往模型的文本、响应或文件；复检失败、字段遗漏、重叠冲突、载体不可安全重写时，阻止相应请求发送或响应交付，并记录脱敏失败事件。

请求脱敏映射只向原用户交付其有权查看的内容，并在响应侧检测前还原，以确保响应检测覆盖最终拟交付内容；响应侧执行的独立脱敏发生在映射还原之后，不得被还原撤销。审计记录和安全事件中的原始命中证据按证据权限与保留期限查看，交互正文仍遵守审计级别与字段留存设置；审计策略不改变模型实际收到或用户实际看到的内容。

### 4\.4 超时与性能

请求侧及策略开启响应检测后的敏感数据关键词/正则检测 P95 目标 \< 50ms；策略匹配目标 \< 5ms；分类器、大语言模型研判和文档改写不纳入基础检测时延承诺。检测引擎超时、不可用或结果缺失按 4\.2 处理；已选脱敏动作的改写失败按 4\.3 处理。安全事件异步写入；事件 ID 在阻断时须可返回。流式响应缓冲和延后分析不得绕过审计字段限制。

## 6\. 模块接口与非功能要求

| 模块                     | 关系 | 关键数据                                                                             |
| ------------------------ | ---- | ------------------------------------------------------------------------------------ |
| 身份管理、终端管理（TO） | 上游 | 已认证用户、部门/用户组/属性及可信终端属性；未接入 TO 时终端条件不可用               |
| 模型接入与路由           | 上游 | 逻辑/物理模型、实际供应商实例及安全等级；路由改变后重评估                            |
| 系统管理                 | 配置 | 各类内置模型能力、外接大语言模型授权与可用性、全局检测失败策略、延后审计分析系统开关 |
| 审计中心                 | 下游 | 访问记录、安全事件、策略和规则快照；按审计字段权限展示                               |
| 成本与预算               | 链路 | 模型请求实际发生后的用量和费用，包括响应被阻断场景                                   |

- 访问控制、数据控制、安全检测、审计策略和白名单的变更均记录操作日志；安全管理员与超级管理员可读写，其他角色按权限只读。系统预置数据控制/安全检测策略和规则不可删除；访问控制不预置策略。历史事件保留命中时快照。

- 审计正文、工具定义和参数按字段授权与保留期限管理；检测命中证据按原值留存，并限制查看、导出权限及保留期限。后续版本若提供延后分析，其结果不得扩大源记录的权限、保留期限或留存字段范围。

- 正则表达式须限制执行开销；IOC 情报源须验证来源和时效。检测失败、能力未配置、未命中需在 API 和管理端分开呈现。

- 样本分析和文档模式运行时检测仅调用系统批准且获准处理相应内容的外接大语言模型，不把内容转发给用户正在访问的目标模型。检测前校验模型授权、数据范围和权限；对外接模型的传输、暂存、保留期限与删除要求由检测能力配置明确。任务与临时文件按操作权限隔离，加密暂存并在完成、取消或失效后清理；普通运行日志不写入样本正文或模型提出的替换原文，安全事件按上述要求记录原始命中证据。

- 样本分析、建议确认和文档模式规则变更均记录操作日志。

- 管理页面 P95 响应目标 \< 500ms；规则导入最多 1000 条、文件不超过 5 MB。中文和英文界面及阻断提示使用同一业务语义。

## 7\. 预置数据与实施边界

首次部署不初始化访问控制策略；访问控制策略列表为空，默认不控制。初始化数据控制七条预置策略、安全检测三条预置策略、全局默认审计策略，以及预置规则清单中的规则。数据控制策略默认状态、观察模式和动作组按 2\.4\.3 定义：依赖企业配置的策略默认禁用；互联网、可信云和私有模型策略默认启用但处于观察模式，管理员确认条件、命中质量和下一步处置后再关闭观察模式。文件上传行为、格式和大小在数据控制策略中直接配置；文件名、签名、哈希通过客户现场文件样本库关联，暂不建立独立文件检测规则。

敏感数据规则方向支持 INPUT、OUTPUT、BOTH；请求侧按规则方向检测，响应侧仅在匹配的数据控制策略开启“检测模型响应”时检测 OUTPUT / BOTH 规则。P0 支持字段规则手动配置、关键词/正则/分类器检测，以及 PDF、DOCX、TXT、CSV、XLSX 可提取文本的请求检测；文本响应检测由策略开关启用。P1 交付依赖获准外接大语言模型的样本分析及字段规则建议，同时交付文档模式规则的创建、样本建议、运行时检测和敏感字段脱敏；六条文档模式预置规则默认禁用，需企业确认识别指南、敏感字段和模型配置后启用。文件样本库、扫描件 OCR 和更深度的非文本文件解析随相应能力交付。

V1\.2 设计明确了敏感数据规则的员工信息、企业信息、客户信息、产品研发、IT 基础设施等分类方向；具体行业与企业子类清单需结合规则库单独维护。系统预置策略和检测规则的实际状态须与 2\.3\.3、2\.4\.3、2\.5\.3 保持一致。延后审计分析作为系统级开关，具体任务、结果展示和质量指标在后续版本细化；其分析范围不得超出审计策略已留存且当前操作者有权访问的数据。
