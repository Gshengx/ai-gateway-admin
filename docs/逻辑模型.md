### 业务说明

逻辑模型是面向用户的模型抽象。用户申请权限、API 调用时看到和使用的都是逻辑模型名称。一个逻辑模型下可以挂载一个或多个同能力的物理模型，系统自动在这些物理模型之间路由；同一物理模型也可以同时挂载到多个逻辑模型。
逻辑模型解决的核心问题：

- 授权简化：用户只需申请一次"GPT-4o"权限，不需要关心背后有几个供应商
- 路由透明：某个供应商不可用时自动切到其他供应商，用户无感知
- 管理解耦：管理员可以随时增减物理模型，不影响用户权限和使用

### 数据模型

| 字段               | 类型          | 必填     | 说明                                                                               |
| ------------------ | ------------- | -------- | ---------------------------------------------------------------------------------- |
| id                 | string (UUID) | 系统生成 | 逻辑模型唯一标识                                                                   |
| name               | string        | 是       | 逻辑模型名称，全局唯一，用户 API 调用时使用（如 gpt-4o），同时也是用户界面展示名称 |
| description        | string        | 否       | 描述（面向管理员的说明）                                                           |
| model_count        | int           | 系统统计 | 关联的物理模型数量                                                                 |
| active_model_count | int           | 系统统计 | ACTIVE 状态的关联物理模型数量                                                      |
| created_at         | datetime      | 系统生成 | 创建时间                                                                           |
| updated_at         | datetime      | 系统生成 | 更新时间                                                                           |
| created_by         | string        | 系统生成 | 创建人                                                                             |

逻辑模型挂载关系（logical_model_mounts）：

| 字段                                                                                    | 类型     | 必填     | 说明                                           |
| --------------------------------------------------------------------------------------- | -------- | -------- | ---------------------------------------------- |
| logical_model_id                                                                        | string   | 是       | 逻辑模型 ID                                    |
| model_id                                                                                | string   | 是       | 物理模型 ID                                    |
| priority                                                                                | int      | 是       | 当前逻辑模型内的路由优先级，数字越小优先级越高 |
| created_at                                                                              | datetime | 系统生成 | 挂载时间                                       |
| (logical_model_id, model_id) 唯一；同一 model_id 可出现在多个不同逻辑模型的挂载关系中。 |

### 功能点

F-LOGICAL-01 逻辑模型列表

- 列表字段：逻辑模型名称、物理模型数（ACTIVE/总数）、状态摘要、创建时间
- 状态摘要：可用（≥1 个 ACTIVE 物理模型）/ 不可用（无 ACTIVE 物理模型）
- 支持按名称搜索
- 支持分页
  F-LOGICAL-02 创建逻辑模型
- 表单字段：
  - 逻辑模型名称 name（必填，全局唯一，用户 API 调用时使用）
  - 描述（选填）
- 创建时可选择挂载已有物理模型（选填，可后续再挂），不限制物理模型状态，也不因物理模型已挂载到其他逻辑模型而排除
  F-LOGICAL-03 编辑逻辑模型
- 可修改名称和描述
- 名称修改需二次确认：会影响用户端 API 调用
  F-LOGICAL-04 挂载/卸载物理模型
- 在逻辑模型详情页管理挂载的物理模型
- 挂载：可从任意状态的物理模型中选择，包括已关联到其他逻辑模型的物理模型；为当前逻辑模型的挂载关系设置路由优先级
- 一个物理模型可同时挂载到多个逻辑模型，各逻辑模型分别维护该物理模型的路由优先级
- 卸载：仅解除当前逻辑模型与该物理模型的关联，不影响物理模型及它与其他逻辑模型的挂载关系
- 物理模型处于 ACTIVE 时可参与其已挂载逻辑模型的路由；其他状态的物理模型保留挂载关系但不参与路由。状态恢复为 ACTIVE 后可重新参与路由
- 挂载/卸载立即生效
  F-LOGICAL-05 删除逻辑模型
- 删除逻辑模型时，只删除该逻辑模型自己的挂载关系（物理模型本身及其与其他逻辑模型的挂载关系不受影响）
- 同步删除该逻辑模型的权限配置
- 删除操作需二次确认
  F-LOGICAL-06 查看逻辑模型详情
- 详情页采用 Tab 页签组织：
  - 基本信息：名称、描述
  - 物理模型：挂载的物理模型列表（含供应商实例、API 接口、安全等级、优先级、状态），支持挂载/卸载/调整优先级
  - 模型权限：权限配置（见 权限配置）

### 权限配置

用户始终通过逻辑模型名称调用 API。权限通过部门、用户组和用户三个维度配置在逻辑模型上。
未挂载到逻辑模型的物理模型不会对用户暴露，仅供管理员接入和检测使用。

### 数据模型

| 字段             | 类型          | 必填     | 说明                            |
| ---------------- | ------------- | -------- | ------------------------------- |
| id               | string (UUID) | 系统生成 | 权限记录唯一标识                |
| logical_model_id | string        | 是       | 逻辑模型 ID                     |
| subject_type     | enum          | 是       | DEPARTMENT / USER_GROUP / USER  |
| subject_id       | string        | 是       | 授权对象 ID（部门/用户组/用户） |
| created_at       | datetime      | 系统生成 | 创建时间                        |
| created_by       | string        | 系统生成 | 创建人                          |

### 功能点

F-PERM-01 权限配置

- 在逻辑模型详情页"模型权限"Tab 中配置
- 分三个区域展示：部门授权、用户组授权、用户授权
- 每个区域展示已授权列表和"添加"按钮
  F-PERM-02 添加授权
- 添加部门授权：从部门树中选择，支持多选。授权部门后，该部门及其所有子部门下的用户均可使用
- 添加用户组授权：从用户组列表中选择，支持多选搜索
- 添加用户授权：从用户列表中选择，支持按部门筛选和搜索，支持多选
- 添加后立即生效
  F-PERM-03 移除授权
- 支持单个和批量移除
- 移除操作需二次确认
- 移除后立即生效
  F-PERM-04 权限查看（用户视角）
- 在用户详情页中展示该用户可使用的逻辑模型列表
- 标注权限来源：部门继承 / 用户组继承 / 用户直接授权
  F-PERM-05 批量授权
- 在逻辑模型列表页支持选择多个逻辑模型后批量配置权限
- 选择授权对象（部门/用户组/用户），批量添加授权
