## 1\. 模块概述

### 1\.1 业务目标

建立企业 AI 消费的全面成本管理与预算控制体系，解决：

> **企业在 AI 上花了多少钱、钱由哪条预算承担、花在哪里，以及如何控制花费不超预期。**

成本与预算是 AI 安全网关的运营管理核心模块。企业需要清晰掌握 AI 消费全貌，并通过预算机制将 AI 支出控制在可预期的范围内。本模块依赖身份管理模块提供的组织和用户信息，依赖模型接入模块提供的物理模型价格配置和请求计量数据。

本模块支持部门预算、项目预算和用户预算。项目与部门解耦：项目可以设置责任部门，用于项目管理归口、预算出账和成本归因。API Key 关联项目时，费用主体为项目，系统同时记录实际使用人、使用人所属部门、项目责任部门，用于企业内部成本归因与分摊参考。

**模块定位**：本模块是网关侧的成本估算、内部归口分摊与预算预警看板，不是精确对账系统。费用金额由网关按请求时生效的单价快照与用量估算，用于内部成本归因、分摊参考和预算控制；厂商计费方式（阶梯价、折扣、缓存、多模态等）存在差异，金额可能与厂商账单不一致，不作为厂商账单核对或财务结算依据。差异通过定期校准处理，不逐笔回溯修改已发生请求的费用。

### 1\.4 关键概念说明

为避免后续章节中多个相近概念混淆，现将费用归属与预算相关的核心术语统一说明如下。

| **概念**               | **说明**                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **费用主体**           | 本次消费主要归属于谁，决定费用最终计入哪个预算对象。一条费用明细只能有一个费用主体，避免重复记账。                                                                                                                                                                                                                                                                                                                            |
| **费用主体类型**       | 费用主体类型，取值如下：\- **部门**：API Key 未关联项目，费用主体为用户所属部门，费用只计入该部门。\- **项目**：API Key 关联项目，费用主体为项目，费用只计入项目预算，并按项目责任部门归集为项目消费。                                                                                                                                                                                                                        |
| **使用人所属部门**     | 发起请求的用户在身份管理中的所属部门。当费用主体为项目时，使用人所属部门仅用于记录"谁在使用、来自哪个部门"，**不代表费用自动归属到该部门预算**。                                                                                                                                                                                                                                                                              |
| **项目责任部门**       | 项目的管理归口部门，同时是项目预算的承担部门。项目预算由该部门承担，项目消费按该部门归集；上级部门统计时汇总下级数据，不重复记账。                                                                                                                                                                                                                                                                                            |
| **非项目消费**         | 未关联项目的 API Key 请求，由使用人所属部门作为费用主体产生的消费。                                                                                                                                                                                                                                                                                                                                                           |
| **项目消费**           | 某部门作为项目责任部门，其负责项目实际产生的消费。该消费属于项目费用，计入项目预算；部门统计中按责任部门归集，上级部门汇总下级数据，不重复记账。                                                                                                                                                                                                                                                                              |
| **部门总消费**         | 本部门及下级部门非项目消费 \+ 本部门及下级部门负责项目的项目消费。                                                                                                                                                                                                                                                                                                                                                            |
| **预算有效期**         | 预算仅在指定起止日期内生效，配置预算时必须指定持续时间。                                                                                                                                                                                                                                                                                                                                                                      |
| **预算总额**           | 当前预算主体在当前起止日期内的总预算                                                                                                                                                                                                                                                                                                                                                                                          |
| **已消费**             | 预算起止日期内发生的大模型费用。<br>\- **部门口径**：本部门及所有下级部门用户使用未关联项目的 API Key 直接产生的消费 \+ 本部门及所有下级部门负责的项目（projectResponsibleDepartmentId ∈ \{self \+ descendants\}）的已消费之和；部门 consumed 字段在请求完成时按上述两个来源异步累加 <br>\- **项目口径**：该项目在预算起止日期内发生的大模型费用 <br>\- **用户口径**：该用户在预算起止日期内使用未关联项目 API Key 的实际消费 |
| **总余额**             | 总余额 = 预算总额 − 累计已消费                                                                                                                                                                                                                                                                                                                                                                                                |
| **本期可用余额**       | 本期可用余额 = 本期预算 − 本期已消费，可为负（红色展示）。跨周期不结转、不抵扣；历史周期差额只在预算详情中以「历史周期差额」展示。                                                                                                                                                                                                                                                                                            |
| **使用率**             | 总使用率 = 已消费 / 预算总额 × 100%；本期使用率 = 本期已消费 / 本期预算 × 100%。                                                                                                                                                                                                                                                                                                                                              |
| **预算来源部门**       | 部门的预算来源 = 其直接上级部门；用户的预算来源 = 其所属部门。项目预算来源 = 项目责任部门。                                                                                                                                                                                                                                                                                                                                   |
| **部门单用户每期上限** | 共享模式下由管理员配置的默认单用户每期额度，作用于该部门及下级部门未单独配置用户预算的用户，逐期生效，支持按期均分或逐期分配；不提前占用部门预算，用户实际消费时才扣减部门预算。未配置时显示「不限制」，仅表示不设个人额度，消费仍受部门预算总额约束                                                                                                                                                                          |
| **项目成员每期上限**   | 项目预算中配置的统一单成员每期额度，逐期生效，支持按期均分或逐期分配；不代表为成员预留额度，成员实际消费时才扣减项目预算，不占用用户预算。未配置时显示「不限制」，仅表示不设个人额度，消费仍受项目预算总额约束                                                                                                                                                                                                                |
| **继承自 XX部门**      | 共享模式下用户未单独配置用户预算时，展示实际提供共享预算的部门：本部门有有效部门预算则为本部门，否则为最近一个有有效预算的共享模式祖先部门                                                                                                                                                                                                                                                                                    |

**用量保护相关术语**

## 2\. 功能需求

### 2\.1 消费与账单

消费与账单模块是成本管理的数据管线，从底层到上层分为三个层级：**费用计量**（请求级，数据产生）→ **费用明细**（记录级，逐条查询）→ **消费账单**（周期\+维度级，聚合出报表）。

#### 2\.1\.1 业务说明

- **费用计量**是数据基础。每一次经过 AI 安全网关的请求，系统自动记录 Token 消耗并按计量规则计算费用，形成费用明细记录。费用数据按用户、项目、部门、模型等维度聚合后，用于仪表盘成本总览、消费账单生成和预算消耗追踪。

- **费用明细**是请求级消费的逐条查询入口，提供完整的字段、常驻筛选、更多筛选和导出能力，既支撑管理员日常审计，也是消费账单详情页跳转回来的数据源。

- **消费账单**以周或月为周期，将该周期内的 AI 消费按供应商、部门、项目、用户、模型五个维度汇总，生成结构化报表。支持手动生成（即时单次）和自动生成任务（周期性）。

- 费用主体归属规则：

  - 当 API Key **未关联项目**时，费用主体为**使用人所属部门**，费用只计入使用人所属部门；

  - 当 API Key **关联项目**时，费用主体为**项目**，费用只计入项目预算。

- 账单统计范围按预算归属判断：

  - 对于未关联项目的费用，按使用人所属部门判断是否纳入账单；

  - 对于关联项目的费用，按项目责任部门判断是否纳入账单；

  - 使用人部门仅表示实际使用人来自哪个部门，不代表项目费用归属到该部门预算。

#### 2\.1\.3 计量规则

- 费用计算在请求完成后（收到供应商响应后）执行

- 计算公式：`总费用 = (Input Token × Input 单价 + Output Token × Output 单价 + Cached Input Token × 缓存 Input 单价) / 1,000,000`，其中 Token 类单价均为每百万 Token 单价

- 使用请求发生时该物理模型当前生效的价格记录

- 如物理模型未配置价格，费用记录为 0

- Token 计数以供应商返回的 usage 字段为准

- 费用明细在请求完成后实时写入，同时异步更新预算消耗

- 费用明细与消费账单统计全部计费请求：模型定价为 0 导致消费金额为 0 的请求仍进入费用明细列表、汇总、导出与账单统计（请求次数与 Token 用量按实际值计入，消费金额为 0），避免静默遗漏导致消费漏计与计费偏低

- 厂商未回传 usage 的成功请求同样保留在费用明细与账单中：费用为 0、无计费项，Token 列以灰色显示「暂无数据」，便于定位网关侧费用低于实际的原因

- 仅当请求失败且完全未产生费用（FAILED 且消费金额为 0）时不计入费用明细与账单；该请求仍保留访问日志

- 如果 API Key 未关联项目，费用主体为部门，费用只计入用户所属部门，同时更新用户预算消费。

- 当 API Key 关联项目时，费用主体为项目。费用计入项目预算，并按项目责任部门归集为项目消费；上级部门统计时汇总下级数据，不重复记账；不更新使用人所属非项目消费。

- 一条费用明细只产生一次实际费用，不在多个部门之间重复记账。也不能在项目和部门间重复记账。

部门维度特有筛选：①「部门消费类型」下拉（全部部门 / 有项目消费 / 仅非项目消费）；②「部门」部门树形下拉（支持模糊搜索、多选，选中部门含其下级）。无名称搜索框。

#### 2\.1\.6 请求详情与多模态 usage（P1）

> P1 规划，不纳入 P0 验收范围。P0 已覆盖文本模型的请求详情与文本 Token 列，P1 仅扩展图片、音频、视频用量与多模态计费项。

**2\.1\.6\.1 背景与目标**

P0 已支持文本模型的请求详情、计费项与原始 usage 展示，但用量维度仍限于输入 / 输出 / 缓存 Token，物理模型也只配置 Token 单价。图片、语音、视频等按张数或时长计费的模型无法逐项还原消费构成，也无法解释不同厂商 usage 字段差异带来的金额差异。

P1 目标：

1. 请求详情在 P0 文本模型基础上扩展多模态展示，按模型模态与厂商返回的 usage 展示本次消费构成。

2. 费用可逐项还原：每个计费项的「用量 × 单价 = 小计」，合计与列表费用一致，可用于核对厂商账单的构成差异。

3. 历史费用使用请求时价格快照，后续调价不影响历史记录金额。

设计原则：

1. 费用 = Σ 计费项小计。

2. 用量保留原始单位，不将图片张数、音频时长、Token 等不同单位合并为一个「总用量」；统一的只有金额。

3. 厂商未回传的用量不补 0、不臆造，明确标注用量来源。

**2\.1\.6\.2 数据模型扩展（F\-P1\-COST\-01）**

费用记录（CostRecord）追加 2\.1\.2 中的 `raw_usage`、`normalized_usage`、`billing_items`、`usage_source`、`price_snapshot_version` 字段，其中 `billing_items` 的子字段为：

| 字段           | 类型    | 说明                                                                                   |
| -------------- | ------- | -------------------------------------------------------------------------------------- |
| name           | string  | 计费项名称，如「输入 Token」「图片生成（1024×1024）」                                  |
| kind           | enum    | TOKEN / IMAGE / AUDIO / VIDEO                                                          |
| quantity       | decimal | 用量                                                                                   |
| unit           | string  | Token / 张 / 秒 / 帧                                                                   |
| unit\_price    | decimal | 请求时生效单价；Token 类为每百万 Token 单价                                            |
| currency       | enum    | 币种，跟随请求时配置                                                                   |
| amount         | decimal | 小计；Token 类 = quantity ÷ 1,000,000 × unit\_price，其他单位 = quantity × unit\_price |
| price\_version | string  | 价格版本，与 price\_snapshot\_version 对应                                             |

**2\.1\.6\.3 统一 usage 口径**

| kind  | 字段                                                                                         | 单位      | 适用场景                             |
| ----- | -------------------------------------------------------------------------------------------- | --------- | ------------------------------------ |
| TOKEN | input\_tokens、output\_tokens、cached\_read\_tokens、cache\_write\_tokens、reasoning\_tokens | Token     | LLM、Embedding、多模态模型的文本部分 |
| IMAGE | image\_count、image\_size、image\_quality、image\_input\_tokens                              | 张、Token | 图片生成、图文输入                   |
| AUDIO | audio\_seconds、audio\_input\_tokens、audio\_output\_tokens                                  | 秒、Token | 语音识别、语音合成、实时语音         |
| VIDEO | video\_seconds、frame\_count                                                                 | 秒、帧    | 视频生成、视频理解                   |
| MIXED | 引用多个计费项                                                                               | —         | 图文混合等多计费项请求               |

规则：

1. 一个请求可同时包含多个 kind，例如多模态模型同时产生文本 Token 与图片计费项。

2. 不同单位不合并汇总，详情按 kind 分组展示，仅金额合计。

3. 厂商未回传的维度留空，不以 0 冒充。

**2\.1\.6\.4 厂商 usage 适配（F\-P1\-COST\-02）**

| 厂商 / 接口                             | 原始 usage 关键字段                                                                                                                        | 映射到统一口径                                     |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| OpenAI Chat Completions                 | prompt\_tokens、completion\_tokens、total\_tokens、prompt\_tokens\_details\.cached\_tokens、completion\_tokens\_details\.reasoning\_tokens | 输入 Token、输出 Token、缓存命中 Token、推理 Token |
| Anthropic Messages                      | input\_tokens、output\_tokens、cache\_read\_input\_tokens、cache\_creation\_input\_tokens                                                  | 输入 Token、输出 Token、缓存读 Token、缓存写 Token |
| Google Gemini                           | usageMetadata\.promptTokenCount、candidatesTokenCount、cachedContentTokenCount、thoughtsTokenCount                                         | 输入 Token、输出 Token、缓存命中 Token、推理 Token |
| 阿里云百炼 / 火山方舟等 OpenAI 兼容接口 | prompt\_tokens、completion\_tokens 或 input\_tokens、output\_tokens                                                                        | 输入 Token、输出 Token                             |
| 语音类模型                              | duration（秒）                                                                                                                             | 音频时长；无 usage 时按网关计时                    |
| 图片生成类模型                          | 通常无 usage                                                                                                                               | 按张数 \+ 尺寸 / 质量计费                          |
| 其他厂商                                | 未知字段保留在 raw\_usage                                                                                                                  | 仅映射已识别字段，其余标注不可用                   |

适配失败处理：

1. 厂商未回传 usage → usage\_source = UNAVAILABLE，请求仍保留在费用明细中，费用为 0；Token 列以灰色展示「暂无数据」，详情展示「厂商未回传 usage，本次请求未计算费用」。

2. 流式中断、超时、失败请求 → 已产生可计量用量按实际计费；完全未产生费用的计费项为空、费用为 0；厂商返回的片段保留在 raw\_usage 供排查。

3. 网关估算用量必须标注 usage\_source = GATEWAY\_ESTIMATED，不得与厂商回传用量混用展示。

**2\.1\.6\.5 按模态计费规则（F\-P1\-COST\-03）**

| 模型类型                  | 计费项                                                         | 单价来源                                |
| ------------------------- | -------------------------------------------------------------- | --------------------------------------- |
| LLM / MULTIMODAL 文本部分 | 输入 Token、输出 Token、缓存读 Token、缓存写 Token、推理 Token | 该模型价格快照中的 Token 单价           |
| EMBEDDING                 | 输入 Token                                                     | 该模型价格快照中的输入单价              |
| IMAGE                     | 图片张数 × 尺寸 / 质量单价；图文输入的图片 Token               | 模型接入提供的图片单价、输入 Token 单价 |
| AUDIO                     | 音频时长 × 秒单价，或音频 Token                                | 模型接入提供的音频单价                  |
| VIDEO                     | 视频时长 × 秒单价                                              | 模型接入提供的视频单价                  |

规则：

1. 计费项小计 = 用量 × 单价，金额按币种保留 6 位小数，页面展示 2 位。

2. 请求落库时同步保存计费项与价格版本；后续调价不回写历史记录。

3. 一次请求包含多个计费项时，总费用 = Σ 小计，与费用明细列表「费用」一致。

4. 失败且完全未产生费用 → 计费项为空，费用为 0，详情展示失败原因。

5. 多模态与工具调用等扩展计费项由模型接入模块提供，成本侧直接按该模型价格快照中的计费项展示，不单独扩展计价字段。

**2\.1\.6\.6 交互设计（F\-P1\-COST\-04）**

列表入口：

- 费用明细表格行支持点击打开右侧「请求详情」抽屉；行内「复制请求 ID」等按钮点击时阻止冒泡，不触发抽屉。

- 不改变 P0 已定义的列与顺序；「输入 Token」「输出 Token」「总 Token」等 Token 列 tooltip 增加说明「仅统计文本类用量，图片、语音、视频请求按计费项在请求详情中展示」。

抽屉结构：

| 区域       | 内容                                                                                                                                                                                                                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 基本信息   | 请求时间、请求 ID、请求状态、费用主体类型、项目、项目责任部门、使用人、使用人部门、API Key、模型名称、供应商实例、币种                                                                                                                                                                                                       |
| 费用构成   | 计费项表格：计费项、用量、单位、单价、小计；Token 类计费项的用量按原始 Token 展示、单价按每百万 Token 展示并标注「/ 百万 Token」，表下说明「Token 类计费项单价按每百万 Token 计」；底部展示费用合计；无计费项时，失败请求展示「本次请求未产生费用」，厂商未回传 usage 的成功请求展示「厂商未回传 usage，本次请求未计算费用」 |
| 原始 usage | 默认折叠、只读；无数据时展示「厂商未回传 usage」                                                                                                                                                                                                                                                                             |
| 请求异常   | 仅失败请求展示错误码与错误信息                                                                                                                                                                                                                                                                                               |

**2\.1\.6\.7 对列表与报表口径的影响**

1. 费用金额与请求次数统计口径不变，仍覆盖全部模态。

2. 纯图片、纯语音、纯视频请求的「输入 Token」「输出 Token」「缓存 Token」「总 Token」列展示「—」；图文混合等含文本用量的请求按文本 Token 正常展示。

3. 账单维度分析中「输入 Token」「输出 Token」「缓存 Token」同步限定为文本类用量，工具提示说明口径。

4. 若后续增加「模态」筛选或「计费维度」列，按新增需求单独评审，不属于本章节验收范围。

**2\.1\.6\.8 边界与约束**

1. 图文输入中，厂商未单独返回图片 Token 时，整体计入输入 Token，并在计费项中注明「图片用量已包含在输入 Token 中」。

2. 缓存读与缓存写按厂商口径分别列项，不将缓存写入折算为输入 Token。

3. `raw_usage` 随费用明细永久保留，与费用明细同生命周期（见 7\.3）。

4. 币种跟随请求时配置，不做汇率换算。

5. 所有估算值必须标注来源，详情页不得出现未标注来源的推断用量。

**2\.1\.6\.9 验收标准**

1. 文本模型（P0 回归）：详情计费项合计与列表费用一致，且等于输入 Token × 单价 \+ 输出 Token × 单价 \+ 缓存费用。

2. Anthropic 请求：缓存读与缓存写分别列为独立计费项，金额可还原。

3. 图片模型：按张数与尺寸 / 质量还原小计。

4. 语音、视频模型：按时长还原小计。

5. 失败请求：费用为 0，展示失败原因，不展示伪造用量。

6. 厂商未回传 usage：费用明细列表 Token 列以灰色显示「暂无数据」，请求详情展示「厂商未回传 usage」，并标注计费来源为网关计量。

7. 调价后查看历史记录：单价与金额保持请求时快照值，不随当前模型配置变化。

**2\.1\.6\.10 P1 范围**

包含：多模态 usage 与计费项扩展、厂商多模态 usage 适配、按模态计费规则、请求详情多模态分组展示、缺失与估算标注、按模型接入计费项展示多模态与工具调用费用。

不包含：成本优化建议、跨币种换算、usage 导出 API、按模态拆分账单、自动异常核对工单。

## 3\. 预算管理

### 3\.1 预算模型与口径

#### 3\.1\.1 预算类型与配置原则

1. 预算管理包括部门预算、项目预算、用户预算，三类预算共用同一配置流程（见 3\.4）。

2. **同一主体只能有一条预算**：部门、项目、用户已配置预算时，再次配置视为编辑现有预算，不新增第二条。

3. 减少预算仅调整预算总额，不涉及已发生消费。

4. 项目预算为项目成员共用，不按成员预分配额度；「项目成员每期上限」仅限制单个成员在每个项目预算期内的消费，逐期重置，不代表预留额度。

5. 允许移除已配置的部门预算、项目预算、用户预算。移除前二次确认并说明影响（关联项目预算失效、项目失去预算支撑、独立模式下用户无法使用 AI 等）；部门预算存在下级部门预算、项目预算或用户预算时，必须同步移除后才能移除，避免出现无上级预算的下级配置。移除后不提供恢复或回收站。

6. **保存阻断**：命中以下任一条件时保存按钮置灰，并在弹窗右栏展示原因：

   - 预算对象未选；

   - 起止日期无效或超出来源预算有效期；

   - 预算总额 ≤ 0；

   - 编辑时预算总额低于当前已消费；

   - 总部预算总额低于下级已配置合计或下级累计已消费；

   - 自定义分期时前 N−1 期之和超过预算总额；

   - 非总部场景本次配置超过来源总余额；

   - 单用户或项目成员每期上限高于对应期预算金额；

   - 总部调整周期时，存在周期比新周期更粗的下级部门或用户预算。

#### 3\.1\.2 预算层级与继承

**预算继承链（effectiveDepartmentBudget）**

继承仅在**当前对象自身未配置预算**时发生：当前部门已配置 DepartmentBudget 时直接使用自身预算，不再向上查找。

- **部门**：部门自身未配置 DepartmentBudget 时，从当前部门向上查找，遇到最近一个有 DepartmentBudget 的祖先：

  - 祖先为 SHARED → 返回该预算，允许继承

  - 祖先为 INDEPENDENT → 停止查找，无预算

- **用户**：用户自身未配置 UserBudget 时，从所属部门向上查找生效部门预算，规则同上；用户已配置 UserBudget 时直接使用自身预算，不再受部门单用户每期上限调整影响。

- **继承来源展示**：共享模式下用户未单独配置用户预算时，「继承自 XX部门」中的 XX部门指实际提供共享预算的部门——用户所属部门有有效部门预算时为该部门，否则为最近一个有有效预算的共享模式祖先部门。

**预算层级与准入**

| 层级       | 适用范围   | 配置要求                         | 未配置时                                                            |
| ---------- | ---------- | -------------------------------- | ------------------------------------------------------------------- |
| 总部预算   | 全部用户   | **必须配置**，系统部署后引导设置 | 系统引导配置，不可跳过                                              |
| 子部门预算 | 部门内用户 | 可选，建议配置                   | 祖先为共享模式：继承祖先预算；祖先为独立模式：该部门用户无法使用 AI |
| 用户预算   | 单个用户   | 取决于生效部门的预算模式         | 共享模式：继承部门单用户每期上限；独立模式：无法使用 AI             |

- **预算是使用 AI 的前提条件**，无预算即不可用

- **总部预算即企业总预算**，总部已消费汇总全部子部门和用户的消费

- **预算向下继承（仅共享模式）**：子部门未配置预算时，如最近祖先预算为共享模式则自动继承；祖先为独立模式则不可继承，子部门必须配置自己的预算

- 部门预算支持两种模式：

  - **共享模式**：用户共享部门预算，可配置部门单用户每期上限，也可为个别用户单独配置用户预算

  - **独立模式**：必须为每位用户配置用户预算，未设置用户预算的用户无法使用 AI

- 用户预算不提前占用部门预算，部门预算总额始终是全局硬约束；配置时校验来源总余额，超出时禁止保存

- 请求时按总部 → 生效部门 → 用户顺序逐级检查

**删除对预算的影响**

| 操作         | 影响                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| 删除用户     | 同步删除该用户的预算配置，历史费用记录保留                                                             |
| 用户转移部门 | 用户预算删除，需在新部门重新配置用户预算；旧部门消费额不回退，新部门开始累计该用户后续消费             |
| 删除部门     | 同步删除该部门的预算配置、部门下所有用户的预算配置，以及该部门负责项目的项目预算配置；历史费用记录保留 |
| 新增用户     | 共享模式部门：自动继承部门单用户每期上限；独立模式部门：需管理员配置用户预算后方可使用 AI              |

#### 3\.1\.3 费用归属与消费汇总

- 非项目费用：API Key 未关联项目时，费用主体为使用人所属部门。费用只计入该部门，并向上汇总至其所有上级部门，扣减该用户预算，不重复记账。

- 项目费用：API Key 关联项目时，费用主体为项目。费用只计入项目预算，并按项目责任部门归集；部门统计中的项目消费由责任部门及其上级部门汇总子树数据展示，不重复记账。

- 总部预算即企业总预算：总部已消费等于全企业非项目消费与项目消费之和。

- 费用主体类型、部门总消费等术语见 1\.4；字段定义见 3\.3。

#### 3\.1\.4 预算周期

| 规则         | 说明                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| 预算周期     | 年度（自然年）、季度（自然季）或月度（自然月）                                       |
| 配置范围     | 总部设置企业预算周期；下级部门、用户预算默认跟随，只能选择等于或更细的周期，不能更粗 |
| 周期起止     | 年度：1 月 1 日至 12 月 31 日；季度：1/4/7/10 月 1 日起；月度：每月 1 日至月末       |
| 自动滚动     | 当前周期结束后自动进入新周期，预算额度按新周期重置，消费记录只累计不归零             |
| 临时追加额度 | 待定，依赖工单管理                                                                   |
| 中途创建     | 周期中间创建预算时，当前周期从创建日开始，下一完整周期按自然年/季/月对齐             |
| 中途修改     | 修改预算总额立即生效，已消费金额不变；永久追加按剩余未结束周期重新拆分各期配额       |

总部修改预算周期后，跟随的下级部门与用户预算同步新周期；已显式配置更细周期的下级保持自身周期与分期计划不变。预算总额和历史消费保持不变，当前周期起止日期由系统按新周期规则维护。下级周期比新周期更粗时阻断保存，并提示先调整该下级周期。

部门单用户每期上限、项目成员每期上限随预算周期一起重排：已存在周期保留原值，新周期默认沿用最近一期金额；均分方式按最新值重新均分。

**预算不结转**

- 跨周期不结转、不抵扣：本期未使用额度不累加到下期，本期超支也不从下期扣回。

- 已消费金额只累计、不归零，历史消费永久保留，用于账单查询与趋势对照。

- 每个新周期的可用额度恒等于该期预算（含该期有效的临时追加），与上一周期的使用情况无关。

#### 3\.1\.5 总额与本期口径

**总余额**：总余额 = 预算总额 − 累计已消费；历史周期是否用完或超支都不影响总余额，可为负。

**本期可用余额**：本期可用余额 = 本期预算 − 本期已消费，可为负；跨周期不结转、不抵扣，历史周期差额只在详情中以「历史周期差额」展示。单期预算时本期数据与整体一致；用户行本期分母包含有效临时追加。

**状态与预警**：列表状态按整体使用率判定；本期状态独立判定，本期也可单独触发预警或拦截。预算有效期外视为无预算，消费按请求完成时间归属到对应预算周期。

#### 3\.1\.6 预算状态判定

**统一状态判定**

适用于部门预算、项目预算、用户预算三类对象。

```Plaintext
ratio = consumed / amount × 100

ratio ≥ 100%          → EXCEEDED（超额，红色）
ratio ≥ critical阈值  → CRITICAL（严重预警，橙色）   // critical 阈值 = 该预算配置的严重预警阈值
ratio ≥ warning阈值   → WARNING（预警，黄色）        // warning 阈值 = 该预算配置的预警阈值
其他                   → NORMAL（正常，绿色）
```

三类派生状态（不参与 budgetStatus 计算）：

| 状态         | 含义                                                               | 列表展示          |
| ------------ | ------------------------------------------------------------------ | ----------------- |
| INHERITED    | 部门未配置预算，从最近一个共享模式祖先继承预算                     | 「继承自 XX部门」 |
| SHARED       | 共享模式下用户未单独配置用户预算，继承部门单用户每期上限或部门预算 | 「继承自 XX部门」 |
| UNCONFIGURED | 部门 / 项目 / 用户未配置预算，且无可继承的共享预算                 | 「未设置」        |

表中预警阈值、严重预警阈值取该预算保存的配置值，不是固定 80% / 95%。

整体状态按总使用率判定；本期状态独立判定，本期超额不改变列表状态。

#### 3\.1\.7 预算操作权限

| 角色                   | 可配置范围                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| 总部管理员             | 全部部门、项目、用户预算                                                                     |
| 部门管理员、系统管理员 | 本部门及下级部门的部门预算、项目预算、用户预算；本部门自身预算由上级配置，可调整本级预算属性 |
| 安全管理员、审计员     | 只读，无预算写权限                                                                           |
| 项目管理员             | 本项目预算只读，可通过工单申请追加                                                           |

- **来源校验**：部门预算要求被配置部门的上级有有效预算；项目预算要求项目责任部门有有效预算；用户预算要求用户所属部门有有效预算。

- **总部预算仅总部账号可配置**，不做来源校验。

- **币种仅总部可修改**，下级币种只读跟随总部。

#### 3\.1\.8 币种

- 币种仅 CNY / USD。

- 总部预算默认 CNY，可切换 USD；保存后级联更新全部下级部门、项目、用户预算币种。

- 所有下级预算币种只读，始终跟随总部。

- P0 不做跨币种折算。

### 3\.2 用量保护规则

用量保护只有个人保护一层，用于限制本人短时间内的非项目消费金额：

1. **配置入口**：仅个人中心「使用概览」由用户本人配置，`scope_type` 固定 `USER_SELF`；管理员端（部门 / 项目 / 用户预算）无配置入口。

2. **窗口与维度**：仅小时、日两个金额窗口，只按金额限制；不做分钟窗口，不按 Token、请求数等计量。

3. **默认状态**：默认关闭；关闭时不展示金额输入，保留历史配置。

4. **预算关系**：不占用、不改变预算额度；预算校验优先，预算通过后才校验用量保护。

5. **生效与处理**：规则变更立即生效；命中限额后按规则选择的动作处理：仅告警时放行并记录，拦截请求时阻断本人非项目调用。

6. **命中通知**：仅通知用户本人，渠道为站内信 / 邮件（至少选一项）；同一用户、同一窗口、同一动作每个窗口只通知一次；邮件要求本人已配置有效邮箱。

7. **并发**：不做在途预占，并发请求可能小幅超出，下一笔请求即被拦截。

8. **边界**：不做 RPM/TPM、模型级、Provider 级、API Key 级限流、并发数限制和多条件组合。

| warning\_threshold     | int\(%\)        | 是       | 同部门预算                                                                                             |
| critical\_threshold    | int\(%\)        | 是       | 同部门预算                                                                                             |
| over\_action           | enum            | 是       | ALERT\_ONLY / BLOCK\_USER（额度用尽后阻断该用户所有非项目 Key 调用）                                   |
| consumed               | decimal         | 系统统计 | 该用户未关联项目 Key 的实际消费；项目消费归入项目预算                                                  |
| temporary\_adjustments | array\(json\)   | 系统维护 | 临时追加额度列表：追加金额、有效期、来源工单 ID、状态（ACTIVE / EXPIRED）                              |
| effective\_amount      | decimal         | 系统计算 | 本期预算总额 = 本周期配额 \+ 本周期有效临时追加；全部到期后回退为本周期配额                            |
| status                 | enum            | 系统维护 | NORMAL / WARNING / CRITICAL / EXCEEDED                                                                 |

**用量保护规则（UsageProtectionRule）**

| 字段           | 类型     | 必填 | 说明                                               |
| -------------- | -------- | ---- | -------------------------------------------------- |
| id             | string   | 是   | 规则 ID                                            |
| scope\_type    | enum     | 是   | 固定 USER\_SELF                                    |
| subject\_id    | string   | 是   | 用户 ID                                            |
| enabled        | boolean  | 是   | 是否启用，默认 false                               |
| hour\_limit    | decimal  | 否   | 每小时消费金额上限；空或 0 表示不限                |
| day\_limit     | decimal  | 否   | 每日消费金额上限；空或 0 表示不限                  |
| currency       | enum     | 是   | CNY / USD，跟随用户所属预算币种                    |
| over\_action   | enum     | 是   | ALERT\_ONLY（默认）/ BLOCK\_USER；命中后的处理动作 |
| channels       | array    | 是   | IN\_APP / EMAIL，至少一项，默认 IN\_APP            |
| configured\_by | string   | 是   | 配置人用户 ID（本人）                              |
| updated\_at    | datetime | 是   | 最近修改时间                                       |

规则：

1. 每个用户最多一条规则；启用时至少一个窗口金额大于 0。

2. 窗口按自然小时 / 自然天切分，按 Asia/Shanghai 计算，跨窗口自动从 0 开始，不结转。

3. 计数按用户维护，只用于用量保护判断，不重复计费。

4. 不占用预算额度；预算校验优先。

### 3\.4 通用预算配置流程

部门预算、项目预算、用户预算共用同一配置弹窗（宽 1300，左右两栏）与保存校验；对象选择与专属字段见 3\.5–3\.7。

**左栏 5 个分区**

1. **预算对象**：选择部门 / 项目 / 用户。

2. **生效时间与预算金额**：起止日期、预算总额、币种。

3. **预算计划**：部门预算的预算模式（共享 / 独立）；预算周期 \+ 总额驱动分配，支持按期均分或逐期分配；部门共享模式的单用户每期上限、项目的项目成员每期上限紧随其后，支持不限制 / 按期均分 / 逐期分配。

4. **预警与超额策略**：预警阈值（默认 80）、严重预警阈值（默认 95）、超额处理策略（仅告警 / 阻断；部门 BLOCK\_DEPARTMENT、项目 BLOCK\_PROJECT、用户 BLOCK\_USER）。

5. **预警通知设置**：预警 / 严重预警 / 超额三级，分别配置接收人与渠道（站内信 / 邮件）。

- 起止日期必须落在来源预算有效期内；预算周期默认跟随来源，只能等于或更细。

- 币种仅总部可修改（CNY / USD），下级预算币种只读跟随总部。

- 每期上限逐期生效、逐期重置，不提前占用部门 / 项目预算；每期上限不得超过对应期预算金额。

- 选择「不限制」时仅表示不设个人额度：部门共享模式下用户消费仍受部门预算总额约束，项目成员消费仍受项目预算总额约束。

- 修改预算周期后，逐期分配的每期上限中已存在周期保留原值，新周期默认沿用最近一期金额。

- 用户预算金额为有效期总额，各期配额由总额拆分；有效临时追加只叠加到本期。

**右栏**

- **总部预算**：「下级配置参考」展示两项：下级已配置合计（含下级部门与总部责任项目）、下级累计已消费。总部预算总额低于任一项时显示红色提示并禁止保存。

- **其他预算**：「预算来源概览」（预算总额、总已消费、总余额）\+「分配影响」（总余额 → 本次配置 → 分配后总余额，分配后为负标红）\+「预算有效期」进度。

- 共享模式用户预算不占用部门预算，本次配置记为「不占用部门预算」。

**保存阻断**：命中 3\.1\.1 任一条件时保存按钮置灰，并在右栏展示具体原因。

### 3\.5 部门预算

**业务说明**

- 部门预算按部门独立配置、自上而下逐级配置。上级不强制下级预算不超过自身额度，也不要求下级预算之和等于上级；每个部门以实际配置的金额为准。

- 部门预算是未关联项目调用的准入条件。未被任何有效预算覆盖的部门（自身未配置预算且最近祖先为独立模式），该部门用户无法通过未关联项目的 API Key 使用 AI；其负责的项目无法使用 AI。

- 部门已消费按子树统计，费用归属见 1\.4 与 3\.1\.3；继承、周期与状态规则见 3\.1\.2、3\.1\.4、3\.1\.6。

**F\-DBUDGET\-01 部门预算列表**

- 列表采用两级表头，按「基础信息 / 整体情况 / 本期情况 / 其他」分组：基础信息（部门名称、预算模式、起止日期）｜整体情况（预算总额、已消费、总余额、整体使用率、状态）｜本期情况（预算周期、本期预算）｜其他（超额策略、操作）。

- 状态用颜色标识：绿色（正常）、黄色（预警）、橙色（严重预警）、红色（超额）；未配置预算的部门按祖先预算模式展示「继承自 XX部门」或「未设置」。

- 「起止日期」展示该预算的整体有效期（开始日期 至 结束日期）；「预算周期」位于本期情况，展示周期类型与本期起止日期（如「月度 · 11\-01 至 11\-30」）。

- 「本期预算」单元格分两行：第一行「本期已消费 / 本期预算」，第二行「本期状态」；不展示进度条，单期预算时本期数据与整体一致。

- 支持按部门名称搜索、按状态筛选、分页；行内提供「查看」「配置」，「移除预算」仅对已配置的本级预算展示。

- 预算配置逻辑见 3\.4。

### 3\.6 项目预算

**业务说明**

- 项目预算用于控制项目维度的 AI 消费。项目与部门解耦，项目成员可以来自多个部门。

- 项目预算由项目责任部门直接承担，不单独配置预算来源部门；责任部门决定预算归属、配置权限、账单归属与展示位置。

- API Key 关联项目时走项目预算；未关联项目时走用户预算。

- 仅状态为「进行中」的项目可使用项目预算；禁用或归档后按「项目未配置预算」处理，重新启用后恢复。

- 「本期预算」单元格分两行：第一行「本期已消费 / 本期预算」，第二行「本期状态」；不展示进度条，单期预算时本期数据与整体一致。

**F\-PBUDGET\-02 配置项目预算**

- 可选择多个当前状态为「进行中」且未配置预算的项目；所选项目须属于同一项目责任部门，共用周期与预算计划。

### 3\.7 用户预算

**业务说明**

1. 用户预算用于控制单个用户未关联项目的 AI 支出，金额口径为有效期总额；预算检查按总额与本期预算两个口径分别判断。

2. **共享模式部门**：用户共享部门预算，先到先得；管理员可配置部门单用户每期上限，也可为个别用户单独配置用户预算，单独配置覆盖部门统一值。

3. **独立模式部门**：每个用户必须配置用户预算，未设置的用户无法使用未关联项目的 Key；用户预算之和不超过部门预算不做校验。

4. 用户预算只用于未关联项目的 API Key 消费；使用关联项目的 Key 时消耗项目预算。

5. 用户参与的项目预算由项目成员共用，不占用用户预算。

6. 用户预算只能由管理员配置；用户本人可在个人中心提交「申请增加预算」工单，审批通过后由系统按工单结果增加预算。

**F\-UBUDGET\-01 用户预算列表**

- 列表采用两级表头：基础信息（用户、所属部门、预算类型、起止日期）｜整体情况（用户预算、有效临时追加、预算总额、已消费、总余额、整体使用率、状态）｜本期情况（预算周期、本期预算）｜其他（超额策略、操作）。

- 「起止日期」展示用户预算整体有效期；「预算周期」展示周期类型与本期起止日期。

- 「本期预算」单元格分两行：第一行「本期已消费 /（本周期配额 \+ 有效临时追加）」，第二行「本期状态」；不展示进度条。

- 默认展示所有用户：已配置、继承部门单用户每期上限、未设置；按状态优先级排序：超额 \> 严重预警 \> 预警 \> 正常 \> 继承 \> 未设置。

- 支持按用户名 / 姓名搜索、按部门筛选、按状态筛选、分页。

**F\-UBUDGET\-02 配置用户预算**

- 配置逻辑见 3\.4。

- 可搜索并多选本部门及下级部门用户；批量配置要求同一预算来源部门、同一预算模式、同一预算周期、同一有效期，不满足的用户置灰并标注原因。

- 用户预算金额按有效期总额录入，各期配额由总额拆分。

- 超额处理策略：ALERT\_ONLY（仅告警）/ BLOCK\_USER（阻断该用户的非项目调用）。

- 不校验用户预算总和与部门预算的关系，部门预算总额始终是全局硬约束。

**F\-UBUDGET\-03 编辑用户预算**

- 可修改用户预算总额、预警阈值、严重预警阈值、超额策略、各级通知接收人和渠道；临时追加独立展示，不计入用户预算总额。

- 预算周期默认跟随来源部门预算，只能等于或更细。

- 修改总额后立即作用于当前及后续周期，按剩余未结束周期拆分各期配额；已消费不变。

**F\-UBUDGET\-04 移除用户预算**

- 仅已单独配置用户预算的用户显示「移除预算」。

- 独立模式下提示移除后该用户将无法使用未关联项目的 AI 服务；共享模式下提示将恢复继承部门单用户每期上限。

- 存在有效临时追加时提示将一并失效；历史记录保留。

**F\-UBUDGET\-05 用户预算详情**

- 以预算详情抽屉（F\-DBUDGET\-01\.1）呈现：

  - 概览：用户预算总额、有效临时追加及有效期、预算总额、阈值、各级通知接收人。

  - 每期预算明细：各期预算与使用情况。

  - 消费分析：消费趋势、用户消费 TOP 10、模型消费 TOP 10。

  - 变更历史：临时追加记录与预算变更历史。

- 临时追加由审批通过的工单自动创建；同一用户可有多条，额度相加、分别到期，不提供独立新增入口。

### 3\.8 预算检查（数据面）

**业务说明**

预算检查在身份识别、Key 使用范围校验和模型权限检查通过后、实际转发请求之前执行。只判断准入时点已发生的消费是否已超额，不按本次请求预估金额判断。

**检查逻辑**

```Plaintext
请求进入
→ 身份识别
→ Key 使用范围与项目有效性校验
   ├── 个人使用：继续
   └── 项目使用：项目必须为进行中，且项目预算存在且在有效期内
→ 模型权限检查
→ 预算检查
→ 个人用量保护
→ 安全检测
→ 模型解析
→ 请求转发
```

非项目使用预算检查流程：

1. 确定用户生效部门预算：有有效预算则使用该部门预算；无则沿部门树向上查找最近祖先预算，共享模式可继承，独立模式拒绝，无任何有效预算则拒绝。

2. 检查总部预算（企业总预算）：超额且策略为 BLOCK\_DEPARTMENT 时拒绝，提示「企业总预算已超额」；ALERT\_ONLY 时记录告警并继续。

3. 检查部门预算子树汇总：从总部到用户生效部门路径上的所有已配置部门预算逐一检查；任一超额且策略为 BLOCK\_DEPARTMENT 时拒绝，ALERT\_ONLY 时告警并继续。部门预算按子树消费汇总判断，各级预算金额独立配置。

4. 检查用户级额度：

   - 共享模式：有单独用户预算时按总额及本期预算检查；无则按部门单用户每期上限的当期额度检查；当期上限也未配置时不设个人额度，但仍受部门预算总额约束。

   - 独立模式：无用户预算时拒绝；有则按总额及本期预算检查。

   - 超额且策略为 BLOCK\_USER 时拒绝；继承部门单用户每期上限的超额固定按 BLOCK\_USER 处理，只阻断当前用户。

项目使用预算检查流程：

1. 校验项目状态与项目预算：项目必须为进行中且项目预算存在、在有效期内，否则拒绝。

2. 检查总部预算：超额且策略为 BLOCK\_DEPARTMENT 时拒绝；ALERT\_ONLY 时告警并继续。

3. 检查项目责任部门及其上级部门预算：任一超额且策略为 BLOCK\_DEPARTMENT 时拒绝；ALERT\_ONLY 时告警并继续。项目调用不检查请求用户所属部门预算。

4. 检查项目预算：按总额及本期预算检查；超额且策略为 BLOCK\_PROJECT 时拒绝，ALERT\_ONLY 时告警并继续。

5. 检查项目成员每期上限：统计当前用户在本项目当前预算期内的消费；超额且策略为 BLOCK\_PROJECT 时拒绝，ALERT\_ONLY 时告警并继续。

6. 所有检查通过后继续请求。

- 每一层级独立判断：先看是否超额，再看超额策略是阻断还是仅告警。

- 预算检查只判断准入时点已发生的消费；消费异步更新，允许在更新窗口内阶段性地小幅超支。

- 临时追加到期导致本期预算回退时，已消费不变；若基础预算为 0 且临时追加全部到期，按无用户预算处理。

- 预算检查需在毫秒级完成，各级预算、周期配额、项目成员当期消费使用内存缓存。

**预算消费更新**

- 请求完成后，根据实际消费金额异步更新各级预算的 `consumed` 和对应 `BudgetPeriodQuota.consumed_amount`。

- 非项目消费：在用户所属部门 `direct_consumed` 中累加，并按子树汇总刷新该部门及所有上级部门的 `consumed`；有用户预算时同时更新用户预算消费。

- 项目消费：更新项目预算、项目成员当期消费，并在项目责任部门 `allocated_project_consumed` 中累加，按子树汇总刷新责任部门及所有上级部门的 `consumed`。

- 更新时同时检查总预算和本期预算两个维度，分别按配置的预警阈值、严重预警阈值和 100% 判断通知；列表状态仍按整体使用率判定。

**预算阻断返回**

- HTTP 状态码：429

- 错误码：`BUDGET_EXCEEDED`

- 响应头：`Retry-After`：本期超额时为距下期开始的秒数；总额超额时为距预算有效期结束的秒数。

- 响应体示例：

```JSON
{
  "error": {
    "code": "BUDGET_EXCEEDED",
    "message": "部门预算已超额，请求未执行。",
    "level": "DEPARTMENT",
    "scope": "non_project",
    "budget_id": "db-d2",
    "budget_name": "平台研发部",
    "limit": 40000.00,
    "consumed": 40520.00,
    "remaining": -520.00,
    "currency": "CNY",
    "period_start": "2026-11-01",
    "period_end": "2026-11-30",
    "reset_at": "2026-12-01T00:00:00+08:00"
  }
}
```

- `level`：ENTERPRISE / DEPARTMENT / USER / PROJECT

- `scope`：non\_project / project

- 被阻断请求记录为「已拒绝」，原因「预算超额」，不计费、不出现在费用明细，可在访问记录与审计中心查询。

**用量保护校验**

预算检查通过后，执行个人用量保护校验：

1. 仅对非项目消费校验用户本人的小时 / 日限额；项目消费不校验。

2. 任一窗口达到限额时按规则自身的 `over_action` 处理：`BLOCK_USER` 拒绝请求，`ALERT_ONLY` 放行并通知本人；不再沿用用户预算的超额策略。

3. 预算已阻断时不再执行用量保护。

拦截返回：

- HTTP 状态码：429

- 错误码：`SPENDING_RATE_LIMIT_EXCEEDED`

- 响应头：`Retry-After`，值为距当前窗口重置的秒数。

- 响应体示例：

```JSON
{
  "error": {
    "code": "SPENDING_RATE_LIMIT_EXCEEDED",
    "message": "已达个人每小时消费保护（¥50.00/小时），请求未执行。",
    "scope": "USER_SELF",
    "window": "HOUR",
    "limit": 50.00,
    "currency": "CNY",
    "reset_at": "2026-11-06T15:00:00+08:00"
  }
}
```

计数与并发：

1. 计数键为「用户 ID \+ 窗口类型 \+ 窗口开始时间 \+ 币种」。

2. 请求进入时按当前窗口已用金额判断，结算后用实际金额更新窗口用量。

3. 不做在途预占与回填；并发请求可能小幅超出，下一笔请求即被拦截。

4. 0 元请求不计入窗口用量；失败但已产生费用的请求按实际金额计入。

5. 规则变更立即生效，已用金额延续，不清空当前窗口。

访问记录：

1. 被拦截请求记录为「已拒绝」，原因「用量保护」，保存窗口、限额、已用金额和重置时间。

2. 被拦截请求不计费、不出现在费用明细，可在访问记录与审计中心查询。

3. 达到限额但放行的请求正常计费，费用明细请求详情展示「已触发用量保护」。

### 3\.9 预算预警通知

**业务说明**

预算配置人可在每条部门、项目或用户预算中分别配置预警、严重预警、超额通知的接收人与渠道。预警阈值与严重预警阈值按每条预算单独配置（默认 80% / 95% 仅为初始值）。总预算和本期预算两个维度分别判断并发送。用户预算默认通知预算所属用户；部门预算和项目预算由配置人显式指定接收用户。P0 支持站内信和邮件。

**F\-NOTIFY\-01 按预算配置接收人与渠道**

| 配置项       | 触发条件                             | 接收人                                                                           |
| ------------ | ------------------------------------ | -------------------------------------------------------------------------------- |
| 预警通知     | 总预算或本期预算任一达到预警阈值     | 部门预算、项目预算：显式所选用户；用户预算：预算所属用户默认接收，可添加其他用户 |
| 严重预警通知 | 总预算或本期预算任一达到严重预警阈值 | 同上；各级接收人可不同                                                           |
| 超额通知     | 总预算或本期预算任一达到或超过 100%  | 同上；各级接收人可不同                                                           |

- 预警阈值、严重预警阈值按保存后的配置值执行，不是固定 80% / 95%。

- 每个级别可选渠道：站内信、邮件，可同时选择，也可清空表示该级别不发送通知；新预算默认选中站内信。

- 部门预算、项目预算任一级别启用渠道时，必须为该级别指定至少一名接收用户。

- 接收人按用户 ID 保存；候选用户为当前配置人本部门及下级部门的启用用户，支持按姓名、用户名、部门路径搜索。

- 选择邮件渠道时，接收人必须为启用用户且已配置有效邮箱，否则阻止保存并提示完善邮箱或调整接收人 / 渠道。

- 预算详情分别展示每级接收人和渠道；部门预算接收人为空时显示「不通知」，用户预算显示「本人（默认）」及额外接收人。

**F\-NOTIFY\-02 预警触发与发送规则**

- 每个预算对象同时检查总预算和当前预算周期两个维度，分别使用该预算配置的阈值和 100% 超额线，两个维度互不替代。

- 无独立周期额度的预算对象（如继承部门单用户每期上限）按来源预算周期检查总预算与本期两个维度。

- 总预算维度按 `已消费 / 预算总额` 判断；本期维度按 `本期已消费 / 本期预算` 判断；达到阈值或 100% 时触发对应级别通知。

- 一次消费更新跨越多个阈值时，按达到的级别分别处理；严重预警触发时，若对应维度预警尚未发送，同时补发预警。

- 总预算和本期预算同时达到同一级别时分别生成两条通知，不合并、不互相抑制。

- 个人用量保护命中时，仅向用户本人发送，渠道取规则配置的 `channels`；同一用户、同一窗口、同一动作每个窗口只发送一次；邮件发送前校验本人邮箱有效。

- 去重键：总预算维度 = `budget_id + level + validity_period + TOTAL + channel + recipient`；本期维度 = `budget_id + level + period_id + PERIOD + channel + recipient`。同一维度、同一级别、同一周期只发送一次；阈值或金额调整、重复消费更新不重复发送。

- 继承部门单用户每期上限触发时，通知本人及部门预算超额通知接收人；不为继承者生成独立预算级预警。

- 项目成员每期上限超额时，按项目预算的超额通知配置发送，文案中包含成员姓名。

- 发送时校验接收用户仍存在且为启用状态；无有效接收人或该级未启用渠道时不发送。

- 保存实际接收人、邮件地址、触发类型、触发维度、实际阈值、预算周期、预算额度、本期预算、消费金额、使用率、处理结果和触发时间的快照。

**F\-NOTIFY\-03 通知方式与访问权限**

- P0 支持站内信和邮件；站内信在管理端 / 用户端消息中心展示，各接收人的已读、未读状态独立。

- 通知包含触发类型（总预算 / 本期预算）、预算名称、预算周期、当前期起止、触发级别、实际阈值、预算总额、本期预算、已消费 / 本期已消费、总余额、使用率、超额策略、处理结果和触发时间。

- 被选为接收人仅允许接收通知摘要，不自动授予预算查看、配置或审批权限。

- 移除预算后保留已发送的通知记录，移除失效的预算查看入口。

### 3\.10 用户端预算信息展示

**业务说明**

预算双轨制：用户可同时使用用户预算和项目预算。API Key 关联项目就扣项目预算，未关联项目就扣用户预算。共享模式下用户未单独配置时继承部门单用户每期上限；独立模式下必须由管理员配置用户预算。

用户在个人中心「使用概览」查看三类信息：我的个人预算概览（已配置 / 继承 / 未设置）、我的项目内使用、我的消费汇总与消耗趋势。个人预算概览提供「申请增加预算」入口；项目管理员另可在「我的项目」列表与项目详情为所管理的进行中项目发起预算追加。

**展示内容**

- 我的个人预算概览：本期预算总额、本期可用余额、本期我的非项目消费、个人可用模型、用量保护；按已配置 / 继承 / 未设置三种状态展示。

- 我的项目内使用：当前用户参与且已配置预算的项目卡片，展示本期项目预算、本期已消费、本期可用余额、本期我已消费、项目成员每期上限、项目内可用模型。

- 我的消费汇总与消耗趋势：总消费、非项目消费、项目内消费、请求次数、Token 消耗、超额处理；「全部 / 非项目 / 项目内」Tab 仅切换趋势统计范围，趋势按模型分色。

卡片结构、字段口径、空状态与错误反馈以《个人中心\-使用概览 PRD（P0）》为准；本 PRD 只定义预算与消费的数据口径。用量保护规则见 3\.2，数据面校验见 3\.8。

### 3\.11 预算管理验收

**配置与默认态**

1. 配置弹窗包含左侧 5 个分区（预算对象、生效时间与预算金额、预算计划、预警与超额策略、预警通知设置），宽度 1300，左右两栏；部门预算模式与单用户 / 项目成员每期上限位于预算计划分区。

2. 币种仅 CNY / USD；总部默认 CNY、可切换，保存后级联全部下级；下级币种只读。

3. 保存按钮在命中 3\.1\.1 阻断清单时置灰，并在右栏展示具体原因。

4. 个人用量保护默认关闭，仅小时 / 日金额；触发动作默认仅告警，通知渠道默认站内信，选择邮件时校验本人邮箱。

5. 单用户 / 项目成员每期上限支持不限制 / 按期均分 / 逐期分配，可编辑；逐期分配在周期变更后，已存在周期保留原值，新周期沿用最近一期金额。

**列表与详情**

1. 部门、项目、用户三个 Tab 的列与 3\.5–3\.7 一致，均采用「基础信息 / 整体情况 / 本期情况 / 其他」两级表头，包含预算总额、已消费、总余额、整体使用率、本期预算，且无「用量保护」列与筛选。

2. 「本期预算」列分两行展示：第一行「本期已消费 / 本期预算」，第二行「本期状态」，无进度条；用户行第一行分母包含有效临时追加；单期预算时与整体一致。

3. 顶部概览卡按「整体情况 \+（多期时）本期情况」展示；单期时仅「整体情况」，三个指标等宽。

4. 详情抽屉 Header 展示总预算四项指标与两条进度条；Tab 为概览 / 每期预算明细 / 消费分析 / 变更历史。

5. 每期预算明细包含期数、周期时间、本期预算、已消费、本期剩余（负数红色）、使用率、状态。

**项目预算追加**

1. 「我的项目」列表与项目详情仅对项目管理员展示「申请增加预算」；项目非「进行中」或未配置预算时不展示。

2. 永久增加按「每期增加额度 × 剩余未结束周期数」换算并展示申请总额；执行后仅剩余未结束周期配额增加，已结束周期配额不变。

3. 临时增加在有效期内提高每个预算周期的上限，不按有效天数折算；到期后本期上限回落，已消费不变。

4. 同一工单重复执行不重复增加额度；变更历史展示来源工单号。

**数据面**

1. 预算检查按总部 → 部门 → 用户 / 项目逐级判断，总额与本期预算双口径。

2. BLOCK\_DEPARTMENT 阻断该部门及下级部门归属的全部调用，含项目调用；ALERT\_ONLY 放行并记录告警。

3. 企业总预算超额时阻断全部调用；项目调用检查责任部门到总部路径上的部门预算。

4. 继承部门单用户每期上限超额时只阻断该用户非项目调用；项目成员每期上限超额时只阻断该用户在该项目内的调用。

5. 预算阻断返回 429、`BUDGET_EXCEEDED` 与正确的 `Retry-After`，不产生费用记录。

6. 个人用量保护命中时按规则动作处理：拦截返回 429、`SPENDING_RATE_LIMIT_EXCEEDED`；仅告警则放行并标记；仅作用于本人非项目调用，并通知本人。

7. 被拦截请求在访问记录中可查。

**预警通知**

1. 阈值取各预算保存的配置值，修改后按新阈值判断。

2. 总预算与本期预算两个维度分别触发通知，同时达到同一级别时分别发送两条。

3. 同一维度、级别、周期、渠道、接收人只发送一次；新周期重新触发。

4. 无有效接收人或该级未启用渠道时不发送；已停用接收人跳过。

**权限与展示**

1. 总部管理员可配置全部预算；部门管理员配置本部门及下级；安全管理员只读；项目管理员仅可对本项目发起预算追加工单，不能直接配置项目预算。

2. 总部预算仅总部账号可配置，币种仅总部可修改。

3. 列表、详情与配置弹窗中的指标问号图标口径一致，以 1\.4 与 3\.5–3\.7 为准。

预算检查不做预估金额判断和额度预占，允许在消费更新窗口（\<3s）内产生阶段性超支；该行为是产品规则，不视为缺陷。

### 7\.2 安全

- 具备成本与预算管理权限的管理员只能查看和管理当前账号所属部门及其下级部门的用户消费、账单明细、用户预算和部门预算；总部账号范围为全组织

- 下级部门管理员不可查看总部预算卡片，仅可查看自己做在部门预算卡片；总部预算总额、币种、周期、模式及其他配置仅总部账号可修改

- 所有成本与预算接口在服务端校验部门树范围；前端隐藏筛选项和操作入口不构成授权边界

- 自动生成任务列表、编辑、启停和删除均按创建人隔离，不能读取或操作其他管理员的任务

- 审计员对费用和预算数据仅有只读权限

- 普通用户仅可查看自己的预算和费用信息

- 所有预算配置变更记录操作日志

- 预算变更历史不可修改、不可删除

- 普通用户只能查看自己参与或管理的项目。

- 项目管理员可查看项目成员及项目成员消费情况，普通成员只查看项目基础信息和自己的项目内消费。

### 7\.3 数据

- 费用明细（CostRecord）永久保留，不可修改、不可删除

- 消费账单永久保留

- 预算变更历史永久保留

- 预算周期结束后，历史周期的消费数据保留用于账单查询和趋势对照

### 7\.4 容量

容量基线与《身份管理 PRD（P0）》7\.4 保持一致：最多 100,000 个用户、10,000 个部门。当前没有生产环境 DAU 和请求频率数据，费用明细容量按日活用户比例和日活用户请求量进行场景估算；费用明细和消费账单按年度新增量估算，预算配置按当前有效对象数量估算。以下请求量是容量规划假设，不是线上实测或行业基准；试点后应使用实际 DAU 和请求分布校准。

| 对象                   | 设计容量   | 估算依据                                                                                                                                                                                                                      |
| ---------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 费用明细（CostRecord） | 10 亿条/年 | 基准场景：100,000 用户 × 30% DAU × 每名日活用户每天 30 次请求 × 365 天 = 3\.285 亿条/年；压力场景：100,000 × 50% DAU × 每名日活用户每天 50 次请求 × 365 天 = 9\.125 亿条/年，按 10 亿条/年规划。请求量按用户所有 API Key 合计 |
| 消费账单（Bill）       | 65 万条/年 | 10,000 个部门范围 ×（每年 12 个月度周期 \+ 最多 53 个周度周期）；同一周期类型、周期起止和部门范围只保留一条账单记录，重新生成时更新该记录                                                                                     |
| 部门预算               | 10,000 条  | 每个部门最多配置一条当前有效预算，含总部预算                                                                                                                                                                                  |
| 项目预算               | 10,000 条  | 每个项目最多配置一条当前有效预算                                                                                                                                                                                              |
| 用户预算               | 100,000 条 | 每个用户最多配置一条当前有效预算                                                                                                                                                                                              |

费用明细和消费账单永久保留，因此年度容量表示每年新增量，不代表全生命周期存量上限。存储、索引和归档设计须按累计留存量规划；账单容量按所有部门范围均生成月度及周度账单的上限估算，实际新增量取决于启用的账单范围和生成周期。

### 7\.5 数据精度

- 费用金额统一使用 decimal 类型，精度保留到小数点后 6 位

- 页面展示时保留 2 位小数

- 汇总计算使用 decimal 高精度运算，避免浮点数误差累积

- 金额为网关侧估算值：按请求时生效的单价快照与用量计算，厂商的阶梯价、折扣、缓存命中、多模态计费等差异不逐笔还原，因此金额可能与厂商账单存在差异

- 估算差异仅用于内部成本归因、分摊参考与预算预警，不回溯修改已发生请求的费用；需要核对的场景通过周期级差异校准处理，不进行逐笔对账

### 7\.6 国际化

- 所有页面文本、提示信息、错误信息支持中文/英文双语

- 金额展示跟随币种配置展示对应币种符号（¥ / $）

- 数字格式跟随语言环境（千分位分隔符等）

- 预算状态枚举内部使用英文（NORMAL/WARNING 等），展示层按语言翻译
