## 1\. 模块概述

### 1\.1 业务目标

建立企业 AI 模型资源的统一接入与治理体系，解决：

> **企业有哪些模型可以给员工使用，以及这些模型是否值得信任。**

模型接入是 AI 安全网关的核心资源模块。所有下游模块——智能路由、安全策略、成本计量、审计追溯——都依赖本模块提供准确的模型元数据（能力、价格、安全等级、可用状态）。

### 1\.2 对象架构

模型接入只管理“供应商实例 \+ 物理模型”两类业务对象。原供应商定义与 Endpoint 实例合并为一个供应商接入对象：供应商目录模板是系统内部规格，具体名称、API 接口和认证等配置保存在管理员创建的供应商实例中。一个供应商实例可承载多个物理模型；每个物理模型独立获得一个全局唯一的模型名称，直接提供给用户调用、授权和计费。多个物理模型之间不再聚合为额外对象。

| 对象           | 定位                                                                                               | 谁关心       |
| -------------- | -------------------------------------------------------------------------------------------------- | ------------ |
| 供应商实例     | 一份可复用的上游模型服务配置，含模板、API 接口、认证信息、安全等级和备注                           | 管理员       |
| 物理模型       | 某供应商实例提供的具体模型，保存模型名称、上游模型标识、支持的调用接口、能力、价格、授权和准入状态 | 用户与管理员 |
| 供应商模板目录 | 系统内维护的供应商规格、默认地址、认证字段和调用接口建议，不提供管理界面                           | 系统         |

对象关系：`供应商实例 1:N 物理模型`。每个模型名称只对应一个物理模型，数据面按该物理模型直接访问对应供应商实例；不创建模型聚合对象或物理模型挂载关系。供应商实例即数据面实际请求使用的上游配置，不再创建或引用独立 Endpoint 对象。

典型场景：管理员分别创建 OpenAI、Azure AI 和火山引擎供应商实例，将各自的 GPT\-4o 物理模型完成准入检测并上架，并分别设置模型名称（如 `gpt-4o-openai-prod`、`gpt-4o-azure-prod`、`gpt-4o-volcengine-prod`）。用户按需直接选择其中一个名称；每个名称只对应一个物理模型和供应商实例。

### 1\.3 接入流程

```Plaintext
① 打开「模型接入 > 供应商」并创建供应商实例
      │
      ├── 选择系统内置供应商模板（例如 DeepSeek、Azure AI、Google Vertex AI）
      ├── 或选择「OpenAI兼容」通用模板
      ▼
② 填写实例名称、API 接口、模板要求的认证信息、安全等级和备注并保存
      │  保存成功后自动进入接入引导
      ▼
③ 获取模型列表，选择模型并确认每个模型的模型名称（名称冲突时需修改）
      └── 无列表接口、列表为空或拉取失败时，在引导中手动填写供应商侧模型标识和模型名称
      ▼
④ 批量创建物理模型，保存唯一的模型名称；确认每个物理模型支持的调用接口
      ▼
⑤ 按每个物理模型配置的支持接口逐个发起指定模型请求测试
      ▼
⑥ 展示测试结果，管理员确认上架通过的模型
```

供应商表单只保存配置，不做独立接入点测试；保存成功后页面自动打开引导，并由服务端尝试获取模型列表。管理员选择模型后才进行指定模型请求测试。获取列表成功不代表模型可调用；测试未通过的模型保留为草稿，不能在引导中上架。管理员可暂时关闭引导；已创建的模型保留，可在模型管理中继续测试或上架。

## 2\. 功能需求

### 2\.1 供应商管理

#### 2\.1\.1 业务说明

供应商实例是管理员创建的一份模型服务接入配置，合并原供应商定义与 Endpoint 对象。供应商模板目录由系统内部维护，管理员在表单中选择模板，不管理模板定义。

模板目录要求：

- 页面选项展示模板名称；选择后自动填充默认 API 接口，并按上表动态展示认证字段。

- 研发按供应商与模型的适配情况预置支持的调用接口；模板和已知模型元数据可提供初始预选建议，但不能因模板或模型名称推断接口已可用。管理员可多选或取消勾选支持的调用接口，并单独填写自定义接口路径；两项配置分别保存在物理模型上并纳入接口测试。

- 接口预选按研发适配规格配置；可结合 `output_modalities` 中的 `embeddings`、`image` 及输入/输出中的 `audio`、`video` 提供建议。管理员保存的接口配置以物理模型为准；模型请求中客户端指定的接口优先透传，目标模型不支持时由网关兼容转换。

- 管理员可覆盖默认 API 接口，以支持区域站点、专属部署和中转地址。

- Azure 字段覆盖租户身份、应用身份、部署名和 API 版本；Google Vertex AI 字段覆盖项目、区域和服务账号凭证；DeepSeek 仅需 API Key。

- “通义千问”模板接入千问 AI 平台的按量计费 OpenAI 兼容接口，使用该平台创建的 API Key；不复用阿里云百炼模板的地址或密钥。已有通过百炼地址接入的通义千问实例保留原配置，管理员迁移至千问 AI 平台时需同时更换 API 地址和对应 API Key。千问 AI 平台 Token Plan 使用另一套专属接口和密钥，不属于本模板的接入规格，不得将其密钥配合本模板默认地址使用。MiniMax 默认使用国际站 OpenAI 兼容接口，可由管理员改成所属站点地址。

- “阿里云百炼”模板不预填 API 地址，也不单独收集地域或业务空间 ID。管理员从百炼控制台复制完整的 OpenAI 兼容 Base URL，并填写与该地址对应的百炼 API Key；已有实例保留原地址，编辑时可直接替换为新的完整地址。

- AWS 模板指 Amazon Bedrock Runtime 的 OpenAI 兼容接口。管理员直接填写完整 Base URL，不单独填写 Region；可选择 Bedrock API Key，或由网关运行环境的 AWS 凭证提供链进行 SigV4 签名。SigV4 所需地域优先从标准 Bedrock 地址解析；使用非标准地址时由网关运行环境提供地域配置。模型兼容性按 AWS 模型卡确认，创建供应商时不调用 `/models`。

- Ollama 地址必须从网关运行环境可达；官方本机示例为 `http://localhost:11434/v1`，部署在其他机器时不能直接照填 `localhost`。原生 Ollama 不校验 API Key。

- “OpenAI兼容”模板适用于任何提供 OpenAI 兼容接口的服务，包括企业自建服务和中转服务；API Key 可选，完整服务地址由管理员填写。

- 模板可声明余额查询适配规格。OpenRouter 使用 `GET /credits` 查询账户额度，需单独配置管理 API Key；可用余额按 `total_credits - total_usage` 计算，单位为 USD。未声明查询适配的模板仍可在供应商实例上配置自定义余额查询接口。

- 供应商模板规格由产品/研发维护并随版本发布；模板清单及规格更新不经过租户管理界面。

模板规格参考：[千问 AI 平台首次调用](https://platform.qianwenai.com/docs/developer-guides/getting-started/first-api-call)、[阿里云百炼 Base URL 总览](https://help.aliyun.com/zh/model-studio/base-url)、[MiniMax OpenAI SDK](https://platform.minimax.io/docs/api-reference/text-openai-api)、[Ollama OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility)、[AWS Bedrock Chat Completions](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html)、[OpenRouter 查询剩余额度](https://openrouter.ai/docs/api/api-reference/credits/get-credits)。

| model\_count                | int             | 系统统计       | 该供应商实例关联物理模型数                                                                           |
| created\_at / updated\_at   | datetime        | 系统生成       | 创建和更新时间                                                                                       |
| created\_by                 | string          | 系统生成       | 创建人                                                                                               |

#### 2\.1\.4 功能点

**F\-PROVIDER\-01 供应商实例列表**

- 左侧二级菜单名称为“供应商”，路径为模型接入下的供应商管理页面。

- 列表字段：名称、供应商模板、API 接口、安全等级、模型数量、备注、创建时间、操作。

- 支持按名称/API 接口/备注搜索和分页。

- 供应商名称以主链接显示，点击打开详情面板，展示模板、API 接口、安全等级、备注、创建时间、认证信息配置状态及关联物理模型；密钥和服务账号凭证只显示“已配置/未配置”，不得回显明文。

- 每个供应商实例的操作统一显示“获取模型”“编辑”“删除”；点击“获取模型”进入同一引导流程并实际尝试拉取列表，不按模板预先判断是否支持。

- 内置模板不作为可编辑的供应商记录展示；列表展示管理员创建的实际接入实例。

**F\-PROVIDER\-02 创建供应商实例**

- 表单依次填写：供应商名称、供应商模板、API 接口、模板认证信息、安全等级、备注。

- 名称必填且全局唯一；API 接口必填并校验合法 URL。

- 列表接口适配与模板认证流程由系统按模板规格实现；物理模型运行时以其支持接口配置为准。

- 有固定默认 API 接口的模板自动填入；Azure AI、AWS Bedrock、阿里云百炼、网宿 AI、腾讯混元、Ollama 和 OpenAI兼容由管理员填写完整地址。

- 按模板展示认证字段并执行必填校验；密钥类字段保存后不回显明文。

- AWS Bedrock 切换认证方式时只显示对应字段：API Key 模式必须填写 Bedrock API Key；IAM 凭证模式要求网关运行环境具备可用的 AWS 凭证，由服务端执行 SigV4 签名。切换模板或认证方式时不沿用已隐藏的密钥。

- 表单保存本身只校验配置，不进行独立连接测试。创建成功后自动打开接入引导并尝试拉取候选模型；获取失败或列表为空时提示原因，同时保留手动登记模型的入口。编辑供应商只保存配置，不强制重启引导。

**F\-PROVIDER\-03 编辑供应商实例**

- 可修改名称、模板、API 接口、认证信息、安全等级和备注。

- 已配置的密钥/多行凭证用已配置占位提示；留空表示保持原值，填入新值表示更新。

- 更换模板后重置 API 默认值并按新模板字段重新展示认证信息；提醒管理员确认后保存。

- 名称唯一性和 API URL 格式校验规则与创建一致。

**F\-PROVIDER\-04 删除供应商实例**

- 删除前二次确认，明确该供应商关联物理模型数。

- 确认后级联删除该供应商下的物理模型及其权限、价格和准入检测记录。

- 系统模板目录不通过该页面增删改，不参与此删除操作。

**F\-PROVIDER\-05 使用统计**

- 列表展示每个供应商实例关联的物理模型数量。

- 费用、调用量等统计由成本与审计模块按供应商实例 ID 归集。

- 本页面不提供独立的连接测试。

**F\-PROVIDER\-06 供应商余额查询与预警**

- 供应商模板可选声明余额查询适配规格，包括请求方法/路径、认证字段、余额单位及响应字段映射。管理员可为任意供应商实例选择不查询、模板接口或自定义接口；未声明模板适配时仍可使用自定义接口。

- 自定义接口支持 GET / POST、无需认证、Bearer Token 或自定义请求头认证；可将响应中的单一可用余额字段作为结果，或按“总额减去已用金额”计算。管理员配置余额单位和 JSON 字段路径，POST 可选填写 JSON 请求体。接口地址须为有效 HTTP\(S\) 地址，字段路径、认证信息及请求体在保存时校验。

- 自定义接口认证密钥加密保存，编辑时不回显，留空表示保留已保存密钥。自定义查询配置与模型调用认证配置分开维护；浏览器不得直接向供应商发送余额请求，服务端应按已配置接口发起请求。

- P0 提供 OpenRouter 余额查询适配：服务端使用独立配置的管理 API Key 请求 `GET /api/v1/credits`，读取 `data.total_credits` 与 `data.total_usage`，计算可用余额 `total_credits - total_usage`，单位为 USD。模型调用 API Key 与管理 API Key 分开保存，均加密且编辑时不回显。

- 供应商列表显示最近成功查询到的可用余额、单位、预警状态和更新时间；详情面板提供“查询余额”操作及最近查询结果。查询仅由服务端发起，浏览器不得直接访问供应商余额 API。

- 支持管理员手动查询；系统每 30 分钟对已启用余额查询的供应商执行一次定期查询。供应商限流或连续失败时采用退避策略；查询失败保留最近一次成功余额，并显示最近失败状态和重试操作。

- 选择模板或自定义查询方式后可配置预警阈值、接收人和通知渠道。开启预警后阈值必填且必须大于 0，单位分别使用模板适配器单位或自定义配置单位；自定义接口的余额单位默认 CNY，可编辑。新建时默认选择当前管理员和站内信；管理员可选择一个或多个启用用户，以及站内信、邮件渠道。开启预警时至少选择一位接收人和一种渠道；选择邮件时，所有接收人须配置有效邮箱。

- 通知渠道按配置分别投递；站内信进入接收人的消息中心，邮件发送至用户资料中的邮箱。通知发送失败需记录状态并支持重试，不重复投递已成功的渠道。

- 同一供应商余额持续低于阈值时不重复发送；余额恢复至阈值以上后恢复监控，下一次再次跌破时重新告警。配置阈值不影响模型请求路由和调用；余额查询失败也不自动禁用供应商或模型。

- 查询接口超时、认证失败、权限不足、响应结构变化及余额值无效时分别展示可采取的处理建议，不覆盖最后一次成功值；手动查询和定时任务均保留查询状态和时间。

**F\-PROVIDER\-07 模型接入引导**

- 新建供应商保存后自动打开“获取并选择模型→模型测试→确认上架→完成”的页面内引导，并使用完整 API 接口和认证信息尝试获取模型列表；已有供应商可从列表操作重新进入。所有模板均显示“获取模型”，不能仅凭模板或“企业自建”身份预判实际实例是否支持列表查询。

- 服务端优先使用已知的列表适配方式；OpenAI 兼容实例可尝试其 `/models` 接口。是否取得候选模型，以该实例的实际响应为准。P0 获取策略如下：

| 模板                                               | 优先获取方式                                                               | 处理要点                                                                                       |
| -------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| OpenAI、DeepSeek、Anthropic、Google AI、OpenRouter | 各自官方 Models/List Models API                                            | 按上游文档处理认证、分页和返回格式                                                             |
| 阿里云百炼                                         | 百炼独立 `GET /api/v1/models`，由所填完整 API 地址的主机与地域构造列表路径 | 不把 OpenAI 兼容 `/models` 当作百炼的列表接口                                                  |
| Google Vertex AI                                   | Vertex AI Publisher Models 列表接口                                        | 按项目、区域、服务账号权限获取候选模型；目录不代表全部已获调用权限                             |

| Ollama                                             | 原生 `GET /api/tags`；能力可进一步查询模型详情                             | 只返回该实例可访问的 Ollama 服务已安装模型                                                     |

- 选择模型步骤展示供应商侧模型名称、供应商侧模型 ID、模型名称、能力标签、输入/输出模态、上下文窗口、最大输出和“可添加/已添加”状态。模型名称默认沿用供应商侧模型 ID；若模型名称已被其他物理模型使用，要求管理员填写一个全局唯一名称后才能添加，并提示“该模型名称已被其他模型使用，请修改后添加”。四类元信息按字段优先使用研发适配预置，其次使用供应商模型列表返回值；均无数据时留空，不通过模型 ID 前缀推断。手动输入供应商侧模型标识的表单始终可展开；列表为空、失败或不支持时直接展示，不中断引导。

- 同一供应商实例下按供应商侧模型 ID 去重，已添加模型保留现有配置并禁选。弹窗默认全选所有可添加模型，管理员可取消勾选或重新全选；再次获取时只默认选中尚未添加的模型。

- 每个新增物理模型按研发适配规格预置支持的“调用接口”。管理员可下拉多选、取消勾选，并可单独输入自定义接口路径；填写路径不改变调用接口的勾选状态。两项配置分别保存在物理模型，不写入供应商实例。自定义接口路径由系统适配器处理，并能通过指定模型请求测试。

- 接着展示本次新增模型及其模型名称，管理员点击“开始模型测试”。服务端对每个供应商侧模型标识逐个测试管理员配置的支持接口，展示待测试、测试中、通过或未通过。所有启用接口均通过后模型进入待审核；存在失败项时保留草稿，展示失败原因，允许调整接口配置后重试；已通过接口无需重复测试。测试由管理员从引导明确发起，不在保存供应商时静默触发。

- 测试结果页只允许具有上架权限的管理员确认上架通过的模型；确认后进入 ACTIVE，用户可按该物理模型的模型名称直接调用。此确认等同现有“审核通过并上架”动作，保留操作日志。关闭引导不撤销已创建模型，未上架模型不参与调用，可在模型管理中继续处理。

- 获取期间展示加载状态；列表接口与模型调用接口可能采用不同路径或权限，获取成功只表示模型目录可读取，不证明某个模型可调用。列表调用失败时展示上游错误和可操作提示，并在同一页面保留手动填写；超时、鉴权失败、无权限、不支持列表接口和空列表分别提示。

- 服务端持有和使用认证信息，前端不直接请求上游，也不回传密钥。服务端分页拉取并限制单次返回量；批量添加按当前供应商 ID 和模型 ID 保证幂等，处理并发导入产生的重复项。

### 2\.2 供应商接入与准入边界

供应商实例保存数据面请求所需的上游 API 地址和认证配置。物理模型通过 `provider_id` 关联供应商实例，并独立保存支持的调用接口及模型元信息。供应商模板和目录元数据可提供模型接口、模态、上下文窗口、最大输出和标签的适配预置；运行时以物理模型已保存的配置为准。验证上游是否可用时必须指定该物理模型的供应商侧模型标识和待测接口，使用真实模型请求验证；部分服务只提供模型调用接口，不提供通用的接入点探测接口或可用模型列表接口。

- 创建/编辑供应商的保存请求：仅校验必填项和输入格式，不探测网络、TLS、认证或协议；新建保存成功后由接入引导单独调用相应模型列表接口。

- 获取模型：对每个供应商实例都发起获取尝试，读取候选元数据，不发送指定模型的推理请求；输入/输出模态、上下文窗口、最大输出和标签按字段优先使用研发适配预置，其次使用供应商列表返回值，均无数据时留空。列表不可用、失败或为空时提示并允许管理员手动登记供应商侧模型标识。

- 创建物理模型：可在引导中手动填写或从获取结果中选择批量添加，并为每个模型确认全局唯一的模型名称；P0 不要求所有供应商都提供模型列表。

- 物理模型准入检测：针对所选供应商实例、具体模型标识和物理模型配置的每个支持接口发起请求，可验证网络/TLS、认证和对应接口的响应格式。

- 模板专用认证流程由协议适配器实现；例如 Azure AI 与 Vertex AI 需使用对应云身份认证参数，不能假定所有服务都能以单一 Bearer API Key 探测。

- 准入检测失败只影响该物理模型进入审核/上架，不阻止管理员保存供应商配置。

### 2\.3 模型管理

#### 2\.3\.1 业务说明

物理模型由一个供应商实例提供，关联该实例 ID，并拥有独立的生命周期、准入检测和价格配置。

| updated\_at                      | datetime        | 系统生成           | 更新时间                                                                                                                                                    |
| created\_by                      | string          | 系统生成           | 创建人                                                                                                                                                      |

模型能力标签保存在 `tags`，常用标签包括“流式输出”“Tool Calling”“JSON 模式”和“图片输入”，也支持其他自定义标签。输入模态、输出模态、上下文窗口、最大输出和标签按字段分别取值：研发适配预置优先，缺少预置时使用供应商模型列表返回值；两者均未提供时保持为空。管理员可在模型配置中修正模态、上下文窗口、最大输出和标签。上下文窗口与最大输出在界面按 K Token 输入和展示，1K Token = 1000 Token；保存时换算为整数 Token 数。任一字段为空时显示“未获取数据”。输入和输出模态分别保存在 `input_modalities` 和 `output_modalities`；不再保存单独的模型 `type` 字段，模型能力及调用协议信息以模态、支持的调用接口和标签表达。准入及健康检查仅在模型包含“流式输出”标签时执行流式响应检测。

`model_id_at_gateway` 在当前租户内全局唯一，且只映射到一个物理模型；同一供应商侧模型标识接入不同供应商实例时，必须配置不同的模型名称。模型名称在模型处于 ACTIVE 时不可修改，以免影响调用方配置；修改草稿或已下架模型的模型名称前，管理员需确认并通知相关调用方。

调用接口标识包括 `CHAT_COMPLETIONS`（Chat Completions）、`RESPONSES`（Responses）、`MESSAGES`（Messages）、`GENERATE_CONTENT`（Generate Content）、`CONVERSE`（Converse）、`EMBEDDINGS`（Embeddings）、`IMAGE_GENERATIONS`（Image Generations）、`AUDIO`、`VIDEO`。研发根据供应商和模型适配情况预置可用接口；管理员可通过下拉多选或取消勾选标准调用接口，并在独立输入框中填写自定义上游路径。填写或清空路径不改变标准调用接口的勾选状态。自定义接口只要求配置路径，接口标识和协议处理由系统适配器完成。请求进入网关后优先透传客户端指定的接口；若目标模型未启用该接口，则由协议适配器根据已注册的兼容转换规则，选择该物理模型已启用且可承接转换请求的上游接口。不存在兼容路径时返回明确错误。接口路径、请求体和响应解析由对应适配器处理。

#### 2\.3\.3 模型生命周期

```Plaintext
DRAFT（草稿）
  │
  ├─ 发起准入检测 ──→ TESTING（检测中）
  │                      │
  │                      ├─ 检测未通过 ──→ DRAFT（保留失败记录，可重试）
  │                      └─ 所有启用接口检测通过 ──→ PENDING_REVIEW（待审核，含检测结果）
  │                                          │
  │                                          ├─ 审核通过 ──→ ACTIVE（已上架）
  │                                          │                  │
  │                                          │                  ├─ 暂停 ──→ SUSPENDED（已暂停）
  │                                          │                  │              │
  │                                          │                  │              ├─ 恢复 ──→ ACTIVE
  │                                          │                  │              └─ 下架 ──→ RETIRED
  │                                          │                  │
  │                                          │                  └─ 下架 ──→ RETIRED（已下架）
  │                                          │
  │                                          └─ 审核拒绝 ──→ DRAFT
```

| 状态            | 说明                                 |
| --------------- | ------------------------------------ |
| DRAFT           | 模型已创建但未通过准入流程           |
| TESTING         | 正在执行准入检测                     |
| PENDING\_REVIEW | 所有已启用接口检测完成，待管理员审核 |
| ACTIVE          | 已上架，可通过模型名称直接调用       |
| SUSPENDED       | 临时暂停，不可调用                   |
| RETIRED         | 已下架                               |

#### 2\.3\.4 功能点

**F\-MODEL\-01 模型列表**

- 列表上方以横向标签显示全部模型和供应商实例及对应数量；选择标签后筛选模型列表，默认选中“全部模型”

- 列表字段：模型名称、供应商侧标识、类型、供应商实例、安全等级、生命周期状态、健康状态、创建时间

- ACTIVE 和 SUSPENDED 模型的操作区提供“健康检查”按钮；列表和详情展示健康状态，鼠标悬停可查看最近检查时间

- 支持按模型名称、供应商侧标识搜索

- 支持按状态筛选

- 支持按输入模态、输出模态筛选

- 支持分页，默认每页 20 条

**F\-MODEL\-02 创建模型**

- 除模型管理中的手动创建外，供应商接入引导可从列表结果勾选或手动填写后批量添加；新增记录先进入 DRAFT，在同一引导中继续测试、确认上架。

- 表单字段：

  - 所属供应商（必填，下拉选择供应商实例名称）

  - 模型名称 model\_id\_at\_gateway（必填，全局唯一；与其他物理模型冲突时需修改）

  - 供应商侧模型标识 model\_id\_at\_provider（必填，同一供应商实例下唯一）

  - 支持的调用接口（必填，多选；按研发适配情况预置，管理员可取消勾选）；自定义接口路径单独输入，不联动多选结果

  - 输入模态、输出模态、上下文窗口、最大输出和标签：按字段优先使用研发适配预置，其次使用供应商模型列表返回值；均无数据时留空。上下文窗口与最大输出均可编辑，界面以 K Token 为单位；任一字段为空时显示“未获取数据”。输入模态、输出模态均支持多选，标签支持选择或新增。

  - 健康检查设置：自动检查开关及检查周期（1 / 6 / 12 / 24 小时，默认关闭、周期默认 6 小时）

  - 描述（选填）

- 系统按供应商和模型的适配情况预置支持的调用接口，管理员可多选、取消勾选，并可独立配置自定义接口路径；预置不代表接口已通过该模型测试

- 模型名称默认预填供应商侧模型标识；如全局冲突，要求管理员填写其他模型名称后方可创建

- 创建后状态为 DRAFT

**F\-MODEL\-03 编辑模型**

- DRAFT、RETIRED 状态可编辑模型名称、支持的调用接口和自定义接口路径；模型名称必须保持全局唯一，修改时提示影响调用方并记录日志，接口配置修改后既有测试结果失效，须重新准入。SUSPENDED 可编辑其他字段，但模型名称和接口配置保持锁定；如需更换，先下架进入 RETIRED 后修改并重新准入

- ACTIVE 状态不可修改：供应商实例、模型名称、供应商侧标识、支持的调用接口和自定义接口路径

- ACTIVE 状态的其他表单字段可编辑，包括支持的输入/输出模态、标签、描述、健康检查设置和价格配置

- TESTING 和 PENDING\_REVIEW 状态不可编辑

**F\-MODEL\-04 模型状态流转操作**

- 发起检测：DRAFT → TESTING

- 所有已启用标准接口及已配置的自定义路径检测通过：TESTING → PENDING\_REVIEW

- 任一待测接口检测未通过：TESTING → DRAFT，记录失败原因并允许重试

- 审核通过：PENDING\_REVIEW → ACTIVE

- 审核拒绝：PENDING\_REVIEW → DRAFT，需填写拒绝原因

- 暂停：ACTIVE → SUSPENDED，需填写暂停原因

- 恢复：SUSPENDED → ACTIVE

- 下架：ACTIVE / SUSPENDED → RETIRED

- 重新启用：RETIRED → DRAFT（需重新走准入流程）

**F\-MODEL\-05 删除模型**

- 删除模型时同步清理该模型的权限配置、价格配置、准入检测记录和健康检查记录

- 仅允许在模型非 ACTIVE 状态时删除

- 删除操作需二次确认

**F\-MODEL\-06 查看模型详情**

- 详情页展示：

  - 基本信息：供应商实例、API 地址、安全等级、模型名称、供应商侧标识、支持的调用接口、输入模态、输出模态、标签、状态

  - 健康状态、自动检查开关和检查周期

  - 模型权限配置（见 2\.6）

  - 准入检测记录和结果（见 2\.5）

  - 健康检查记录和结果（见 2\.5）

  - 价格配置（见 2\.7）

### 2\.5 模型准入检测

#### 2\.5\.1 业务说明

准入检测针对具体物理模型执行，使用其供应商实例配置、供应商侧模型标识和该模型已启用的调用接口发起请求，检查模型服务连通性、认证和请求/响应兼容性。可靠性检测归入后续模型质量检测功能，不属于本模块准入检测或健康检查。服务方通常不提供与模型无关的接入点测试，因此不进行脱离具体模型的供应商实例探测。

健康检查复用本节定义的准入检测项、执行方式和判定标准。准入检测用于新模型上架前验证，结果参与生命周期审核；健康检查用于已配置模型运行期间的状态监控，结果只更新健康状态和检查记录，不改变模型生命周期状态。

| 检测类型     | 目的                       |
| ------------ | -------------------------- |
| 连通性检测   | 确认模型服务可达、认证有效 |
| 协议能力检测 | 验证模型支持的协议特性     |

准入检测、健康检查及模型质量检测产生的上游调用费用归属系统内置用户 `system`，并计入总部成本。`triggered_by` 仅记录发起检测的管理员，不作为费用归属人。

#### 2\.5\.2 数据模型

| 字段              | 类型            | 必填     | 说明                                                                               |
| ----------------- | --------------- | -------- | ---------------------------------------------------------------------------------- |
| id                | string \(UUID\) | 系统生成 | 检测任务唯一标识                                                                   |
| model\_id         | string          | 是       | 物理模型 ID                                                                        |
| purpose           | enum            | 系统生成 | ADMISSION / HEALTH；区分准入检测与健康检查                                         |
| trigger\_type     | enum            | 系统生成 | MANUAL / AUTO；准入检测为 MANUAL                                                   |
| invocation\_api   | string          | 是       | 本次实际测试的物理模型调用接口（包括自定义接口标识），便于追溯接口变更前的历史结果 |
| type              | enum            | 是       | CONNECTIVITY / PROTOCOL / STREAMING                                                |
| status            | enum            | 系统维护 | PENDING / RUNNING / PASSED / FAILED / ERROR                                        |
| result            | json            | 系统生成 | 检测结果详情                                                                       |
| started\_at       | datetime        | 系统维护 | 开始时间                                                                           |
| completed\_at     | datetime        | 系统维护 | 完成时间                                                                           |
| triggered\_by     | string          | 系统生成 | 触发人                                                                             |
| billing\_user\_id | string          | 系统生成 | 固定关联系统内置用户 `system`；对应检测费用计入总部成本                            |
| created\_at       | datetime        | 系统生成 | 创建时间                                                                           |

健康检查记录独立于准入记录保存，逐次记录模型、触发类型（MANUAL / AUTO）、调用接口、检测项、汇总结果、分项结果、执行起止时间、触发人和费用归属用户（固定为 `system`）；对应检测费用计入总部成本。模型字段 `health_status` 与 `health_checked_at` 始终反映最近一次完成的健康检查。

#### 2\.5\.3 检测项说明

**指定模型请求检测**

| 检测项       | 说明                                                                        | 判定标准                                                                                   |
| ------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 指定模型请求 | 使用物理模型已启用的调用接口、供应商 API 地址和登记的模型标识发送最小化请求 | 每个启用接口均返回有效模型响应；连接失败记录网络/TLS 错误                                  |
| 认证验证     | 在指定模型请求过程中验证模板要求的凭证                                      | 响应不是认证失败；按 Azure/Vertex 等协议模板完成对应认证                                   |
| 模型标识     | 验证请求实际指向登记的模型或部署                                            | 上游接受该模型/部署标识，记录未知模型或未部署错误                                          |
| 响应协议     | 验证每个已启用调用接口的适配器能否解析该模型的响应                          | `Chat Completions`、`Responses`、`Messages` 等按各自的响应结构分别校验；模板只提供适配线索 |

**协议能力检测**

| 检测项       | 说明          | 判定标准             |
| ------------ | ------------- | -------------------- |
| Streaming    | 流式输出支持  | SSE 事件正确返回     |
| Tool Calling | 函数调用支持  | 正确返回 tool\_calls |
| JSON Mode    | JSON 输出模式 | 返回合法 JSON        |

#### 2\.5\.4 功能点

**F\-ADMISSION\-01 发起准入检测**

- 在已登记供应商侧模型标识的物理模型详情页中操作；供应商配置页面不提供独立连通性测试

- 发起前校验物理模型至少配置一个支持接口；对每个已启用接口分别发起检测，不以供应商模板字段代替

- 选择检测类型（默认全部勾选）

- 发起后模型状态变为 TESTING

- 检测异步执行，页面展示实时进度

**F\-ADMISSION\-02 检测进度与结果展示**

- 实时展示各检测项的执行状态：等待中 / 执行中 / 通过 / 失败 / 错误

- 每个检测项展示：检测名称、状态、耗时、详细结果

- 全部检测完成后汇总：通过项数 / 总项数

- 检测失败的项展示失败原因和排查建议

**F\-ADMISSION\-03 检测记录**

- 展示该物理模型的历史检测记录列表

- 列表字段：检测时间、检测类型、结果（通过/失败）、触发人

- 点击可查看历史检测结果详情

**F\-ADMISSION\-04 检测完成后流转**

- 所有已启用调用接口及本次附加检测项均通过后模型流转为 PENDING\_REVIEW；存在失败项则保留为 DRAFT，展示原因并允许调整接口配置后重试

- 审核页面展示完整检测结果；管理员只能将所有已启用调用接口测试通过的模型审核上架

#### 2\.5\.5 模型健康检查

**F\-HEALTH\-01 手动健康检查**

- ACTIVE 和 SUSPENDED 模型可从列表操作区或详情页手动触发健康检查；检测项、进度和结果详情与准入检测一致，不含可靠性评估

- 健康检查完成后更新 `health_status` 和 `health_checked_at`，并保存独立的健康检查记录；全部检测项通过时为 HEALTHY，存在 FAIL 或 ERROR 时为 UNHEALTHY；每个模型仅保留最近 5 次记录

- 健康检查不修改模型生命周期状态、准入记录或准入时间；运行期间可显示 CHECKING

- 同一模型同一时间只允许一个准入或健康检查任务运行；重复触发时提示当前任务正在执行

**F\-HEALTH\-02 自动健康检查**

- 模型创建/编辑表单提供自动检查开关和周期设置，支持每 1 / 6 / 12 / 24 小时，默认关闭、默认周期 6 小时

- 自动检查仅对 ACTIVE 模型运行；到期后按与准入检测相同的检测项执行，SUSPENDED、RETIRED 等状态暂停自动调度

- 任务使用最小化检查请求，不携带企业真实数据；执行中不重复调度同一模型，任务完成后记录触发类型为 AUTO

- 列表和详情展示健康状态；悬停状态可查看最近检查时间，详情可查看历史健康检查结果

### 2\.7 价格配置

#### 2\.7\.1 业务说明

价格配置绑定物理模型，保存该企业用于内部核算的价格快照。产品出厂为每个内置模型配置计费模式、研发确认可映射的计费项及价格；企业可在此基础上调整单价和计价规则。系统不提供云端统一价格目录、手动同步或自动同步。供应商适配器将上游 usage 映射到研发为该模型配置的计量指标；原始 usage 保留用于审计，未上报或无法解析的值记录为未知，不得自动补成 0。

本功能用于帮助企业以统一口径衡量内部 AI 使用成本与效益，不作为企业与模型供应商对账或结算的依据。受供应商定价体系、折扣、地域、模型版本和价格更新时间差异影响，内部价格及费用统计可能与供应商账单不一致，平台不承诺与供应商账单一致。该说明须同时显示在模型价格配置和消费账单页面。

计量指标覆盖文本 Token、多模态内容、推理消耗和工具调用。只对配置了价格的指标计费；同一多模态方向选择 Token、次数或时长中的一种计价口径。同一实际 Token 用量只能落入一个计费分项：缓存读写、推理或多模态 Token 单独计价时，须从普通输入/输出 Token 计费量中扣除对应子项。多模态按次数或时长计价时，也须从普通输入/输出 Token 计费量中扣除该模态的 Token；因此只有适配器能提供互斥用量时，才能同时配置普通 Token 价格和多模态次数/时长价格。供应商只返回聚合 Token 且无法拆分时，仅按聚合 Token 计价，不叠加拆分指标。工具调用、搜索等次数与 Token 属于不同计量项，可按价格配置叠加；单独计价的搜索次数不再计入工具调用次数。

#### 2\.7\.2 数据模型

| 字段          | 类型            | 必填     | 说明                                                     |
| ------------- | --------------- | -------- | -------------------------------------------------------- |
| id            | string \(UUID\) | 系统生成 | 价格快照唯一标识                                         |
| model\_id     | string          | 是       | 物理模型 ID                                              |
| version       | int             | 系统生成 | 价格快照版本；每次保存新建版本                           |
| source\_type  | enum            | 是       | BUILT\_IN（产品内置） / ENTERPRISE\_CUSTOM（企业自定义） |
| metric\_rates | object\[\]      | 是       | 按计量指标配置的计价单位、计价模式和价格规则             |
| currency      | enum            | 是       | 币种（USD / CNY / EUR 等），同一快照统一币种             |
| created\_at   | datetime        | 系统生成 | 快照创建时间；作为新请求选择价格版本的生效时间           |
| created\_by   | string          | 系统生成 | 创建人                                                   |

每项 metric\_rates 包含 metric\_key、unit 和对应价格规则；每个价格快照统一配置 pricing\_mode，应用于其中所有计费项。系统为每个内置模型出厂配置默认计费模式、计费项及价格，首次创建物理模型时匹配并初始化该配置。管理员可调整已配置计费项的价格和规则，但不能自行新增或删除计费项；各模型可配置的 metric\_key 由供应商适配器和模型适配规格确定，研发完成 usage 字段映射后才能加入。当前 pricing\_mode 仅支持 FIXED（固定价格）和 TIME\_BASED（分时段价格）。Token 单价以每百万 Token 为计价单位；次数、秒数、帧数、工具调用和搜索次数按每个单位计价。

产品内置价格初始来源记为 BUILT\_IN。管理员修改价格后创建新的 ENTERPRISE\_CUSTOM 快照；已生成费用继续引用原快照。对于未匹配到内置计价配置的手动登记模型，管理员仅可为其已识别的计费项配置价格，不得添加尚无 usage 映射的指标。

##### 计费指标目录

| 指标键                                                   | 计量单位 | 说明                                                                         |
| -------------------------------------------------------- | -------- | ---------------------------------------------------------------------------- |
| input\_tokens                                            | Token    | 普通输入 Token；已拆分计价的缓存、多模态等 Token 不计入此可计费分量          |
| output\_tokens                                           | Token    | 普通输出 Token；已拆分计价的推理 Token 不计入此可计费分量                    |
| cached\_input\_tokens                                    | Token    | 缓存命中的输入 Token                                                         |
| cache\_write\_tokens                                     | Token    | 写入缓存的 Token                                                             |
| reasoning\_tokens                                        | Token    | 推理 Token                                                                   |
| image\_input\_tokens / image\_output\_tokens             | Token    | 输入/输出图像对应的 Token；上游提供可拆分 usage 时使用                       |
| image\_input\_count / image\_output\_count               | 次       | 输入/输出图像数量                                                            |
| audio\_input\_tokens / audio\_output\_tokens             | Token    | 输入/输出音频 Token                                                          |
| audio\_input\_seconds / audio\_output\_seconds           | 秒       | 输入/输出音频时长                                                            |
| audio\_input\_count / audio\_output\_count               | 次       | 输入/输出音频片段或文件数量                                                  |
| video\_input\_tokens / video\_output\_tokens             | Token    | 输入/输出视频对应的 Token                                                    |
| video\_input\_seconds / video\_output\_seconds           | 秒       | 输入/输出视频时长                                                            |
| video\_input\_count / video\_output\_count               | 次       | 输入/输出视频片段或文件数量                                                  |
| video\_input\_frame\_count / video\_output\_frame\_count | 帧       | 输入/输出视频帧数量                                                          |
| tool\_call\_count                                        | 次       | 工具调用次数；与模型输入/输出 Token 分开计量，单独计价的搜索调用不计入此分量 |
| search\_count                                            | 次       | 搜索调用次数；可由工具调用或上游 usage 映射                                  |
| request\_count                                           | 次       | 请求次数；仅当研发适配声明该模型可映射请求次数时纳入内置计费项               |

计量指标目录及各模型可用的指标由产品和研发维护，不向管理员开放任意新增或删除。供应商适配器记录原始字段及映射结果；某项指标确实未发生时记为 0，供应商未返回或无法确认时记为未知并标记计量不完整。普通输入/输出 Token、缓存、推理和多模态 Token 需按上游 usage 拆分为互斥计费分量；单独计价的搜索次数从工具调用次数中排除。total\_tokens 等汇总值用于统计，不作为独立计费指标。

##### 价格规则

| 模式        | 规则字段                                                         | 计算规则                                                                                                                                                                                                                              |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FIXED       | unit\_price、price\_unit                                         | 计量数量乘以单位价格；Token 以每百万 Token 计价，其余按每次、每秒或每帧计价                                                                                                                                                           |
| TIME\_BASED | time\_periods（id、name、is\_fallback、conditions、unit\_price） | 配置具名时段及其价格；每个时段可包含多个星期和开始/结束时间条件，命中任一条件即应用该时段价格；按系统统一时区和请求开始时间匹配。必须配置一个无条件的兜底时段，未命中其他时段时应用其价格；所有时间条件不得重叠，跨午夜时拆成两个条件 |

当前仅支持 FIXED 和 TIME\_BASED。阶梯定价及其他模式暂不支持配置、同步和计费；价格模式与规则结构保留扩展能力，未来可由后续版本定义并启用。

多模态指标可按 Token、次数或时长选择计量单位，图像按次数时使用图像数量，音频按时长时使用秒数，视频可按秒数或帧数。对于同一模态和方向，只能启用一种计费口径；供应商同时返回其他口径时保留用量但不叠加计费。

#### 2\.7\.3 功能点

**F\-PRICE\-01 价格配置**

- 在物理模型创建/编辑表单中配置；详情页展示当前价格和价格历史

- 每个内置模型默认使用产品内置的计费模式、已适配计费项和价格；管理员可查看来源并调整已有计费项的价格及计价规则，修改后标记为企业自定义并生成新快照

- 管理员不能任意添加或移除计费项；页面仅展示研发已确认并完成 usage 映射的指标。未支持的计量项不提供配置入口

- 价格说明：“价格用于企业内部衡量 AI 使用成本与效益，不作为供应商对账或结算依据。受供应商价格规则、折扣、地区、模型版本及更新时间影响，内部统计可能与供应商账单不同；平台不承诺两者一致。”

- 统一选择固定价格或分时段计价模式，应用于所有计费项；币种必填，默认 CNY。固定价格为每项配置一个单价；分时段价格先配置具名时段及时间条件，再为每项分别填写各时段和兜底时段的单价。其他计价模式暂不支持配置和计算，保留后续扩展能力

- 基础指标包括输入/输出 Token、缓存输入、缓存写入和推理 Token；多模态支持图像、音频、视频的 Token、次数或时长口径；工具调用支持工具调用次数和搜索次数

- 固定价格允许设为 0；分时段规则要求每个具名时段至少有一个有效条件、时段名称非空且不重复（“兜底时段”为保留名称）、所有时间条件无重叠，并且始终保留一个兜底时段。时区由系统统一配置

- 每个多模态方向只能选择一种计费口径；若普通输入/输出 Token 与多模态次数/时长同时计价，适配器必须能提供互斥的剩余 Token 用量，否则不允许保存冲突的价格组合。配置完成后展示预估单价及单位。价格精度按币种及计价单位保存，界面最多展示 2 位小数

- 产品出厂为每个内置模型预置计费模式、已适配计费项和价格；非内置模型中尚未识别映射的指标不显示计价入口

**F\-PRICE\-02 价格历史**

- 展示该物理模型的价格历史列表；首次保存价格时记录初始价格，后续每次价格变更都记录价格快照

- 列表字段：版本、价格来源、计量指标及单位、计价模式、价格规则摘要、币种、创建人、记录时间

- 当前价格高亮展示

**F\-PRICE\-03 修改价格**

- 修改价格时新增一条历史记录，保留旧价格快照

- 保存后立即用于新请求；已发生请求始终关联当时使用的价格快照，不支持预设未来日期生效的价格版本

- 时段定价是同一价格版本内按星期和本地时刻循环匹配的费率，不是未来生效日期

- 产品内置价格更新或企业修改产生新快照后，只影响新请求；历史费用继续引用原价格快照

## 4\. 业务规则

### 4\.1 模型可用性判断

员工请求使用某个模型时，在 `model` 字段提交模型名称，系统按以下条件依次判断：

| 序号 | 检查项                                                   | 不满足时                         |
| ---- | -------------------------------------------------------- | -------------------------------- |
| 1    | 模型名称存在且只映射到一个物理模型                       | 拒绝，提示“模型不存在”           |
| 2    | 对应物理模型处于 ACTIVE 状态                             | 拒绝，提示“模型暂不可用”         |
| 3    | 用户拥有该物理模型的使用权限                             | 拒绝，提示“无权限使用该模型”     |
| 4    | 请求格式及结构化能力可由该物理模型原生接口处理或兼容转换 | 拒绝，提示“请求与模型能力不兼容” |

### 4\.2 模型权限判断逻辑

```Plaintext
1. 检查用户是否被直接授权该物理模型 → 有则允许
2. 检查用户所属的用户组是否被授权该物理模型 → 有则允许
3. 检查用户所属的部门（含上级部门）是否被授权该物理模型 → 有则允许
4. 以上均无 → 拒绝
```

### 4\.3 直接调用与请求转发

数据面按模型名称直接解析到唯一物理模型，不构建跨供应商候选池：

1. **模型解析**：通过 `model_id_at_gateway` 精确查找一个物理模型；标识不存在或模型未上架时拒绝请求。

2. **请求校验**：检查用户权限、模型状态、请求格式和结构化能力；根据请求路径识别客户端指定的调用接口，并确认存在原生透传或兼容转换路径。无可用路径时返回明确错误。

3. **请求转发**：若目标模型支持客户端指定的接口，优先使用该接口透传；否则由协议适配器根据已注册的兼容转换规则，选择该物理模型已启用且可承接转换请求的上游接口。对应适配器负责请求路径、协议转换、响应解析及将响应还原为客户端所用接口格式；转发时将请求中的 `model` 替换为 `model_id_at_provider`，并使用对应供应商实例的 API 地址和认证信息。不存在兼容路径时返回明确错误。

4. **失败处理**：上游调用失败时返回该模型的失败结果，不自动切换到其他物理模型或供应商；调用方需要显式选择其他模型名称后重试。

### 4\.4 模型状态流转约束

| 当前状态        | 允许的操作                   | 目标状态        |
| --------------- | ---------------------------- | --------------- |
| DRAFT           | 发起检测                     | TESTING         |
| TESTING         | 所有已启用调用接口检测通过   | PENDING\_REVIEW |
| TESTING         | 任一已启用调用接口检测未通过 | DRAFT           |
| PENDING\_REVIEW | 审核通过                     | ACTIVE          |
| PENDING\_REVIEW | 审核拒绝                     | DRAFT           |
| ACTIVE          | 暂停                         | SUSPENDED       |
| ACTIVE          | 下架                         | RETIRED         |
| SUSPENDED       | 恢复                         | ACTIVE          |
| SUSPENDED       | 下架                         | RETIRED         |
| RETIRED         | 重新启用                     | DRAFT           |

### 4\.5 价格计费规则

- 费用按请求模型名称对应物理模型的价格计算

- 费用计算公式：费用 = 对每个已配置价格的计量指标分别应用其固定或分时段规则后求和；Token 按每百万 Token 单价折算，其余按配置单位计价

- 使用请求开始时最近一次保存的价格快照计费；分时段费率按系统统一时区及请求开始时刻匹配。账单保留价格快照 ID、计量值、命中的计价规则及分项金额，便于追溯

- 计量使用供应商 usage 经适配器归一化后的指标；分项指标和聚合输入/输出 Token 必须互斥，防止缓存、多模态和推理 Token 重复收费

- 如物理模型未配置价格，请求正常执行，费用记录为 0

- 已配置价格的指标未返回计量值时标记 USAGE\_INCOMPLETE，不把未知数量当作 0；有计量值但无对应价格时标记 UNPRICED\_METRIC，并保留已知分项费用。请求本身继续执行，费用记录需携带计费状态

- 物理模型价格配置支持设为 0（适用于企业自建模型等无 Token 费用的场景）

- 准入检测、健康检查和模型质量检测产生的上游调用费用统一归属系统内置用户 `system`，计入总部成本；检测发起人仅作为操作审计记录

- 币种以价格配置中的币种为准，报表展示时可按企业配置的统一展示币种折算

- 计费结果用于企业内部成本与效益衡量，不代表供应商实际账单，不承诺与供应商对账一致；消费账单页面须就近展示该说明

## 7\. 非功能需求

### 7\.1 性能

| 指标                        | 要求                                 |
| --------------------------- | ------------------------------------ |
| 模型名称解析响应时间        | \< 5ms（数据面关键路径，需内存缓存） |
| 模型权限检查响应时间        | \< 5ms（数据面关键路径，需内存缓存） |
| 供应商/模型管理页面响应时间 | \< 500ms                             |
| 准入检测任务启动            | \< 2s                                |
| 准入检测全流程完成          | \< 5min                              |
| 自动健康检查调度延迟        | 配置周期到期后 5 分钟内启动          |

### 7\.2 安全

- 供应商实例认证信息（API Key、OAuth Secret 等）加密存储，不可明文读取

- 认证信息在管理界面展示时脱敏（仅展示前缀和后 3 位）

- 所有管理操作（创建/编辑/删除/状态变更/权限变更/价格变更）记录操作日志

- 准入检测使用的测试请求不发送任何企业真实数据

- 健康检查沿用准入检测的最小化测试请求，不读取或发送企业真实数据

### 7\.3 数据

- 物理模型下架后数据保留，不物理删除，历史审计和费用记录中的模型信息不受影响

- 价格历史记录永久保留，用于历史费用追溯

- 准入检测记录保留最近 50 次

- 健康检查记录保留最近 5 次，自动和手动检查均记录触发类型、执行时间和分项结果

### 7\.4 容量

| 对象         | 设计容量 |
| ------------ | -------- |
| 供应商实例   | 500      |
| 物理模型     | 2,000    |
| 模型权限记录 | 100,000  |
| 价格配置记录 | 10,000   |

### 7\.5 国际化

- 所有页面文本、提示信息、错误信息支持中文/英文双语

- 模型名称、供应商名称等业务数据管理员以何种语言录入即以何种语言存储和展示

- 模型状态枚举内部使用英文（DRAFT、ACTIVE 等），展示层按语言翻译

- 价格币种符号跟随币种配置展示
