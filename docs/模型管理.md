### 业务说明

物理模型由一个供应商实例提供，关联该实例 ID，并拥有独立的生命周期、准入检测和价格配置。
模型管理页面采用左右双栏布局：左侧列出供应商实例，右侧展示物理模型。选中某个实例展示该实例下的模型，选中根节点展示全部模型。

### 数据模型

| 字段                  | 类型          | 必填     | 说明                                                                                                  |
| --------------------- | ------------- | -------- | ----------------------------------------------------------------------------------------------------- |
| id                    | string (UUID) | 是       | 系统生成的模型唯一标识                                                                                |
| provider_id           | string        | 是       | 所属供应商实例 ID                                                                                     |
| model_id_at_provider  | string        | 是       | 供应商侧模型标识（API 调用时使用的 model 参数值，如 gpt-4o、gpt-4o-2024-08-06），同一供应商实例下唯一 |
| type                  | enum          | 是       | LLM / EMBEDDING / IMAGE / AUDIO / VIDEO / MULTIMODAL                                                  |
| invocation_api        | enum          | 是       | 该物理模型最终调用的唯一接口，如 CHAT_COMPLETIONS、RESPONSES、MESSAGES；须通过指定模型测试            |
| context_window        | int           | 否       | 上下文窗口大小（Token 数）                                                                            |
| max_output_tokens     | int           | 否       | 最大输出 Token 数                                                                                     |
| supports_streaming    | boolean       | 否       | 是否支持流式输出                                                                                      |
| supports_tool_calling | boolean       | 否       | 是否支持 Tool Calling                                                                                 |
| supports_json_mode    | boolean       | 否       | 是否支持 JSON 输出模式                                                                                |
| supports_vision       | boolean       | 否       | 是否支持图片输入                                                                                      |
| status                | enum          | 系统维护 | DRAFT / TESTING / PENDING_REVIEW / ACTIVE / SUSPENDED / RETIRED                                       |
| suspend_reason        | string        | 否       | 暂停/下架原因                                                                                         |
| description           | string        | 否       | 模型描述                                                                                              |
| created_at            | datetime      | 系统生成 | 创建时间                                                                                              |
| updated_at            | datetime      | 系统生成 | 更新时间                                                                                              |
| created_by            | string        | 系统生成 | 创建人                                                                                                |

流式、Tool Calling、JSON 模式和视觉是模型调用参数对应的结构化能力字段，用于记录模型及其调用接口的支持情况。供应商模型列表返回的信息可用于填充这些字段；缺少上游信息时保持未知，由管理员核实维护。请求兼容判断和路由只依赖结构化请求参数及这些字段，不对用户自然语言做意图分析。
物理模型与逻辑模型通过逻辑模型挂载关系关联。一个物理模型可同时挂载到多个逻辑模型；是否参与某个逻辑模型的请求路由由物理模型当前状态决定。
调用接口枚举：CHAT_COMPLETIONS（Chat Completions）、RESPONSES（Responses）、MESSAGES（Messages）、GENERATE_CONTENT（Generate Content）、CONVERSE（Converse）、EMBEDDINGS（Embeddings）、IMAGE_GENERATIONS（Image Generations）、AUDIO、VIDEO、TEMPLATE_NATIVE（模板专用接口）。每个物理模型只选一种最终调用接口；同一供应商实例下的不同物理模型可以选不同接口。接口路径、请求体和响应解析由对应适配器根据物理模型配置决定。

### 模型生命周期

DRAFT（草稿）
│
├─ 发起准入检测 ──→ TESTING（检测中）
│ │
│ ├─ 检测未通过 ──→ DRAFT（保留失败记录，可重试）
│ └─ 调用接口检测通过 ──→ PENDING_REVIEW（待审核，含检测结果）
│ │
│ ├─ 审核通过 ──→ ACTIVE（已上架）
│ │ │
│ │ ├─ 暂停 ──→ SUSPENDED（已暂停）
│ │ │ │
│ │ │ ├─ 恢复 ──→ ACTIVE
│ │ │ └─ 下架 ──→ RETIRED
│ │ │
│ │ └─ 下架 ──→ RETIRED（已下架）
│ │
│ └─ 审核拒绝 ──→ DRAFT

| 状态           | 说明                               |
| -------------- | ---------------------------------- |
| DRAFT          | 模型已创建但未通过准入流程         |
| TESTING        | 正在执行准入检测                   |
| PENDING_REVIEW | 检测完成待管理员审核               |
| ACTIVE         | 已上架，可被逻辑模型引用并参与路由 |
| SUSPENDED      | 临时暂停，不参与路由               |
| RETIRED        | 已下架                             |

### 功能点

F-MODEL-01 模型列表

- 支持两种视图切换：
  - 供应商视图（默认）：左侧为供应商实例列表，选中节点过滤右侧模型列表
  - 逻辑模型视图：左侧为逻辑模型列表（含"未挂载"分组），选中逻辑模型展示其下挂载的物理模型，选中"未挂载"展示所有未关联逻辑模型的物理模型
- 右侧为模型列表
- 列表字段：供应商侧标识、类型、逻辑模型、状态、创建时间
- 支持按名称搜索
- 支持按状态筛选
- 支持按"是否已挂载逻辑模型"筛选
- 支持分页，默认每页 20 条
  F-MODEL-02 创建模型
- 除模型管理中的手动创建外，供应商接入引导可从列表结果勾选或手动填写后批量添加；新增记录先进入 DRAFT，在同一引导中继续测试、确认上架。
- 表单字段：
  - 所属供应商（必填，下拉选择供应商实例名称）
  - 供应商侧模型标识 model_id_at_provider（必填，同一供应商实例下唯一）
  - 模型类型（必填）
  - 调用接口（必填，单选，表示该模型最终调用的接口）
  - 能力信息（选填）：上下文窗口、最大输出、流式/Tool Calling/JSON/视觉支持
  - 描述（选填）
- 系统预置常见模型元数据和供应商模板用于预填调用接口，管理员可在测试前调整；预填不表示该接口已获上游支持
- 创建后状态为 DRAFT
- 创建时可选择挂载到一个或多个逻辑模型，挂载不受物理模型状态限制；可在逻辑模型详情页为每个挂载关系设置路由优先级
- 逻辑模型关联：先按 model_id_at_provider 与逻辑模型 name 去空格并忽略大小写精确匹配；未命中时识别明确的日期快照后缀（-YYYYMMDD、-YYYY-MM-DD），唯一匹配时默认选择并显示“版本匹配”。多候选时要求管理员选择目标或新建；完全未匹配时默认选择自动创建。不做通用前缀/子串匹配，mini、turbo、instruct 等变体保持独立。管理员可在每个模型行改选逻辑模型；点击“添加并继续”时才创建或挂载。模型管理页单独手动创建沿用相同的唯一匹配规则
- 接入引导完成后，管理员仍可在模型管理中将物理模型挂载到其他逻辑模型或调整挂载优先级
  F-MODEL-03 编辑模型
- DRAFT、RETIRED 状态可编辑调用接口；修改后既有测试结果失效，须重新准入。SUSPENDED 可编辑其他字段，但调用接口保持锁定；如需更换，先下架进入 RETIRED 后修改并重新准入
- ACTIVE 状态不可修改：供应商实例、供应商侧标识、模型类型、调用接口
- ACTIVE 状态的其他表单字段可编辑，包括逻辑模型挂载、能力信息、描述和价格配置
- TESTING 和 PENDING_REVIEW 状态不可编辑
  F-MODEL-04 模型状态流转操作
- 发起检测：DRAFT → TESTING
- 调用接口检测通过：TESTING → PENDING_REVIEW
- 调用接口检测未通过：TESTING → DRAFT，记录失败原因并允许重试
- 审核通过：PENDING_REVIEW → ACTIVE
- 审核拒绝：PENDING_REVIEW → DRAFT，需填写拒绝原因
- 暂停：ACTIVE → SUSPENDED，需填写暂停原因
- 恢复：SUSPENDED → ACTIVE
- 下架：ACTIVE / SUSPENDED → RETIRED
- 重新启用：RETIRED → DRAFT（需重新走准入流程）
  F-MODEL-05 删除模型
- 删除模型时同步清理其与逻辑模型的关联、价格配置和检测记录
- 仅允许在模型非 ACTIVE 状态时删除
- 删除操作需二次确认
  F-MODEL-06 查看模型详情
- 详情页展示：
  - 基本信息：供应商实例、API 地址、安全等级、供应商侧标识、类型、调用接口、能力信息、状态
  - 所属逻辑模型列表（如有，展示每个逻辑模型内的路由优先级）
  - 准入检测记录和结果（见 模型准入检测）
  - 价格配置（见 模型价格配置）

### 模型准入检测

F-ADMISSION-01 发起准入检测

- 在已登记供应商侧模型标识的物理模型详情页中操作；供应商配置页面不提供独立连通性测试
- 发起前校验物理模型已配置调用接口；只测试这一种最终接口，不以供应商模板字段代替
- 选择检测类型（默认全部勾选）
- 发起后模型状态变为 TESTING
- 检测异步执行，页面展示实时进度
  F-ADMISSION-02 检测进度与结果展示
- 实时展示各检测项的执行状态：等待中 / 执行中 / 通过 / 失败 / 错误
- 每个检测项展示：检测名称、状态、耗时、详细结果
- 可靠性检测额外展示：成功率、TTFT（P50/P95）、延迟（P50/P95）
- 全部检测完成后汇总：通过项数 / 总项数
- 检测失败的项展示失败原因和排查建议
  F-ADMISSION-03 检测记录
- 展示该物理模型的历史检测记录列表
- 列表字段：检测时间、检测类型、结果（通过/失败）、触发人
- 点击可查看历史检测结果详情
  F-ADMISSION-04 检测完成后流转
- 调用接口及本次附加检测项均通过后模型流转为 PENDING_REVIEW；存在失败项则保留为 DRAFT，展示原因并允许调整配置后重试
- 审核页面展示完整检测结果；管理员只能将调用接口测试通过的模型审核上架

### 模型价格配置

F-PRICE-01 价格配置

- 在物理模型创建/编辑表单中配置；详情页展示当前价格和价格历史
- 表单字段：
  - Input Token 单价（必填，每百万 Token，允许为 0）
  - Output Token 单价（必填，每百万 Token，允许为 0）
  - 缓存 Input Token 单价（选填，每百万 Token）
  - 币种（必填，默认 CNY）
- 系统预置常见模型的参考价格，创建模型时如选择了模板，自动带入参考价格
- 价格以每百万 Token 为单位展示和输入，精度保留到小数点后 4 位
  F-PRICE-02 价格历史
- 展示该物理模型的价格历史列表；首次保存价格时记录初始价格，后续每次价格变更都记录价格快照
- 列表字段：Input 单价、Output 单价、缓存 Input 单价、币种、创建人、记录时间
- 当前价格高亮展示
  F-PRICE-03 修改价格
- 修改价格时新增一条历史记录，保留旧价格快照
- 不维护价格生效/失效日期，不支持预设未来价格调整
