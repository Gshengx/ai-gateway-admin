### 1 业务说明

供应商实例是管理员创建的一份模型服务接入配置，合并原供应商定义与 Endpoint 对象。供应商模板目录由系统内部维护，管理员在表单中选择模板，不管理模板定义。

模板目录要求：

- 页面选项展示模板名称；选择后自动填充默认 API 接口，并按上表动态展示认证字段。
- 模板可结合已知模型元数据，从 Chat Completions、Responses、Messages 等接口中建议一个初始值；建议值只用于自动识别和表单预填，最终调用接口保存在物理模型上。不能因模板或模型名称推断接口已可用。
- P0 的建议规则：Embedding、图像、音频、视频模型先按模型类型建议对应接口；Anthropic 建议 Messages，Google AI / Vertex AI 建议 Generate Content，腾讯混元建议模板专用接口，其余模板先建议 Chat Completions。Responses、Converse 等由管理员根据所接模型和 API 地址选择；后续可信模型元数据可细化建议，但不能覆盖物理模型已保存的配置。
- 管理员可覆盖默认 API 接口，以支持区域站点、专属部署和中转地址。
- Azure 字段覆盖租户身份、应用身份、部署名和 API 版本；Google Vertex AI 字段覆盖项目、区域和服务账号凭证；DeepSeek 仅需 API Key。
- “通义千问”模板接入千问 AI 平台的按量计费 OpenAI 兼容接口，使用该平台创建的 API Key；不复用阿里云百炼模板的地址或密钥。已有通过百炼地址接入的通义千问实例保留原配置，管理员迁移至千问 AI 平台时需同时更换 API 地址和对应 API Key。千问 AI 平台 Token Plan 使用另一套专属接口和密钥，不属于本模板的接入规格，不得将其密钥配合本模板默认地址使用。MiniMax 默认使用国际站 OpenAI 兼容接口，可由管理员改成所属站点地址。
- “阿里云百炼”模板不预填 API 地址，也不单独收集地域或业务空间 ID。管理员从百炼控制台复制完整的 OpenAI 兼容 Base URL，并填写与该地址对应的百炼 API Key；已有实例保留原地址，编辑时可直接替换为新的完整地址。
- AWS 模板指 Amazon Bedrock Runtime 的 OpenAI 兼容接口。管理员直接填写完整 Base URL，不单独填写 Region；可选择 Bedrock API Key，或由网关运行环境的 AWS 凭证提供链进行 SigV4 签名。SigV4 所需地域优先从标准 Bedrock 地址解析；使用非标准地址时由网关运行环境提供地域配置。模型兼容性按 AWS 模型卡确认，创建供应商时不调用 /models。
- Ollama 地址必须从网关运行环境可达；官方本机示例为 http://localhost:11434/v1，部署在其他机器时不能直接照填 localhost。原生 Ollama 不校验 API Key。
- “OpenAI兼容”模板适用于任何提供 OpenAI 兼容接口的服务，包括企业自建服务和中转服务；API Key 可选，完整服务地址由管理员填写。
- 供应商模板规格由产品/研发维护并随版本发布；模板清单及规格更新不经过租户管理界面。
  模板规格参考：千问 AI 平台首次调用、阿里云百炼 Base URL 总览、MiniMax OpenAI SDK、Ollama OpenAI 兼容接口、AWS Bedrock Chat Completions。

### 4 功能点

F-PROVIDER-01 供应商实例列表

- 左侧二级菜单名称为“供应商”，路径为模型接入下的供应商管理页面。
- 列表字段：名称、供应商模板、API 接口、安全等级、模型数量、备注、创建时间、操作。
- 支持按名称/API 接口/备注搜索和分页。
- 供应商名称以主链接显示，点击打开详情面板，展示模板、API 接口、安全等级、备注、创建时间、认证信息配置状态及关联物理模型；密钥和服务账号凭证只显示“已配置/未配置”，不得回显明文。
- 每个供应商实例的操作统一显示“获取模型”“编辑”“删除”；点击“获取模型”进入同一引导流程并实际尝试拉取列表，不按模板预先判断是否支持。
- 内置模板不作为可编辑的供应商记录展示；列表展示管理员创建的实际接入实例。
  F-PROVIDER-02 创建供应商实例
- 表单依次填写：供应商名称、供应商模板、API 接口、模板认证信息、安全等级、备注。
- 名称必填且全局唯一；API 接口必填并校验合法 URL。
- 列表接口适配与模板认证流程由系统按模板规格实现；物理模型运行时调用接口以其单选配置为准。
- 有固定默认 API 接口的模板自动填入；Azure AI、AWS Bedrock、阿里云百炼、网宿 AI、腾讯混元、Ollama 和 OpenAI兼容由管理员填写完整地址。
- 按模板展示认证字段并执行必填校验；密钥类字段保存后不回显明文。
- AWS Bedrock 切换认证方式时只显示对应字段：API Key 模式必须填写 Bedrock API Key；IAM 凭证模式要求网关运行环境具备可用的 AWS 凭证，由服务端执行 SigV4 签名。切换模板或认证方式时不沿用已隐藏的密钥。
- 表单保存本身只校验配置，不进行独立连接测试。创建成功后自动打开接入引导并尝试拉取候选模型；获取失败或列表为空时提示原因，同时保留手动填写模型标识。编辑供应商只保存配置，不强制重启引导。
  F-PROVIDER-03 编辑供应商实例
- 可修改名称、模板、API 接口、认证信息、安全等级和备注。
- 已配置的密钥/多行凭证用已配置占位提示；留空表示保持原值，填入新值表示更新。
- 更换模板后重置 API 默认值并按新模板字段重新展示认证信息；提醒管理员确认后保存。
- 名称唯一性和 API URL 格式校验规则与创建一致。
  F-PROVIDER-04 删除供应商实例
- 删除前二次确认，明确该供应商关联物理模型数。
- 确认后级联删除该供应商下的物理模型，并解除这些模型在逻辑模型中的挂载。
- 系统模板目录不通过该页面增删改，不参与此删除操作。
  F-PROVIDER-05 使用统计
- 列表展示每个供应商实例关联的物理模型数量。
- 费用、调用量等统计由成本与审计模块按供应商实例 ID 归集。
- 本页面不提供独立的连接测试。
  F-PROVIDER-06 模型接入引导
- 新建供应商保存后自动打开“获取并选择模型→模型测试→确认上架→完成”的页面内引导，并使用完整 API 接口和认证信息尝试获取模型列表；已有供应商可从列表操作重新进入。所有模板均显示“获取模型”，不能仅凭模板或“企业自建”身份预判实际实例是否支持列表查询。
- 服务端优先使用已知的列表适配方式；OpenAI 兼容实例可尝试其 /models 接口。是否取得候选模型，以该实例的实际响应为准。P0 获取策略如下：
  |模板|优先获取方式|处理要点|
  |--|--|--|
  |OpenAI、DeepSeek、Anthropic、Google AI、OpenRouter|各自官方 Models/List Models API|按上游文档处理认证、分页和返回格式|
  |阿里云百炼|百炼独立 GET /api/v1/models，由所填完整 API 地址的主机与地域构造列表路径|不把 OpenAI 兼容 /models 当作百炼的列表接口|
  |Google Vertex AI|Vertex AI Publisher Models 列表接口|按项目、区域、服务账号权限获取候选模型；目录不代表全部已获调用权限|
  |AWS Bedrock|Bedrock 原生 ListFoundationModels，必要时结合 ListInferenceProfiles|IAM（SigV4）模式可尝试；Bedrock Runtime API Key 模式无法直接调用原生列表接口，提示后可手动填写|  
  |Ollama|原生 GET /api/tags；能力可进一步查询模型详情|只返回该实例可访问的 Ollama 服务已安装模型|
  |OpenAI兼容及其他 OpenAI 兼容服务|尝试该实例的 GET /models |自建或中转服务可能未实现；按实际响应展示结果或失败提示|
  |其他专用协议模板|尝试已实现的专用列表适配器|未实现或上游不支持时提示原因并保留手动填写|

- 选择模型步骤展示模型名称、供应商侧模型 ID、上游可确认的结构化调用能力、“可添加/已添加”状态和逻辑模型关联项。上游能力用于展示并填充流式、Tool Calling、JSON、视觉等模型调用参数。上游仅返回 ID 或缺少能力字段时，使用经维护的精确模型元数据映射，仍无法确定则展示“待完善”，不得通过模型 ID 前缀猜测已验证能力。手动输入模型标识和类型的表单始终可展开；列表为空、失败或不支持时直接展示，不中断引导。
- 逻辑模型匹配先对供应商侧模型 ID 与逻辑模型名称做去空格、忽略大小写的精确匹配；精确匹配不存在时，再识别末尾的日期快照后缀（-YYYYMMDD 或 -YYYY-MM-DD）并比较基础模型 ID。例如 gpt-4o-20261111 唯一匹配 gpt-4o 时，默认选择该逻辑模型并标注“版本匹配”。仅在匹配结果唯一时自动选中；存在多个候选时要求管理员手动选择已有逻辑模型或新建，完全未匹配时默认选择“未匹配，自动创建「模型 ID」”。不按通用前缀或子串模糊匹配，mini、turbo、instruct 等模型变体保持独立。手动填写加入列表的模型使用相同规则。逻辑模型只在确认“添加并继续”时创建或挂载，关闭引导或稍后处理不产生逻辑模型变更。
- 同一供应商实例下按供应商侧模型 ID 去重，已添加模型保留现有配置并禁选。弹窗默认全选所有可添加模型，管理员可取消勾选或重新全选；再次获取时只默认选中尚未添加的模型。
- 点击“添加并继续”后批量生成物理模型草稿，归属当前供应商实例，并按管理员在选择步骤确认的映射挂载逻辑模型；选择自动创建时按供应商侧模型 ID 创建同名逻辑模型后挂载。新挂载的路由优先级排在目标逻辑模型已有物理模型之后。导入可确认的类型、上下文和结构化调用能力；未返回的字段保持未知并提示待完善。若上游未提供类型，管理员在选择步骤补选类型后才能继续；价格由管理员在模型管理中核对与配置。
- 每个新增物理模型由模型元数据和供应商模板预填一个“调用接口”。管理员在模型测试步骤逐个确认或修改；每个模型必须选定一个最终调用接口。无法识别时给出可修改的建议值，模板建议不作为测试通过或上架依据。配置保存在物理模型，不写入供应商实例。
- 接着展示本次新增模型和关联的逻辑模型，管理员点击“开始模型测试”。服务端对每个模型标识使用该物理模型选定的调用接口执行准入请求，逐个展示待测试、测试中、通过或未通过。通过的模型进入待审核；未通过的保留草稿，展示失败原因，允许返回调整调用接口后重试；已通过模型无需重复测试。测试由管理员从引导明确发起，不在保存供应商时静默触发。
- 测试结果页只允许具有上架权限的管理员确认上架通过的模型；确认后进入 ACTIVE 并可按已挂载的逻辑模型参与路由。此确认等同现有“审核通过并上架”动作，保留操作日志。关闭引导不撤销已创建模型或挂载关系，未上架模型不参与路由，可在模型管理中继续处理。
- 获取期间展示加载状态；列表接口与模型调用接口可能采用不同路径或权限，获取成功只表示模型目录可读取，不证明某个模型可调用。列表调用失败时展示上游错误和可操作提示，并在同一页面保留手动填写；超时、鉴权失败、无权限、不支持列表接口和空列表分别提示。
- 服务端持有和使用认证信息，前端不直接请求上游，也不回传密钥。服务端分页拉取并限制单次返回量；批量添加按当前供应商 ID 和模型 ID 保证幂等，处理并发导入产生的重复项。
